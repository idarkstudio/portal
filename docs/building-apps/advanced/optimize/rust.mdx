# Optimización de canisters en Rust

<MarkdownChipRow labels={["Principiante", "Rust", "Tutorial"]} />

Compilar Rust a Wasm a menudo incrementa significativamente el tamaño del
archivo. A partir de la versión `0.14.0`, `dfx` incluye el paquete `wasm-opt`,
que puede utilizarse para optimizar el consumo de ciclos y el tamaño del
binario.

## Reducción del consumo de ciclos

El primer paso para optimizar un sistema es el análisis de rendimiento. Comienza
midiendo el número de instrucciones que consumen tus endpoints.

La API `instruction_counter` te permite conocer la cantidad de instrucciones que
tu código ha consumido desde la última llamada de entrada. Las instrucciones son
la unidad fundamental de trabajo en el entorno de ejecución; cada instrucción
ICP representa una operación, como cargar un entero de 32 bits desde una
dirección de memoria. El protocolo asigna un costo en instrucciones a cada
operación Wasm y llamada al sistema, y define todos sus límites en términos de
instrucciones.  
[Consulta un desglose detallado de las limitaciones actuales de instrucciones y Wasm en ICP](/docs/building-apps/canister-management/resource-limits).

A continuación, se muestra un método de ejemplo para medir el número de
instrucciones consumidas:

```rust
#[update]
async fn transfer(from: Account, to: Account, amount: Nat) -> Result<TxId, Error> {
    let start = ic_cdk::api::instruction_counter();
    let tx = apply_transfer(from, to, amount)?;
    let tx_id = archive_transaction(tx).await?;
    // NOTA: el punto await anterior restablece el contador de instrucciones.
    let end = ic_cdk::api::instruction_counter();
    record_measurement(end - start);
    Ok(tx_id)
}
```

## Uso de `wasm-opt`

`wasm-opt` es un optimizador de WebAssembly de propósito general que está
disponible en `dfx` a partir de la versión `0.14.0`.

Puedes habilitar las optimizaciones para tu canister configurando la opción en
el archivo `dfx.json` de tu proyecto, como se muestra a continuación:

```json title="dfx.json"
{
  "canisters": {
    "my_canister": {
      "optimize": "cycles"
    }
  }
}
```

## Optimización para el uso de ciclos

Al utilizar la opción `"optimize": "cycles"`, se puede reducir el consumo de
ciclos en los canisters de Rust aproximadamente en un 7%.

Se recomienda usar `"optimize": "cycles"` como opción predeterminada, ya que
corresponde al nivel de optimización 3 en `wasm-opt`.

Los niveles de optimización para el uso de ciclos son los siguientes:

```
O4
O3 (equivalent to “cycles”)
O2
O1
O0 (performs no optimizations)
```

## Optimización para el tamaño del binario

Para optimizar el tamaño del binario en su lugar, puedes usar la opción
`"optimize": "size"`. Al utilizar esta opción, los binarios pueden reducirse
aproximadamente en un 16%.

Los niveles de optimización para el tamaño del binario son los siguientes:

```
Oz (equivalent to “size”)
Os
```

Cada optimización conserva las secciones de metadatos específicas de ICP en cada
canister.  
Además, las secciones de nombres en tu módulo Wasm pueden preservarse invocando
directamente `ic-wasm` con la opción `--keep-name-section`.

:::info

Ten en cuenta que, en algunos casos, estas optimizaciones pueden aumentar la
complejidad de ciertas funciones dentro del módulo Wasm, lo que podría hacer que
sean rechazadas por la réplica. Si encuentras este problema, se recomienda
utilizar un nivel de optimización menos agresivo para no superar el límite de
complejidad.

:::

Más información sobre la optimización de canisters y pruebas de rendimiento de
`wasm-opt` está disponible en
[este post del foro](https://forum.dfinity.org/t/canister-optimizer-available-in-dfx-0-14-0/21157).
