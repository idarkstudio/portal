## Rust: Utiliza `thread_local!` con `Cell/RefCell` para variables de estado y coloca todas tus variables globales en una sola cesta

### Preocupación de seguridad

Los canisters necesitan un estado mutable global. En Rust, hay varias formas de
lograr esto. Sin embargo, algunas opciones pueden llevar a vulnerabilidades como
la corrupción de memoria.

### Recomendación

- [Utiliza `thread_local!` con `Cell/RefCell` para variables de estado](https://mmapped.blog/posts/01-effective-rust-canisters.html#use-threadlocal)
  (de
  [canisters Rust efectivos](https://mmapped.blog/posts/01-effective-rust-canisters.html)).

- [Coloca todas tus variables globales en una sola cesta](https://mmapped.blog/posts/01-effective-rust-canisters.html#clear-state)
  (de
  [canisters Rust efectivos](https://mmapped.blog/posts/01-effective-rust-canisters.html)).

## Limita la cantidad de datos que se pueden almacenar en un canister por usuario

### Preocupación de seguridad

Si un usuario puede almacenar una gran cantidad de datos en un canister, esto
puede ser abusado para llenar el almacenamiento del canister y hacerlo
inutilizable.

### Recomendación

Limita la cantidad de datos que se pueden almacenar en un canister por usuario.
Este límite debe verificarse cada vez que se almacenan datos para un usuario en
una llamada de actualización.

## Considera utilizar memoria estable, versionarla y probarla

### Preocupación de seguridad

La memoria del canister no se mantiene a través de las actualizaciones. Si los
datos deben mantenerse a través de las actualizaciones, puedes serializar la
memoria del canister en `pre_upgrade` y deserializarla en `post_upgrade`. El uso
de los métodos `pre_upgrade` y `post_upgrade` no se recomienda y se debe evitar.
El número disponible de instrucciones para estos métodos es limitado. Si la
memoria crece demasiado, el canister ya no se puede actualizar.

### Recomendación

- La memoria estable se mantiene a través de las actualizaciones y se puede
  utilizar para abordar este problema.

- [Considera utilizar memoria estable](https://mmapped.blog/posts/01-effective-rust-canisters.html#stable-memory-main)
  (de
  [canisters Rust efectivos](https://mmapped.blog/posts/01-effective-rust-canisters.html)).
  Ten en cuenta las desventajas discutidas.

- [Versiona la memoria estable](https://mmapped.blog/posts/01-effective-rust-canisters.html#version-stable-memory)
  (de
  [canisters Rust efectivos](https://mmapped.blog/posts/01-effective-rust-canisters.html)).

- [Prueba los ganchos de actualización](https://mmapped.blog/posts/01-effective-rust-canisters.html#test-upgrades)

  [canisters Rust efectivos](https://mmapped.blog/posts/01-effective-rust-canisters.html)).

## Considera cifrar datos sensibles en los canisters

### Preocupación de seguridad

Por defecto, los canisters proporcionan integridad pero no confidencialidad. Los
datos almacenados en los canisters pueden ser leídos por nodos/replicas.

### Recomendación

- Considera cifrar de extremo a extremo cualquier dato privado o personal (por
  ejemplo, información personal o privada de un usuario) en los canisters.

- El ejemplo de dapp
  [notas cifradas](https://github.com/dfinity/examples/tree/master/motoko/encrypted-notes-dapp)
  ilustra cómo se puede realizar el cifrado de extremo a extremo.

## Crea copias de seguridad

### Preocupación de seguridad

Un canister podría quedar inutilizable e imposible de actualizar. Por ejemplo,
debido a una de las siguientes razones:

- Tiene un proceso de actualización defectuoso debido a algún error del
  desarrollador de la dapp.

- El estado se vuelve inconsistente o corrupto debido a un error en el código
  que persiste los datos.

### Recomendación

- Asegúrate de que los métodos utilizados en la actualización estén probados, o
  el canister se vuelve inmutable.

- Puede ser útil tener una estrategia de recuperación ante desastres que permita
  reinstalar el canister.

- Consulta la sección "Copia de seguridad y recuperación" en
  [cómo auditar un canister del Internet Computer](https://www.joachim-breitner.de/blog/788-How_to_audit_an_Internet_Computer_canister)
