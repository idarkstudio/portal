# Registro de Canister (Canister logging)

<MarkdownChipRow labels={["Principiante", "Administración"]} />

La función de registro de <GlossaryTooltip>canister</GlossaryTooltip> está
diseñada para proporcionar a los desarrolladores información sobre el
comportamiento de su canister y ayudar en escenarios donde el canister se traba
(trap). Esta función admite mensajes de registro para:

- Heartbeats.
- Timers.
- Pre/post upgrade y `canister_init`.
- Llamadas de actualización.
- Consultas (queries), solo si se llaman en modo replicado.

El controlador de un canister puede recuperar los registros del canister,
incluso cuando las ejecuciones fallan, utilizando el comando  
[`dfx canister logs <canister-name>`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-logs):

```bash
dfx canister logs <canister-name>
```

:::info

Las llamadas no replicadas actualmente no son compatibles con el registro de
logs.

:::

## Visibilidad de los registros

De forma predeterminada, los registros de un canister solo son visibles para los
controladores del canister. Sin embargo, los registros pueden hacerse públicos
actualizando la configuración del canister con el comando  
[`dfx canister update-settings`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-update-settings):

```bash
dfx canister update-settings <canister-name> --log-visibility public
```

### Listas de permitidos para el visor de registros

Las listas de permitidos para el visor de registros permiten que principales que
no son controladores del canister puedan ver los registros sin necesidad de
hacerlos públicos. Estas listas están disponibles en versiones de `dfx` `0.24.2`
y superiores.

Para especificar principales en la lista de permitidos para los registros del
canister, actualiza la configuración del canister con las siguientes opciones:

- `dfx canister update-settings <canister-name> --set-log-viewer <principal-id>`:  
  Establece un único principal como visor de registros.

- `dfx canister update-settings <canister-name> --add-log-viewer <principal-id>`:  
  Agrega un principal a la lista de visores de registros.

- `dfx canister update-settings <canister-name> --remove-log-viewer <principal-id>`:  
  Elimina un principal de la lista de visores de registros.

También puedes configurar un principal como visor de registros al crear un
canister:

```bash
dfx canister create <canister-name> --log-viewer <principal-id>
```

O bien, puedes establecer la configuración  
`canisters[].initialization_values.log_visibility.allowed_viewers` en el archivo
`dfx.json` de tu proyecto para definir los visores de registros del canister en
el momento de su creación.
