# Estado del canister

<MarkdownChipRow labels={["Principiante", "Gestión"]} />

Después de implementar un <GlossaryTooltip>canister</GlossaryTooltip>, puede
comenzar a recibir y procesar solicitudes de usuarios y de otros canisters. Los
canisters que están disponibles para enviar solicitudes y recibir respuestas se
consideran en estado **Ejecutándose**.

Aunque los canisters normalmente se colocan en el estado Ejecutándose de forma
predeterminada, hay casos en los que es posible que desee detener temporal o
permanentemente un canister. Por ejemplo, es posible que desee detener un
canister antes de actualizarlo. Detener un canister ayuda a garantizar el manejo
adecuado de cualquier mensaje en progreso que necesite ejecutarse por completo o
deshacerse. También es posible que desee detener un canister para limpiar su
cola de mensajes de forma limpia como requisito previo para eliminar el
canister.

Para modificar el estado de un canister:

- [`dfx canister status <nombre-del-canister>`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-status):
  Verifique si el canister está `Ejecutándose`, `Deteniéndose` o `Detenido`.
  Este comando también devuelve detalles sobre la configuración del canister.

- [`dfx canister stop <nombre-del-canister>`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-stop):
  Detenga el canister. El estado del canister cambiará a `Deteniéndose` si tiene
  mensajes en curso que deben ser abordados antes de que se pueda detener.

- [`dfx canister start <nombre-del-canister>`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-start):
  Inicie el canister. Después de que un canister se haya detenido con
  `dfx canister stop`, la única forma de reiniciarlo es a través de
  `dfx canister start`. Otros comandos, como `dfx deploy`, no inician el
  canister si se ha detenido manualmente.
