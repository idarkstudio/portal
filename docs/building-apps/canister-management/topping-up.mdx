# Recarga de un canister

<MarkdownChipRow labels={["Principiante", "Gestión"]} />

Un <GlossaryTooltip>canister</GlossaryTooltip> necesita que se le depositen
cycles continuamente para pagar los recursos que utiliza. Este proceso se conoce
como 'recargar' el canister. La recarga de canisters es un mantenimiento
rutinario.

Cualquiera puede recargar cualquier canister desplegado en ICP; no es necesario
ser el propietario ni el controlador del canister. Todo lo que necesitas es el
principal del canister.

Hay varias formas de recargar un canister:

- Usando
  [`dfx cycles top-up`](/docs/building-apps/developer-tools/dfx/dfx-cycles#dfx-cycles-top-up).
- A través de la [aplicación web del NNS](https://nns.ic0.app).
- A través de un
  [servicio de terceros](/docs/building-apps/canister-management/topping-up)
  (por ejemplo, [CycleOps](https://cycleops.dev)).

### Cantidad de cycles

Para facilitar su uso, puedes copiar y pegar las siguientes cantidades de
cycles:

| cycles        | Número              |
| ------------- | ------------------- |
| 1 millón      | 1_000_000           |

## Flujo de trabajo para recargar un canister

Los siguientes ejemplos demostrarán cómo interactuar con un canister y
recargarlo utilizando el ID `jqylk-byaaa-aaaal-qbymq-cai` con un trillón de
cycles (1_000_000_000_000) o su equivalente en un ICP. Estas instrucciones
funcionarán con cualquier ID de canister o cantidad de cycles/ICP.

### Consultar el saldo de cycles de un canister

El saldo de cycles de un canister está disponible mediante el comando
[`dfx canister status`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-status).
Por defecto, no se expone públicamente; solo puedes verlo si eres el controlador
del canister.

```bash
dfx canister status jqylk-byaaa-aaaal-qbymq-cai --network=ic
```

### Opción 1: Si tienes ICP en tu cuenta

Si tienes ICP asociado con tu
[identidad de desarrollador](/docs/building-apps/getting-started/identities),
puedes usar
[`dfx ledger top-up`](/docs/building-apps/developer-tools/dfx/dfx-ledger) para
convertir ICP en cycles y luego recargar un canister con esos cycles.

### Opción 2: Si ya tienes cycles

Si ya posees cycles, puedes recargar un canister con el siguiente comando:

```bash
dfx cycles top-up jqylk-byaaa-aaaal-qbymq-cai 1T --network ic
```

### Caso especial: recargar una wallet de cycles

:::danger La wallet de cycles será eliminada de `dfx` en una futura versión.

Se recomienda usar el ledger de cycles en su lugar. :::

Las wallets de cycles son canisters como cualquier otro. Si tienes una wallet de
cycles controlada mediante `dfx`, puedes enviar cycles desde tu wallet a otro
canister con el siguiente comando:

[`dfx wallet send [OPCIONES] <DESTINO> <CANTIDAD>`](/docs/building-apps/developer-tools/dfx/dfx-wallet#dfx-wallet-send).

[Más información sobre la wallet de cycles](cycles-wallet.mdx).

## Recargar un canister con la aplicación web del NNS

También puedes recargar cualquier canister a través de la
[aplicación web del NNS](https://nns.ic0.app):

- #### Paso 1: Dirígete a la sección **Mis Canisters** de la aplicación.
- #### Paso 2: Haz clic en **Vincular Canister**.
- #### Paso 3: Agrega el principal del canister. No necesitas ser el controlador del canister.
- #### Paso 4: Una vez agregado el canister, haz clic sobre él.
- #### Paso 5: Presiona `Agregar cycles` para recargarlo utilizando ICP desde la aplicación web del NNS.

## Gestionar el agotamiento de cycles con el umbral de congelación

ICP cuenta con un mecanismo para evitar que los canisters se queden sin cycles.
Los canisters tienen un `freezing_threshold` configurable, evaluado
dinámicamente en cycles.

[Más información sobre los umbrales de congelación](/docs/building-apps/canister-management/settings#freezing-threshold).

## Usar un servicio de gestión de cycles

Los servicios de gestión de cycles ofrecen monitoreo y recargas automáticas para
garantizar que las aplicaciones en canisters sigan funcionando sin quedarse sin
cycles.

En lugar de recargar un canister manualmente con `dfx` o programar una solución
personalizada, estos servicios proporcionan automatización probada y métricas
sobre los canisters.

### Servicios populares de gestión de cycles:

- [CycleOps](https://cycleops.dev): Monitoreo proactivo sin código, gráficos de
  tendencias históricas, notificaciones por correo y registro de transacciones
  descargable.
- [TipJar](https://k25co-pqaaa-aaaab-aaakq-cai.ic0.app/): Permite donar cycles a
  tus canisters favoritos en Internet Computer para mantenerlos en
  funcionamiento.
- [Canistergeek](https://cusyh-iyaaa-aaaah-qcpba-cai.raw.icp0.io/): Permite
  recargar canisters, monitorear cycles, memoria y logs, además de generar
  reportes mensuales.

### Librerías populares de gestión de cycles:

#### Motoko

- [cycles-manager](https://github.com/CycleOperators/cycles-manager): Framework
  simplificado y basado en permisos para la gestión de cycles en aplicaciones
  multi-canister (patrocinado por CycleOps).
- [canistergeek-ic-motoko](https://github.com/usergeek/canistergeek-ic-motoko):
  Herramienta de código abierto en Motoko para rastrear cycles y memoria de
  canisters en Internet Computer.

#### Rust

- [canfund](https://github.com/dfinity/canfund): Librería de código abierto para
  la gestión automatizada de cycles en canisters de Internet Computer.
- [canistergeek_ic_rust](https://github.com/usergeek/canistergeek_ic_rust):
  Herramienta de código abierto en Rust para monitorear cycles, memoria y logs
  de canisters en Internet Computer.

## Crear soluciones autónomas de recarga de cycles

Para evitar depender de un servicio externo, puedes crear un canister autónomo
que gestione la recarga de cycles en tu proyecto. Un enfoque común es el
utilizado por
[CycleOps](https://github.com/CycleOperators/cycles-manager/tree/main), donde un
canister actúa como administrador de cycles y proporciona una API para solicitar
cycles cuando otro canister del proyecto alcanza un umbral mínimo.
