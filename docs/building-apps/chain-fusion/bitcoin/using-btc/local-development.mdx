# Desarrollo local

<MarkdownChipRow labels={["Avanzado", "Bitcoin", "Tutorial"]} />

Probar aplicaciones localmente te permite iterar y mejorar tu dapp más rápido.

`dfx` incluye soporte tanto para la  
[API ECDSA](/docs/references/ic-interface-spec#ic-ecdsa_public_key) como para
la  
[API de Bitcoin](https://github.com/dfinity/bitcoin-canister/blob/master/INTERFACE_SPECIFICATION.md),  
para que puedas probar tu dapp localmente antes de desplegarla en el Internet
Computer.

## Configuración de una red Bitcoin local

Para desarrollar dapps de Bitcoin localmente, necesitarás configurar una red
Bitcoin en tu máquina.  
Tener tu propia red Bitcoin local te permite minar bloques rápidamente y cuando
lo desees,  
lo que facilita probar distintos casos sin depender de la (lenta) testnet de
Bitcoin  
o de la (aún más lenta) mainnet de Bitcoin.

- #### Paso 1: Descarga [Bitcoin Core v27](https://bitcoin.org/bin/bitcoin-core-27.0/).
  Se recomienda usar la versión `.tar.gz` para usuarios de Mac.
- #### Paso 2: Descomprime el archivo `.tar.gz`:
  ```sh
  tar -xf bitcoin-27.0-arm64-apple-darwin.tar.gz
  ```
  No uses otro método para descomprimir el archivo, ya que podría generar
  problemas.
- #### Paso 3: Crea un directorio llamado `data` dentro de la carpeta descomprimida:
  ```sh
  cd bitcoin-27.0 && mkdir data
  ```
- #### Paso 4: Reemplaza el contenido del archivo `bitcoin.conf` en la raíz de la carpeta descomprimida con lo siguiente:

  ```
  # Habilita el modo regtest. Esto es necesario para configurar una red Bitcoin privada.
  regtest=1

  # Credenciales ficticias necesarias para `bitcoin-cli`.
  rpcuser=ic-btc-integration
  rpcpassword=QPQiNaph19FqUsCrBRN0FII7lyM26B51fAMeBQzCb-E=
  rpcauth=ic-btc-integration:cdf2741387f3a12438f69092f0fdad8e$62081498c98bee09a0dce2b30671123fa561932992ce377585e8e08bb0c11dfa
  ```

- #### Paso 5: Ejecuta `bitcoind` para iniciar el cliente Bitcoin con el siguiente comando:

  ```sh
  ./bin/bitcoind -conf=$(pwd)/bitcoin.conf -datadir=$(pwd)/data --port=18444
  ```

  Si todo ha salido bien, deberías ver una salida como esta. `bitcoind` ahora
  está listo para aceptar solicitudes:

  ```
  2022-07-11T12:49:51Z Bitcoin Core version v22.0.0 (release build)
  ...
  2022-07-11T12:49:51Z Config file arg: regtest="1"
  2022-07-11T12:49:51Z Config file arg: rpcauth=****
  2022-07-11T12:49:51Z Config file arg: rpcpassword=****
  2022-07-11T12:49:51Z Config file arg: rpcuser=****
  ...
  2022-07-11T12:49:51Z Bound to 127.0.0.1:18445
  2022-07-11T12:49:51Z Bound to [::]:18444
  2022-07-11T12:49:51Z Bound to 0.0.0.0:18444
  ...
  2022-07-11T12:49:52Z opencon thread start
  2022-07-11T12:49:52Z addcon thread start
  2022-07-11T12:49:52Z 0 addresses found from DNS seeds
  2022-07-11T12:49:52Z dnsseed thread exit
  ```

  El comando anterior asume que el puerto `18444` está disponible en tu
  máquina.  
  Si no lo está, cambia el puerto especificado en `--port` según corresponda.

## Desplegando tu dapp de Bitcoin

Ahora que tienes una red Bitcoin local, estás listo para comenzar a desarrollar
y probar localmente tus dapps de Bitcoin.

Para los siguientes pasos, usarás el proyecto de ejemplo del  
[repositorio de ejemplos](https://github.com/dfinity/examples)  
para demostrar algunos conceptos clave.

- #### Paso 1: Clona el repositorio `examples`:

  ```sh
  git clone https://github.com/dfinity/examples
  ```

- #### Paso 2: Ve al ejemplo `basic_bitcoin` en el lenguaje de tu elección:

```sh
# Para Motoko
cd examples/motoko/basic_bitcoin
# Para Rust
cd examples/rust/basic_bitcoin
```

- #### Paso 3: Instala el gestor de paquetes `mops`

```sh
# Para Motoko
curl -fsSL cli.mops.one/install.sh | sh
# Para Rust, este paso no es necesario
```

### Desplegando en modo `regtest`

Tu nodo Bitcoin local opera en lo que se llama "modo de prueba de regresión"  
o
[modo regtest](https://developer.bitcoin.org/examples/testing.html#regtest-mode).  
Ahora puedes desplegar tu canister y configurarlo para conectarse a tu red
`regtest` local.

- #### Paso 1: Ejecuta `dfx start --clean`:

Si al ejecutar `dfx start` ves errores como:

```
Failed to connect to 127.0.0.1:18444 ::: Connecting to the stream timed out.
```

Esto significa que `dfx` no puede conectarse a tu nodo Bitcoin.  
 Asegúrate de que tu nodo Bitcoin esté en funcionamiento  
 y de que estás usando el puerto correcto (por defecto es `18444`).  
 Puedes cambiar el puerto en `dfx.json`.

- #### Paso 2: Despliega el canister de ejemplo:

```sh
  dfx deploy basic_bitcoin --argument '(variant { regtest })'
```

Si se ejecuta correctamente, deberías ver una salida como esta:

```
Deploying: basic_bitcoin
Building canisters...
...
Deployed canisters.
URLs:
Candid:
    basic_bitcoin: http://127.0.0.1:4943/?canisterId=...
```

¡Tu canister está activo y listo para usar! Puedes interactuar con él  
 desde la línea de comandos o a través de la interfaz Candid,  
 que es el enlace que aparece en la salida anterior.

## Generando una dirección de Bitcoin

Bitcoin tiene diferentes tipos de direcciones (por ejemplo, P2PKH, P2SH).  
La mayoría de estas direcciones pueden generarse a partir de una clave pública
ECDSA.  
El código de ejemplo muestra cómo tu canister puede generar una dirección
P2PKH  
usando la API
[`ecdsa_public_key`](/docs/references/ic-interface-spec#ic-ecdsa_public_key).

En la interfaz Candid de tu canister, haz clic en el botón "Call"  
debajo de `get_p2pkh_address` para generar una dirección P2PKH de Bitcoin:

![Generando una dirección de Bitcoin P2PKH](../../_attachments/generate-ecdsa-key.png)

O, si prefieres la línea de comandos:

```sh
dfx canister call basic_bitcoin get_p2pkh_address
```

La dirección de Bitcoin que verás será diferente a la mostrada arriba,  
porque la clave pública ECDSA que obtiene tu canister es única.

### Recibiendo Bitcoin

Para recibir BTC en tu red local de Bitcoin, necesitas minar bloques.  
Por cada bloque que mines, recibirás una recompensa en BTC.

La principal diferencia entre trabajar con una red local de Bitcoin y con una
testnet o mainnet es la forma en que recibes Bitcoin.

En el mismo directorio donde está `bitcoind`, puedes ejecutar el siguiente
comando para minar bloques:

```bash
./bin/bitcoin-cli -conf=$(pwd)/bitcoin.conf generatetoaddress <número-de-bloques> <dirección>
```

Por ejemplo, para minar un bloque y recibir la recompensa en tu canister:

```bash
./bin/bitcoin-cli -conf=$(pwd)/bitcoin.conf generatetoaddress 1 <your-canister-btc-address>
```

`<your-canister-btc-address>` es la dirección obtenida al llamar al endpoint
`get_p2pkh_address` en tu canister.

Si la operación es exitosa, verás un resultado similar a este:

```json
["5eaf0bb0947bc5c3348749b7e194e000f6d93902235e7422b6472a1edfa5a821"]
```

Este es el hash del bloque que acabas de minar. En los logs de `dfx`, en unos
segundos deberías ver algo como:

```bash
INFO .../blockchainmanager Added headers: Height = 1, Active chain's tip = 5eaf0bb0947bc5c3348749b7e194e000f6d93902235e7422b6472a1edfa5a821
DEBG .../ic_btc_canister/heartbeat New Bitcoin tip height: 1
```

Estos registros indican que tu proyecto `dfx` ha procesado el bloque minado.

La sincronización del primer bloque de Bitcoin puede tardar hasta 30 segundos,
pero los siguientes se sincronizan casi instantáneamente.

Ahora, verifica tu balance de BTC:

![Verificar Balance de Bitcoin](../../_attachments/bitcoin-local-check-balance.png)

O con el siguiente comando:

```bash
dfx canister call basic_bitcoin get_balance '("<your-canister-btc-address>")'
```

Si todo salió bien, deberías ver un saldo de 5_000_000_000 Satoshis, lo que
equivale a 50 BTC. Esta es la recompensa por minar un bloque.

El BTC que minas solo es válido en tu red local de Bitcoin y no se puede gastar
ni usar en otro lugar.

### Madurez de Coinbase

En el paso anterior, minaste un bloque y tu canister recibió 50 BTC como
recompensa.

Sin embargo, estas recompensas están sujetas a la regla de
[madurez de Coinbase](https://github.com/bitcoin/bitcoin/blob/bace615ba31cedec50afa4f296934a186b9afae6/src/consensus/consensus.h#L19).  
Esta regla establece que debes minar 100 bloques adicionales antes de poder
gastar la recompensa.

Para minar 100 bloques adicionales, ejecuta:

```bash
./bin/bitcoin-cli -conf=$(pwd)/bitcoin.conf generatetoaddress 100 mtbZzVBwLnDmhH4pE9QynWAgh6H3aC1E6M
```

El comando minará 100 bloques, enviando las recompensas a una dirección
aleatoria.  
De esta manera, los **50 BTC** en tu canister se volverán utilizables.

Si el comando se ejecutó correctamente, verás un resultado similar a este:

```json
[
    "0e70a5e8a56f1799e13fd7a52b445023c2d857a5d4b508971390dc9ae010dedc",
    ...
    "3e0410961a3b144d16dcdc95d73c262e0ec09e9812ce33835b2a55606d2be84b"
]
```

En los logs de `dfx`, deberías ver algo como:

```bash
INFO .../blockchainmanager Added headers: Height = 101, Active chain's tip = 3e0410961a3b144d16dcdc95d73c262e0ec09e9812ce33835b2a55606d2be84b
DEBG .../ic_btc_canister/heartbeat New Bitcoin tip height: 101
```

Estos registros indican que `dfx` ha procesado los **100 nuevos bloques** que
acabas de minar.  
Ahora, el BTC de tu canister puede ser gastado.

## Enviando Bitcoin

Puedes enviar Bitcoin usando el endpoint `send_from_${type}` en tu canister,
donde `${type}` puede ser uno de los siguientes:

- `p2pkh_address`
- `p2tr_key_only_address`
- `p2tr_address_key_path`
- `p2tr_address_script_path`

En la interfaz Candid UI, agrega una dirección de destino y el monto a enviar.  
Por ejemplo, para enviar **1 BTC** a la dirección
`n2dcQfuwFw7M2UYzLfM6P7DwewsQaygb8S`:

![Enviar Transacción de Bitcoin](../../_attachments/bitcoin-local-send-tx.png)

Desde la línea de comandos, el mismo comando sería:

```bash
dfx canister call basic_bitcoin send_from_p2pkh_address '(record { destination_address = "n2dcQfuwFw7M2UYzLfM6P7DwewsQaygb8S"; amount_in_satoshi = 100000000; })'
```

Este comando crea y envía una transacción a tu nodo de Bitcoin local.  
Para más detalles sobre cómo funcionan los endpoints `send_from_${type}`,
consulta los tutoriales de
**[Motoko](https://github.com/dfinity/examples/tree/master/motoko/basic_bitcoin)**
o
**[Rust](https://github.com/dfinity/examples/tree/master/rust/basic_bitcoin)**.

**Paso final:** Minar un bloque para confirmar la transacción.

Ejecuta lo siguiente en el directorio de `bitcoind`:

```bash
./bin/bitcoin-cli -conf=$(pwd)/bitcoin.conf generatetoaddress 1 mtbZzVBwLnDmhH4pE9QynWAgh6H3aC1E6M
```

Esto es similar al proceso de **madurez de Coinbase**, y verás los logs en `dfx`
actualizándose para reflejar la inclusión del nuevo bloque.

Si todo funcionó correctamente, la dirección
`n2dcQfuwFw7M2UYzLfM6P7DwewsQaygb8S` debería mostrar un saldo de **1 BTC**.

![Verificar Balance de Bitcoin](../../_attachments/bitcoin-local-balance-after-send.png)

## Solución de problemas

### Problemas al enviar transacciones

Si intentas enviar una transacción y no se mina, prueba enviándola manualmente
con `bitcoin-cli` para obtener más información sobre los errores:

```bash
./bin/bitcoin-cli -conf=$(pwd)/bitcoin.conf sendrawtransaction <tx-en-hex>
```

Ejemplo:

```bash
./bin/bitcoin-cli -conf=$(pwd)/bitcoin.conf sendrawtransaction 0200000001b0ca9600da1057765dab692467579cb309aba2524d0cd45376874d6e39e1cd50000000006a47304402200024c768daeb38591438cb3cc7e40212442e8a3662f7465bd466d00ceede8014022069ca804f7ca0ba757c9531c5c37c41943a1a1b53b96697b27e928fb35637c5b10121024f9671d4f1a434cfa6c5ca863670b34f2836c259ef2c8c33f4195f2997dc3ee3ffffffff0200e1f505000000001976a914ce0966271055a5b17abb0e9021a7eafdfe557d3088ac1f101024010000001976a9143fc55ebf65a72a3658f0e14c75c99f6eae65b9b388ac00000000
```

Si ves un error como este:

```bash
error code: -25
error message:
bad-txns-inputs-missingorspent
```

Significa que los inputs de la transacción ya fueron gastados o no existen.

### Restablecer el estado

Si necesitas empezar desde cero, elimina el estado local de `dfx` y `bitcoind`:

- #### Paso 1: En tu directorio de `dfx`, ejecuta:

```bash
   dfx stop
   rm -rf .dfx
```

:::caution

Ejecutando `rm -rf .dfx` eliminará permanentemente _todas_ las canisters que
tienes instaladas localmente.

:::

- #### Paso 2: En el directorio de `bitcoind`, detén el proceso si está corriendo y ejecuta:

```bash
  rm -r data
  mkdir data
```
