# Runes

<MarkdownChipRow labels={["Avanzado", "Bitcoin", "Tutorial"]} />

Los Runes de Bitcoin son un tipo de activo fungible desplegado en la red de
Bitcoin.  
A diferencia de otros estándares de activos en Bitcoin como BRC-20 y SRC-20, los
Runes no dependen del [protocolo Ordinals](ordinals.mdx).  
Los Runes están diseñados para ser un activo eficiente y simple que utiliza el
modelo UTXO de Bitcoin y el código de operación `OP_RETURN`.  
Aunque los Runes no dependen de Ordinals, el protocolo Rune fue creado e
implementado por el mismo desarrollador y forma parte del mismo proyecto de
código abierto que Ordinals.

El modelo de transacción UTXO permite que cada salida de transacción contenga
información y sea tratada como una moneda digital.  
Para iniciar una transacción, se deben usar esas salidas como entradas de la
transacción.  
En el caso de los Runes, cada UTXO puede contener una cantidad o tipo diferente
de Rune, lo que simplifica la gestión de tokens en Bitcoin.

El código de operación `OP_RETURN` de Bitcoin permite adjuntar información
adicional a una transacción de Bitcoin, con un límite de 80 bytes de datos.  
Los Runes utilizan este valor de `OP_RETURN` para almacenar los datos del token,
como el nombre, símbolo, comandos o ID.  
A estos datos del token se les conoce como "Runestone".

La creación de un Rune se realiza mediante un proceso llamado "etching"
(grabado), que consiste en enviar una transacción a la red de Bitcoin
especificando los datos del Rune en la salida `OP_RETURN` de una transacción.  
Una vez que un Rune ha sido grabado, puede acuñarse a través de minting abierto
o cerrado.  
El minting abierto permite que cualquier persona acuñe una instancia del Rune a
través de una transacción de minting, mientras que el minting cerrado establece
requisitos específicos que deben cumplirse para que el Rune pueda acuñarse.  
Cuando un Rune se graba inicialmente, su creador puede reservar una parte de los
Runes para sí mismo antes de que otros puedan acuñarlos.

## Runes en ICP

Los canisters desplegados en ICP pueden firmar y enviar transacciones
directamente a la red de Bitcoin a través de la
[integración de Bitcoin en ICP](../overview.mdx) y las
[firmas umbral](/docs/references/t-sigs-how-it-works).  
Específicamente, para que un canister pueda grabar Runes, debe firmar
transacciones utilizando
[firmas umbral de Schnorr](/docs/references/t-sigs-how-it-works#deuterium-schnorr-release-beta)
y contar con una
[dirección de Bitcoin taproot](/docs/building-apps/chain-fusion/bitcoin/using-btc/generate-addresses#generating-addresses-with-threshold-schnorr).

## Grabado y acuñación de Runes

Para grabar un Rune a través de un canister en ICP, primero se debe llamar a la
API `schnorr_public_key` para obtener una clave pública de Schnorr.  
Esta clave pública se utilizará para generar una dirección taproot (P2TR) de
Bitcoin para el canister.  
Se requiere una dirección taproot para firmar y enviar transacciones de Rune,
tanto de grabado como de acuñación, en Bitcoin.  
[Aprende más sobre direcciones taproot de Bitcoin](/docs/building-apps/chain-fusion/bitcoin/using-btc/generate-addresses#generating-addresses-with-threshold-schnorr).

Una vez que se haya generado una dirección taproot para el canister, se debe
escribir un método en el canister que cree una transacción de grabado y luego la
firme con la clave pública de Schnorr del canister.  
Aquí hay un ejemplo de una transacción de grabado escrita en Rust:

```rust reference
https://github.com/pramitgaha21/etcher/blob/ca6c9a1423a597b5f544470eb0e6f0954279b4a4/src/etcher_backend/src/lib.rs#L284-L323
```

## Consulta de información sobre Runes

Para consultar información sobre un Rune, se puede utilizar el  
[canister indexador de Runes](https://github.com/octopus-network/runes-indexer)  
creado por [Omnity Network](https://omnity.network/).  
El canister indexador de Runes permite obtener información sobre Runes, detalles
del grabado de un Rune específico y saldos de Runes.  
Por ejemplo, para consultar datos sobre un Rune usando su nombre, se puede hacer
la siguiente llamada al método `get_rune` del indexador de Runes:

```
dfx canister call runes-indexer get_rune '("HOPE•YOU•GET•RICH")' --ic
```

Retorna:

```json
(
  opt record {
    confirmations = 39_825 : nat32;
    mints = 81_000 : nat;
    terms = opt record {
      cap = opt (81_000 : nat);
      height = record { opt (840_001 : nat64); opt (844_609 : nat64) };
      offset = record { null; null };
      amount = opt (10_000_000 : nat);
    };
    etching = "d66de939cb3ddb4d94f0949612e06e7a84d4d0be381d0220e2903aad68135969";
    turbo = true;
    premine = 0 : nat;
    divisibility = 2 : nat8;
    spaced_rune = "HOPE•YOU•GET•RICH";
    number = 431 : nat64;
    timestamp = 1_713_571_767 : nat64;
    block = 840_000 : nat64;
    burned = 48_537_380 : nat;
    rune_id = "840000:846";
    symbol = opt "🧧";
  },
)
```

[Consulta la referencia completa de la API](https://github.com/octopus-network/runes-indexer?tab=readme-ov-file#api-reference)  
para más información.
