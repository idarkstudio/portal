# Canister EVM RPC

<MarkdownChipRow labels={["Avanzado", "Ethereum", "Tutorial"]} />

El canister **EVM RPC** se utiliza para comunicarse con
[Ethereum](https://ethereum.org/en/) y otras
[blockchains EVM](https://chainlist.org/?testnets=true) utilizando una API en la
cadena. La comunicación con cadenas compatibles con EVM incluye obtener y enviar
información como:

- Los registros de un bloque o transacción específica.

- Información sobre un bloque.

- Detalles sobre una transacción.

- Datos históricos sobre la tarifa de gas de la red.

- Transacciones para una dirección específica.

- Envío de una transacción firmada.

- Consulta del estado de un contrato inteligente.

Para utilizar el canister EVM RPC, puedes enviar solicitudes al
[instancia desplegada en la red principal](https://dashboard.internetcomputer.org/canister/7hfb6-caaaa-aaaar-qadga-cai),
o puedes bifurcar el código fuente y desplegar tu propia instancia del canister.

El código fuente de este proyecto está disponible en GitHub
([internet-computer-protocol/evm-rpc-canister](https://github.com/internet-computer-protocol/evm-rpc-canister)
⭐️) bajo la licencia Apache 2.0.

## Objetivo

El objetivo del canister EVM RPC es actuar como una puerta de enlace entre los
canisters en ICP y las redes compatibles con EVM a través de servicios RPC como
Alchemy, Ankr o Cloudflare. El canister EVM RPC proporciona los métodos
necesarios para que otros canisters de ICP envíen solicitudes a la API JSON-RPC
de Ethereum y reciban respuestas.

## Terminología

A continuación se muestra una lista de términos utilizados para describir
diferentes aspectos del uso del canister EVM RPC:

- **Servicio RPC**: Un servicio IPv6 como Alchemy, Gateway.fm o CloudFlare que
  ofrece acceso a la API JSON-RPC de Ethereum a través de HTTPS. Tenga en cuenta
  que otros Las blockchains EVM a menudo también están cubiertas por esta API
  JSON-RPC.

- **red**: Una blockchain EVM como la red principal de Ethereum, la red de
  prueba de Sepolia, o
  [cadena de capa 2](https://www.investopedia.com/what-are-layer-1-and-layer-2-blockchain-scaling-solutions-7104877).

- **ID de cadena**: Un identificador numérico único y conocido de una red EVM.

- **proveedor**: Un servicio JSON-RPC específico registrado en el canister EVM
  RPC. Cada ID de cadena para un servicio particular requiere un proveedor
  diferente y típicamente también requiere una clave de API diferente. Se pueden
  registrar varios proveedores para una combinación de servicio/ID de cadena.

## Gestión de claves de API

Los proveedores de RPC a menudo requieren el uso de claves de API para
autenticar las solicitudes de RPC. Las solicitudes autenticadas ayudan a mitigar
posibles ataques de denegación de servicio que agotan la límites de velocidad de
solicitud establecidos por los proveedores de RPC. El uso de una clave de API
puede presentar desafíos para los desarrolladores, como:

- Las claves de API para los proveedores de RPC a menudo requieren una
  suscripción paga y/o créditos de cómputo más allá de un cierto número de
  solicitudes por mes.

- Para los desarrolladores que desean construir un prototipo rápido, puede que
  no valga la pena adquirir múltiples claves de API hasta más adelante en el
  desarrollo.

- Cuando un desarrollador de dapp controla una clave de API, se considera que la
  dapp es menos descentralizada.

- El almacenamiento seguro de las claves de API no está soportado a nivel de
  plataforma y requiere que los desarrolladores utilicen sus propias estrategias
  para proteger sus claves, lo que crea una complejidad adicional para los
  desarrolladores que desean utilizar compilaciones reproducibles. Las claves
  personales también son visibles para todos los nodos en la subred ICP.
  [Más información sobre la autenticación](how-it-works.mdx#authentication).

Para proporcionar una solución a los desarrolladores, el canister EVM RPC de
producción está configurado con las claves de API requeridas. Sin embargo, si un
desarrollador desea utilizar sus propios proveedores con sus propias claves de
API, pueden [pasar sus propias claves](evm-rpc-canister.mdx#replacing-api-keys)
al canister EVM RPC. Las variaciones de prueba del canister EVM RPC no utilizan
claves de API.

## Costos

Las llamadas realizadas al canister EVM RPC tienen un costo en
[ciclos](/docs/building-apps/getting-started/tokens-and-cycles). El costo por
solicitud es generalmente similar al de realizar las llamadas equivalentes
[HTTPS](/docs/references/https-outcalls-how-it-works#pricing) en tu propio
canister.

Obtén más información sobre los
[costos de las solicitudes de EVM RPC](costs.mdx).

## Canister desplegado

[fiduciary](/docs/building-apps/developing-canisters/create) con el siguiente
principal:
[`7hfb6-caaaa-aaaar-qadga-cai`](https://dashboard.internetcomputer.org/canister/7hfb6-caaaa-aaaar-qadga-cai).

Consulta el
[repositorio de GitHub](https://github.com/internet-computer-protocol/evm-rpc-canister?tab=readme-ov-file#reproducible-builds)
para obtener información sobre cómo verificar el hash del módulo WebAssembly
desplegado.
