# Inspección de mensajes

<MarkdownChipRow labels={["Intermedio", "Rust"]} />

Un canister puede inspeccionar un mensaje de entrada (ingress) y aceptarlo o
rechazarlo a través de su interfaz HTTPS. Si el mensaje es aceptado, el canister
lo ejecutará.

Un canister sin módulo Wasm instalado rechazará todos los mensajes de entrada.
Si el canister no implementa `canister_inspect_message`, todos los mensajes de
entrada serán aceptados.

La funcionalidad `canister_inspect_message` no debe usarse para control de
acceso definitivo, ya que se ejecuta en una sola réplica sin consenso completo,
y su resultado podría ser falsificado por un nodo límite malicioso. Sin embargo,
como no pasa por consenso completo, un usuario malicioso no puede drenar cycles
de tu canister, ya que no pagas el costo del mensaje pasando por consenso.

Usando el endpoint `canister_inspect_message`, el canister puede invocar
`ic0.accept_message : () → ()` para aceptar el mensaje.

Puedes aprender más en la
[especificación de interfaz de IC](/docs/references/ic-interface-spec#ingress-message-inspection).

Esta guía describe cómo usar `inspect_message` en un canister Rust.

## `inspect_message`

El punto de entrada `canister_inspect_message` puede definirse y exportarse en
un canister Rust usando `#[inspect_message]`.

La función con este atributo no puede tener valor de retorno, y un canister solo
puede tener un punto de entrada `canister_inspect_message`.

```rust
#[inspect_message]
fn inspect_message_function() {
    if /* some condition */ {
        ic_cdk::api::call::accept_message();
    } else {
        /* trap or simply not call accept_message to deny*/
    }
}
```
