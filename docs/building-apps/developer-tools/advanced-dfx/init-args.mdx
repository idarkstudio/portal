# Argumentos de inicialización del canister

<MarkdownChipRow labels={["Intermedio", "Flujo de trabajo dfx"]} />

Al instalar el código de un canister, es posible que se requieran argumentos de
inicialización de Candid para pasar con el comando `dfx canister install`. Los
argumentos de inicialización son parámetros de configuración iniciales que la
instalación del canister espera para instalar el código correctamente. Un
ejemplo de un canister que requiere estos argumentos de inicialización de Candid
es el [canister de ICP ledger](/docs/defi/token-ledgers/setup/icp_ledger_setup).

## Usando `init_arg`

Puedes pasar argumentos de inicialización de Candid a un canister a través del
comando de la CLI:

```
dfx canister install canister_name --argument (...)
```

Para usar este comando, deberás construir el argumento dentro de la CLI, como:

```
dfx canister install icp_ledger_canister --argument
"
  (variant {
    Init = record {
      minting_account = \"$MINTER_ACCOUNT_ID\";
      initial_values = vec {
        record {
          \"$DEFAULT_ACCOUNT_ID\";
          record {
            e8s = 10_000_000_000 : nat64;
          };
        };
      };
      send_whitelist = vec {};
      transfer_fee = opt record {
        e8s = 10_000 : nat64;
      };
      token_symbol = opt \"LICP\";
      token_name = opt \"Local ICP\";
    }
  })
"
```

Alternativamente, puedes pasar estos argumentos al canister directamente en el
archivo `dfx.json`:

```json
{
  "canisters": {
    "icp_ledger_canister": {
      "type": "custom",
      "candid": "https://raw.githubusercontent.com/dfinity/ic/aba60ffbc46acfc8990bf4d5685c1360bd7026b9/rs/ledger_suite/icp/ledger.did",
      "wasm": "https://download.dfinity.systems/ic/aba60ffbc46acfc8990bf4d5685c1360bd7026b9/canisters/ledger-canister.wasm.gz",
      "remote": {
        "id": {
          "ic": "ryjl3-tyaaa-aaaaa-aaaba-cai"
        }
      },
      "init_arg" : "(variant { Init = record { minting_account = "MINTER_ACCOUNT_ID"; initial_values = vec { record { "DEFAULT_ACCOUNT_ID"; record { e8s = 10_000_000_000 : nat64; }; }; }; send_whitelist = vec {}; transfer_fee = opt record { e8s = 10_000 : nat64; }; token_symbol = opt \"LICP\"; token_name = opt \"Local ICP\"; } })"
    }
  },
  "defaults": {
    "build": {
      "args": "",
      "packtool": ""
    }
  },
  "output_env_file": ".env",
  "version": 1
}
```

## Usando un `init_arg_file`

Para facilitar la gestión de los argumentos de inicialización en proyectos
grandes con múltiples canisters, se admite la opción `init_arg_file`. Se puede
utilizar tanto en la CLI como en el archivo `dfx.json`.

Para utilizarlo en la CLI, simplemente pasa la bandera `--argument-file`,
seguida de la ruta relativa al archivo desde el directorio que contiene el
archivo `dfx.json`:

```
dfx canister install canister_name --argument-file src/candid/icp_ledger_init.did
```

Un ejemplo de archivo de argumentos de inicialización se puede encontrar a
continuación:

```did
(variant {
  Init = record {
    minting_account = "MINTER_ACCOUNT_ID";
    initial_values = vec {
      record {
        "DEFAULT_ACCOUNT_ID";
        record {
          e8s = 10_000_000_000 : nat64;
        };
      };
    };
    send_whitelist = vec {};
    transfer_fee = opt record {
      e8s = 10_000 : nat64;
    };
    token_symbol = opt "LICP";
    token_name = opt "Local ICP";
  }
})
```

Puedes especificar el `init_arg_file` para cada canister en el archivo
`dfx.json`:

```json
"canisters": {
    "icp_ledger": {
      "type": "custom",
      "candid": "https://raw.githubusercontent.com/dfinity/ic/aba60ffbc46acfc8990bf4d5685c1360bd7026b9/rs/ledger_suite/icp/ledger.did",
      "wasm": "https://download.dfinity.systems/ic/aba60ffbc46acfc8990bf4d5685c1360bd7026b9/canisters/ledger-canister.wasm.gz",
      "remote": {
        "id": {
          "ic": "ryjl3-tyaaa-aaaaa-aaaba-cai"
        }
      },
      "init_arg_file": "src/candid/icp_ledger_init.did"
    },
    ...
```

### Notas importantes

- Si se utilizan los flags `--argument` o `--argument-file` en la CLI, cualquier
  configuración para `init_args` en `dfx.json` será ignorada. La configuración
  de la CLI tiene prioridad.

- Solo se puede definir un `init_arg` y un `init_arg_file` a la vez.

- Los argumentos de inicialización deben configurarse individualmente para cada
  canister, ya sea a través de la CLI o de `dfx.json`. Para facilitar esto, se
  pueden utilizar archivos `init_arg_file`, como se detalla a continuación.

- Al usar `dfx.json` o un archivo de argumentos, los valores referenciados como
  variables de entorno dentro del archivo no serán pasados al canister.
