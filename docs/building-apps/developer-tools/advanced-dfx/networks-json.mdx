# Definir redes personalizadas

<MarkdownChipRow labels={["Avanzado", "dfx workflow"]} />

Cuando se desarrollan varios proyectos simultáneamente, puede ser beneficioso
desplegar cada proyecto en una red local diferente para mayor simplicidad o para
apoyar diferentes flujos de trabajo de desarrollo. Las redes personalizadas se
pueden configurar con `dfx` tanto a nivel global del sistema como a nivel
específico del proyecto.

## Definir redes globales del sistema en `networks.json`

Los canisters de cualquier proyecto pueden ser desplegados en redes globales del
sistema. Las redes personalizadas globales se pueden configurar en el archivo de
configuración `networks.json` para `dfx`.

Para localizar este archivo en tu sistema local, utiliza el comando `dfx`:

```
dfx info networks-json-path
```

ESto devolverá la ruta del archivo donde se encuentra el archivo `networks.json`
de tu sistema, como:

```
/Users/developer/.config/dfx/networks.json
```

### Configuración predeterminada

De manera predeterminada, este archivo contiene la siguiente configuración:

```json
{
  "local": {
    "replica": {
      "subnet_type": "application"
    }
  }
}
```

Alternativamente, si no se define un archivo `network.json` localmente, `dfx`
utilizará por defecto la configuración anterior.

### Definir una red personalizada

Para definir una red personalizada, puedes definir una dirección de enlace en tu
archivo `networks.json` como `localhost` u otro nombre de dominio, como:

```json
{
  "network_1": {
    "bind": "localhost:4943",
    "replica": {
      "subnet_type": "application"
    }
  }
}
```

Para definir varias redes, utiliza múltiples definiciones en diferentes nombres

```json
{
  "network_1": {
    "bind": "localhost:4943",
    "replica": {
      "subnet_type": "application"
    }
  },
  "network_2": {
    "bind": "127.0.0.1:4943",
    "replica": {
      "subnet_type": "application"
    }
  }
}
```

Luego, para desplegar en una de estas redes, utiliza la bandera `--network` con
`dfx deploy`, como:

```
dfx deploy --network network_2
```

`dfx deploy` mostrará URLs en el formato `<canister>.localhost:port` o
`<network>:port/?canisterId=<canister>`:

```
  Frontend canister via browser
    poll_frontend: http://b77ix-eeaaa-aaaaa-qaada-cai.localhost:4943/
  Backend canister via Candid interface:
    poll_backend: http://by6od-j4aaa-aaaaa-qaadq-cai.localhost:4943/?id=bw4dl-smaaa-aaaaa-qaacq-cai
```

```
URLs:
  Frontend canister via browser
    poll_frontend: http://127.0.0.1:4943/?canisterId=bd3sg-teaaa-aaaaa-qaaba-cai
  Backend canister via Candid interface:
    poll_backend: http://127.0.0.1:4943/?canisterId=be2us-64aaa-aaaaa-qaabq-cai&id=bkyz2-fmaaa-aaaaa-qaaaq-cai
```

## Definir redes específicas del proyecto en `dfx.json`

Las redes también se pueden definir en el archivo `dfx.json` de un proyecto.
Solo los canisters dentro del proyecto pueden ser desplegados en las redes
definidas en `dfx.json`.

Las definiciones de red en el archivo `dfx.json` pueden tener los siguientes
componentes de configuración:

- `providers`: El proveedor de la red; puede ser `localhost` o cualquier otro
  nombre de dominio. Los nombres de dominio deben ser una URL completa, como
  `https://domain.com`.
- `type`: El tipo de red, puede ser `ephemeral` o `persistent`. Las redes
  efímeras no retienen los mismos IDs para los canisters, mientras que las redes
  persistentes retendrán los mismos IDs para los canisters.

Para definir una red específica del proyecto, agrega una sección "networks" a tu
archivo `dfx.json`, como:

```json
"networks": {
    "dev": {
      "providers": [
        "https://ic0.app"
      ],
      "type": "persistent"
    }
  }
```

Si estás utilizando una
[wallet de cycles](/docs/building-apps/canister-management/topping-up),
asegúrate de desplegar tu wallet de ciclos en esta red personalizada.

```
dfx identity --network dev set-wallet $(dfx identity --network ic get-wallet)
```

Luego, despliega en la red:

```
dfx deploy --network dev
```
