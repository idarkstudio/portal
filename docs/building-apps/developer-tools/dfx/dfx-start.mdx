# dfx start

<MarkdownChipRow labels={["Referencia"]} />

Utiliza el comando `dfx start` para iniciar un entorno local de ejecución de
canisters y procesos de servidor web. Este comando te permite implementar
canisters en el entorno local de ejecución de canisters para probar tus dapps
durante el desarrollo.

Por defecto, todos los proyectos locales de dfx utilizarán este único entorno
local de ejecución de canisters, y puedes ejecutar `dfx start` y `dfx stop`
desde cualquier directorio. Consulta
[Configuración del servidor local](#configuración-del-servidor-local) y
[Redes locales específicas del proyecto](#redes-locales-específicas-del-proyecto)
a continuación para conocer las excepciones.

## Uso básico

```bash
dfx start [option] [flag]
```

## Flags

Puedes usar los siguientes flags opcionales con el comando `dfx start`.

| Flag                     | Descripción                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--background`           | Inicia el entorno de ejecución de canisters locales y los procesos del servidor web en segundo plano, esperando una respuesta antes de devolver el control al shell.                                    |
| `--clean`                | Inicia el entorno de ejecución de canisters locales y los procesos del servidor web en un estado limpio eliminando los checkpoints del caché del proyecto. Útil para solucionar problemas o depuración. |
| `--enable-bitcoin`       | Habilita la integración con Bitcoin.                                                                                                                                                                    |
| `--enable-canister-http` | Habilita las solicitudes HTTP de canisters. (Deprecado: ahora está habilitado por defecto).                                                                                                             |
| `--pocketic`             | Ejecuta [PocketIC](https://github.com/dfinity/pocketic) en lugar de la réplica.                                                                                                                         |
| `--replica`              | Ejecuta la réplica en lugar de [PocketIC](https://github.com/dfinity/pocketic).                                                                                                                         |

## Opciones

Puedes usar las siguientes opciones con el comando `dfx start`.

| Opción                            | Descripción                                                                                                                                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--host host`                     | Especifica la dirección IP y el puerto para enlazar el frontend. El valor predeterminado para la red compartida local es `127.0.0.1:4943`, mientras que para un proyecto específico es `127.0.0.1:8000`. |
| `--bitcoin-node host:port`        | Especifica la dirección de un nodo `bitcoind`. Implica `--enable-bitcoin`.                                                                                                                               |
| `--artificial-delay milliseconds` | Especifica el retraso que debe sufrir una llamada de actualización. Valor predeterminado: 600ms.                                                                                                         |
| `--domain domain`                 | Un dominio que puede ser servido. Puede especificarse varias veces. Se usa para la resolución de canisters [valor predeterminado: localhost].                                                            |

## Ejemplos

Puedes iniciar el entorno de ejecución de canisters locales y los procesos del
servidor web en el shell actual ejecutando el siguiente comando:

```bash
dfx start
```

Si ejecutas el entorno de ejecución local de canisters en segundo plano, sin
embargo, asegúrate de detener el entorno de ejecución local de canisters antes
de desinstalar o volver a instalar el entorno de ejecución `dfx` ejecutando el
siguiente comando:

```bash
dfx start --background
```

Si ejecutas el entorno de ejecución local de canisters en segundo plano,
asegúrate de detener el entorno de ejecución local de canisters antes de
desinstalar o reinstalar el entorno de ejecución `dfx` ejecutando el siguiente
comando:

```bash
dfx stop
```

Puedes ver el identificador de proceso (`pid`) actual para el proceso de entorno
de ejecución de canisters local iniciado por `dfx` ejecutando el siguiente
comando:

```bash
more .dfx/pid
```

## Configuración del Servidor Local

### La Red Local Compartida

Por defecto, `dfx start` administra una única réplica independiente de cualquier
proyecto local. Ejecutar `dfx deploy` y otros comandos gestionará los canisters
en esta misma red local, de manera similar a como `dfx deploy --network ic`
despliega proyectos en la mainnet.

Si se ejecuta fuera de un proyecto de `dfx` o si `dfx.json` no define la red
`local`, entonces `dfx start` buscará la definición de la red `local` en
`$HOME/.config/dfx/networks.json`. Si este archivo no existe o no contiene una
definición para la red `local`, `dfx` usará la siguiente definición
predeterminada:

```
{
  "local": {
    "bind": "127.0.0.1:4943",
    "type": "ephemeral"
  }
}
```

`dfx` almacena datos para la red local compartida en una de las siguientes
ubicaciones, dependiendo de tu sistema operativo:

- `$HOME/.local/share/dfx/network/local` (Linux)
- `$HOME/Library/Application Support/org.dfinity.dfx/network/local` (MacOS)

### Redes Locales Específicas de un Proyecto

Si `dfx.json` define la red `local`, entonces `dfx start` usará esta definición
y almacenará los archivos de datos de la red en
`<project dir>/.dfx/network/local`.

Ten en cuenta que para los proyectos que definen la red `local` en `dfx.json`,
solo puedes ejecutar los comandos `dfx start` y `dfx stop` desde dentro de la
estructura de directorios del proyecto. Por ejemplo, si tu proyecto se llama
`hello_world`, tu directorio de trabajo actual debe ser el directorio principal
`hello_world` o uno de sus subdirectorios.
