# dfx nns

<MarkdownChipRow labels={["Referencia"]} />

:::caution

El comando `dfx nns` ya no forma parte de dfx y ahora se ha convertido en la
extensión dfx. Para obtenerlo, ejecuta `dfx extension install nns`.

:::

Utiliza los subcomandos `dfx nns` para interactuar con el Sistema Nervioso de la
Red.

La sintaxis básica para ejecutar comandos `dfx nns` es:

```bash
dfx nns [subcommand] [flag]
```

Dependiendo del subcomando `dfx nns` que especifiques, pueden aplicarse
argumentos, opciones y banderas adicionales. Para obtener información de
referencia y ejemplos que ilustren el uso de los comandos `dfx nns`, selecciona
un comando apropiado.

| Comando                        | Descripción                                                               |
| ------------------------------ | ------------------------------------------------------------------------- |
| [`import`](#_dfx_nns_import)   | Agrega los canisters NNS al dfx.json local como canisters remotos.        |
| [`install`](#_dfx_nns_install) | Implementa los canisters NNS en el servidor dfx local.                    |
| `help`                         | Muestra un mensaje de información de uso para un subcomando especificado. |

Para ver la información de uso de un subcomando específico, especifica el
subcomando y la bandera `--help`. Por ejemplo, para ver la información de uso de
`dfx nns install`, puedes ejecutar el siguiente comando:

```bash
$ dfx nns install --help
```

## dfx nns import

Usa el comando `dfx nns import` para agregar los canisters NNS al `dfx.json`
local. También descarga los archivos did y establece los IDs de canister de los
canisters NNS para que puedas hacer llamadas API a los canisters NNS.

### Uso básico

```bash
$ dfx nns import
```

### Flags

Puedes utilizar las siguientes flags opcionales con el comando `dfx nns import`.

| Flags               | Descripción                                              |
| ------------------- | -------------------------------------------------------- |
| `--network-mapping` | Renombra las redes al instalar los IDs de los canisters. |

### Ejemplos

Puedes utilizar el comando `dfx nns import` para obtener archivos did y así
consultar los canisters NNS.

```bash
$ dfx nns import
$ dfx canister call --network ic nns-governance get_pending_proposals '()'
```

Puedes renombrar una red al importarla. Por ejemplo, si tienes `test-ic`
configurado como un alias de la red `ic`, puedes establecer los IDs de los
canisters NNS para `test-ic` con:

```bash
$ dfx nns import --network-mapping test-ic=ic
```

## dfx nns install

Utiliza el comando `dfx nns install` para instalar un NNS local. Esto
proporciona los canisters de contabilidad y gobernanza locales, así como los
canisters de GUI Internet Identity y NNS-Dapp.

### Uso básico

La red local debe configurarse con una configuración muy específica:

```
$ cat ~/.config/dfx/networks.json
{
  "local": {
    "bind": "127.0.0.1:8080",
    "type": "ephemeral",
    "replica": {
      "subnet_type": "system"
    }
  }
}
```

Esto es porque:

- Los canisters NNS deben ejecutarse en una subnet del sistema.
- Algunos canisters se compilan para ejecutarse solo en pares de ID de canister
  y nombre de host/puerto muy específicos.

Además, el servidor dfx local debe estar limpio:

```bash
$ dfx start --clean --background
$ dfx nns install
```

Esto se debe a que los canisters NNS deben instalarse antes que cualquier otro.

### Ejemplos

#### Ejemplo: Hacer llamadas API al NNS local

```bash
$ dfx stop
$ dfx start --clean --background
$ dfx nns install
$ dfx nns import
$ dfx canister call --network ic nns-governance get_pending_proposals '()'
```

Puedes ver las llamadas API que se pueden realizar para cada canister NNS al
consultar los archivos de definición de interfaz instalados por `dfx nns import`
en `candid/*.did`. Los métodos de la API se encuentran en la sección `service`,
que generalmente se encuentra al final de un archivo `.did`. Lo más fácil es
comenzar a experimentar con métodos que no requieran argumentos.

#### Ejemplo: Acceder a ICP en la línea de comandos

Se inicializan dos cuentas en el libro mayor local con ICP que se pueden usar
para pruebas. Una utiliza una clave secp256k1, que es conveniente para el uso en
la línea de comandos, y otra utiliza una clave ed25519, que es más conveniente
en aplicaciones web.

Para usar ICP en la línea de comandos:

- Inicia dfx e instala el NNS, como se describe en
  [`install`](#_dfx_nns_install).
- Coloca esta clave secreta en un archivo llamado `ident-1.pem`:

```bash
$ cat <<EOF >ident-1.pem
-----BEGIN EC PRIVATE KEY-----
MHQCAQEEICJxApEbuZznKFpV+VKACRK30i6+7u5Z13/DOl18cIC+oAcGBSuBBAAK
oUQDQgAEPas6Iag4TUx+Uop+3NhE6s3FlayFtbwdhRVjvOar0kPTfE/N8N6btRnd
74ly5xXEBNSXiENyxhEuzOZrIWMCNQ==
-----END EC PRIVATE KEY-----
EOF
```

- Verifica la clave: (opcional)

```
$ openssl ec -in ident-1.pem -noout -text
```

- Crea una identidad con esa clave secreta:

```bash
$ dfx identity import ident-1 ident-1.pem
```

- Ahora puedes usar los fondos (de testeo):

```bash
$ dfx ledger balance
```

Para usar ICP en una aplicación web existente:

- Instala el módulo npm
  [@dfinity/agent](https://www.npmjs.com/package/@dfinity/agent).
- Crea una identidad con este par de claves:

```
  const publicKey = "Uu8wv55BKmk9ZErr6OIt5XR1kpEGXcOSOC1OYzrAwuk=";
  const privateKey =
    "N3HB8Hh2PrWqhWH2Qqgr1vbU9T3gb1zgdBD8ZOdlQnVS7zC/nkEqaT1kSuvo4i3ldHWSkQZdw5I4LU5jOsDC6Q==";
  const identity = Ed25519KeyIdentity.fromKeyPair(
    base64ToUInt8Array(publicKey),
    base64ToUInt8Array(privateKey)
  );

  // If using node:
  const base64ToUInt8Array = (base64String: string): Uint8Array => {
    return Buffer.from(base64String, 'base64')
  };
  // If in a browser:
  const base64ToUInt8Array = (base64String: string): Uint8Array => {
    return Uint8Array.from(window.atob(base64String), (c) => c.charCodeAt(0));
  };
```

- Esa identidad ahora puede hacer llamadas API, incluido el envío de ICP.
