# dfx build

<MarkdownChipRow labels={["Referencia"]} />

Utiliza el comando `dfx build` para compilar tu programa en un módulo de
WebAssembly que se puede implementar en el IC. Puedes utilizar este comando para
compilar todos los programas que están definidos para un proyecto en el archivo
de configuración `dfx.json` del proyecto o un canister específico.

Ten en cuenta que solo puedes ejecutar este comando desde el directorio de
estructura del proyecto. Por ejemplo, si el nombre de tu proyecto es
`hello_world`, tu directorio de trabajo actual debe ser el directorio principal
del proyecto `hello_world` o uno de sus subdirectorios.

El comando `dfx build` busca el código fuente para compilar utilizando la
información que has configurado en la sección `canisters` en el archivo de
configuración `dfx.json`.

## Uso básico

```bash
dfx build [flag] [option] [--all | canister_name]
```

## Flags (banderas)

Puedes usar las siguientes flags opcionales con el comando `dfx build`.

| Bandera   | Descripción                                                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--check` | Compila los canisters utilizando un identificador de canister temporal, predefinido y local, para probar que tu programa se compila sin necesidad de conectarse a la IC. |

## Opciones

Puedes especificar las siguientes opciones para el comando `dfx build`.

| Opción                | Descripción                                                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--network <network>` | Especifica el alias de red o la URL a la que deseas conectarte. Puedes usar esta opción para sobrescribir la red especificada en el archivo de configuración `dfx.json`. |
| `--output-env-file`   | Escribe las variables de entorno de `dfx` en la ruta proporcionada. Sobrescribe la configuración `output_env_file` en `dfx.json` si se proporciona.                      |

## Argumentos

Puedes especificar los siguientes argumentos para el comando `dfx build`.

| Argumento       | Descripción                                                                                                                                                                                                                                                           |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--all`         | Compila todos los canisters configurados en el archivo `dfx.json` del proyecto.                                                                                                                                                                                       |
| `canister_name` | Especifica el nombre del canister que deseas compilar. Si no usas la opción `--all`, puedes seguir ejecutando `dfx build` o proporcionar un nombre de canister como argumento (el nombre debe coincidir con uno configurado en la sección `canisters` de `dfx.json`). |

## Ejemplos

Puedes usar el comando `dfx build` para compilar uno o más módulos WebAssembly a
partir de los programas especificados en el archivo de configuración `dfx.json`,
bajo la clave `canisters`.  
Por ejemplo, si tu archivo `dfx.json` define un canister `hello_world_backend` y
un canister `hello_world_frontend`, al ejecutar `dfx build` se compilan dos
módulos WebAssembly.

Ten en cuenta que el nombre del archivo y la ruta de los programas en tu sistema
de archivos deben coincidir con la información especificada en el archivo de
configuración `dfx.json`.

En este ejemplo, el canister `hello_world_backend` contiene el código principal
del programa y el canister `hello_world_frontend` almacena el código del
frontend y los activos.  
Si deseas mantener el canister `hello_world_frontend` definido en el archivo
`dfx.json`, pero solo compilar el programa backend, puedes ejecutar el siguiente
comando:

```bash
dfx build hello_world_backend
```

Compilar un canister específico es útil cuando tienes múltiples canisters
definidos en el archivo dfx.json, pero deseas probar y depurar operaciones para
canisters de forma independiente.

Para probar si un canister se compila sin conectarse al IC o al entorno de
ejecución local del canister, debes ejecutar el siguiente comando:

```bash
dfx build --check
```

## Canister de gestión (management)

Si `dfx` detecta que tu proyecto de Motoko está importando el Canister de
Gestión (por ejemplo, `import Management "ic:aaaaa-aa";`) automáticamente
proporcionará la interfaz Candid para el Canister de Gestión durante la
compilación.
