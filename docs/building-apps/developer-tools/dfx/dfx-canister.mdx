# dfx canister

<MarkdownChipRow labels={["Referencia"]} />

Utiliza el comando `dfx canister` con opciones y subcomandos para gestionar las
operaciones de los canisters y la interacción con el Internet Computer o el
entorno de ejecución de canisters local. En la mayoría de los casos, utilizas
los subcomandos de `dfx canister` después de compilar un programa para gestionar
el ciclo de vida del canister y realizar tareas clave como llamar a las
funciones del programa.

La sintaxis básica para ejecutar los comandos de `dfx canister` es:

```bash
dfx canister <subcommand> [options]
```

Dependiendo del subcomando `dfx canister` que especifiques, podrían aplicarse o
ser requeridos argumentos y opciones adicionales. Para ver información de uso de
un subcomando específico de `dfx canister`, especifica el subcomando y la
bandera `--help`. Por ejemplo, para ver información de uso de
`dfx canister call`, puedes ejecutar el siguiente comando:

```bash
dfx canister call --help
```

## Sobrescribir el entorno de despliegue predeterminado

Por defecto, los comandos `dfx canister` se ejecutan en el entorno local
definido en el archivo `dfx.json`.  
Si deseas enviar un subcomando de `dfx canister` a Internet Computer o a una red
de prueba sin modificar la configuración en tu archivo `dfx.json`, puedes
especificar explícitamente la URL de conexión utilizando la opción `--network`.

Por ejemplo, para registrar identificadores de canister únicos para un proyecto
en el entorno de ejecución local, puedes ejecutar el siguiente comando:

```bash
dfx canister create --all
```

Si quieres registrar identificadores de canister únicos para el mismo proyecto
en el Internet Computer, puedes ejecutar el siguiente comando:

```bash
dfx canister create --all --network ic
```

El SDK viene con un alias de `ic`, que está configurado para apuntar al Internet
Computer. También puedes pasar una URL como opción de red, o puedes configurar
alias adicionales en `dfx.json` bajo la configuración de `networks`, o en
`$HOME/.config/dfx/networks.json`.

Para ilustrar, puedes llamar a un canister y función que se ejecuta en una red
de prueba utilizando un comando similar al siguiente:

```bash
dfx canister call counter get --network http://192.168.3.1:5678
```

## Realizando una llamada a través de la wallet

Por defecto, la mayoría de los comandos `dfx canister` hacia Internet Computer
están firmados y enviados desde tu propio principal. (Las excepciones son los
comandos que requieren ciclos: `dfx canister create` y
`dfx canister deposit-cycles`. Esos automáticamente pasan a través de la
wallet). Ocasionalmente, es posible que desees realizar una llamada desde tu
wallet, por ejemplo, cuando solo tu wallet tiene permitido llamar a una función
específica. Para enviar una llamada a través de tu wallet, puedes usar la opción
`--wallet`. Deberás especificar el principal de la wallet o el nombre de una
identidad asociada a una wallet.

### Especificando una wallet por principal

Para especificar una wallet por principal, pasa el principal directamente.

```bash
dfx canister status <canister name> --wallet <wallet id>
```

Como ejemplo concreto, si deseas solicitar el estado de un canister en el IC que
solo está controlado por tu wallet, debes hacer lo siguiente:

```bash
dfx identity get-wallet --network ic
```

Este comando muestra el principal de tu wallet (por ejemplo,
`22ayq-aiaaa-aaaai-qgmma-cai`) en la red `ic`. Usando este id, puedes consultar
el estado del canister (asumiendo que el canister se llama `my_canister_name`)
de la siguiente manera:

```bash
dfx canister status --network ic --wallet 22ayq-aiaaa-aaaai-qgmma-cai
```

### Especificando una wallet por nombre de identidad

En el ejemplo anterior, primero buscamos el principal de la billetera
seleccionada actualmente. Podemos evitar este paso especificando el nombre de
una identidad, en cuyo caso dfx buscará el principal de la billetera por
nosotros.

Por ejemplo, el siguiente comando consultará el estado de un canister,
utilizando la billetera asociada con la identidad predeterminada en la red ic:

```bash
dfx canister status --network ic --wallet default
```

Como otro ejemplo, los siguientes comandos son equivalentes:

```bash
dfx canister status --network ic --wallet $(dfx identity get-wallet --network ic --identity alice)
dfx canister status --network ic --wallet alice
```

## dfx canister call

Usa el comando `dfx canister call` para llamar a un método específico en un
canister desplegado.

### Uso básico

```bash
dfx canister call [options] <canister_name> <method_name> [argument]
```

## Opciones de `dfx canister call`

Puedes utilizar las siguientes opciones con el comando `dfx canister call`:

| Opción                            | Descripción                                                                                                                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--argument-file <argument-file>` | Especifica el archivo desde el cual leer el argumento que se pasará al método. Se puede utilizar `-` para referirse a la entrada estándar (stdin).                                                                                          |
| `--async`                         | No espera el resultado de la llamada. En su lugar, devuelve un ID de respuesta.                                                                                                                                                             |
| `--candid <file.did>`             | Proporciona un archivo `.did` para decodificar la respuesta. Sobrescribe el valor de `dfx.json` para canisters en el proyecto.                                                                                                              |
| `--output <output>`               | Especifica el formato de salida al mostrar el resultado del método. Valores válidos: `idl`, `json`, `pp`, `raw`. La opción `pp` es equivalente a `idl`, pero con formato mejorado.                                                          |
| `--query`                         | Envía una solicitud de consulta en lugar de una solicitud de actualización. Para más información sobre la diferencia entre llamadas `query` y `update`, consulta [Canister State](/docs/building-apps/essentials/canisters#canister-state). |
| `--random <random>`               | Especifica la configuración para generar argumentos aleatorios.                                                                                                                                                                             |
| `--type <type>`                   | Especifica el formato de datos para el argumento al realizar la llamada. Valores válidos: `idl` y `raw`.                                                                                                                                    |
| `--update`                        | Envía una solicitud de actualización a un canister. Este es el comportamiento predeterminado si el método no es de tipo `query`.                                                                                                            |
| `--with-cycles <amount>`          | Especifica la cantidad de ciclos a enviar con la llamada. Se deduce del wallet y requiere la opción `--wallet` en `dfx canister`.                                                                                                           |

---

## Argumentos de `dfx canister call`

Puedes especificar los siguientes argumentos al usar `dfx canister call`:

| Argumento       | Descripción                                                                                                                                     |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `canister_name` | Especifica el nombre del canister al que se llamará. Debe coincidir con el nombre configurado en la sección `canisters` del archivo `dfx.json`. |
| `method_name`   | Especifica el nombre del método a llamar en el canister. Este argumento es obligatorio.                                                         |
| `argument`      | Especifica el argumento que se pasará al método.                                                                                                |

### Especificar el argumento a pasar al método

Dependiendo de la lógica del programa, el argumento puede ser obligatorio u
opcional.  
Si pasas un argumento al canister, puedes especificar un tipo de formato de
datos usando la opción `--type`.  
Por defecto, puedes especificar argumentos utilizando la sintaxis
[Candid](/docs/references/candid-ref) (`idl`).

Para más información sobre cómo usar Candid y sus tipos compatibles, consulta:

- [Interactuar con un servicio en terminal](/docs/building-apps/interact-with-canisters/candid/using-candid#idl-syntax)
- [Tipos compatibles](/docs/references/candid-ref#supported-types)

Si deseas pasar bytes sin procesar, puedes usar `raw` como tipo de argumento.

## Ejemplos

Puedes usar el comando `dfx canister call` para invocar métodos específicos, con
o sin argumentos, después de haber desplegado el canister con
`dfx canister install`.

Por ejemplo, para invocar el método `get` de un canister con el nombre
`counter`, puedes ejecutar el siguiente comando:

```bash
dfx canister call counter get --async
```

En este ejemplo, el comando incluye la opción `--async` para indicar que deseas
realizar una llamada separada a `request-status` en lugar de esperar a que se
complete el entorno de ejecución local del canister o el Internet Computer para
obtener el resultado. La opción `--async` es útil cuando el procesamiento de una
operación puede llevar tiempo en completarse. La opción te permite continuar
realizando otras operaciones y luego verificar el resultado utilizando un
comando separado `dfx canister request-status`. El resultado devuelto se
mostrará en formato textual IDL.

#### Usando la sintaxis IDL

Puedes especificar explícitamente que estás pasando argumentos utilizando la
sintaxis IDL ejecutando comandos similares a los siguientes para un tipo de
datos Text:

```bash
dfx canister call hello greet --type idl '("Lisa")'
("Hello, Lisa!")

dfx canister call hello greet '("Lisa")' --type idl
("Hello, Lisa!")
```

También puedes usar implícitamente el IDL ejecutando un comando similar al
siguiente:

```bash
dfx canister call hello greet '("Lisa")'
("Hello, Lisa!")
```

Para especificar varios argumentos utilizando la sintaxis IDL, utiliza comas
entre los argumentos. Por ejemplo:

```bash
dfx canister call contacts insert '("Amy Lu","01 916-335-2042")'

dfx canister call hotel guestroom '("Deluxe Suite",42,true)'
```

Puedes pasar datos en bruto en bytes ejecutando un comando similar al siguiente:

```bash
dfx canister call hello greet --type raw '4449444c00017103e29883'
```

Este ejemplo utiliza el tipo de datos raw para pasar un hexadecimal a la función
`greet` del canister `hello`.

## Salida en formato JSON

La opción `--output json` formatea la salida como JSON.

Los tipos de datos de Candid no tienen una correspondencia 1:1 con los tipos de
JSON.  
Notablemente, los siguientes tipos de Candid se representan como cadenas en
lugar de números: `nat`, `nat64`, `int`, `int64`.

### Mapeo de tipos de Candid a JSON:

| Tipo Candid | Tipo JSON                 |
| ----------- | ------------------------- |
| `null`      | `null`                    |
| `bool`      | `boolean`                 |
| `nat`       | `string`                  |
| `nat8`      | `number`                  |
| `nat16`     | `number`                  |
| `nat32`     | `number`                  |
| `nat64`     | `string`                  |
| `int`       | `string`                  |
| `int8`      | `number`                  |
| `int16`     | `number`                  |
| `int32`     | `number`                  |
| `int64`     | `string`                  |
| `float32`   | `float` o `"NaN"`         |
| `float64`   | `float` o `"NaN"`         |
| `text`      | `string`                  |
| `opt`       | array con 0 o 1 elementos |
| `vec`       | array                     |
| `record`    | objeto                    |
| `variant`   | objeto                    |
| `blob`      | array de números          |

## `dfx canister create`

El comando `dfx canister create` registra uno o más identificadores de canister
sin código compilado.  
Los nuevos identificadores de canister se almacenan en `canister_ids.json` para
redes no locales.  
Para ejecutar este comando, debes estar conectado a un entorno de ejecución
local o a la Internet Computer.

Nota que solo puedes ejecutar este comando dentro de la estructura del
directorio del proyecto.  
Por ejemplo, si el nombre de tu proyecto es `hello_world`, tu directorio de
trabajo actual debe ser  
el directorio raíz `hello_world` o una de sus subcarpetas.

### Uso básico

```bash
dfx canister create [options] [--all | canister_name]
```

## Opciones

Puedes utilizar las siguientes opciones con el comando `dfx canister create`:

| Opción                                    | Descripción                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-c`, `--compute-allocation <allocation>` | Especifica la asignación de cómputo del canister. Debe ser un porcentaje en el rango [0..100].                                                                                                                                                                                                                                                     |
| `--controller <principal>`                | Especifica el nombre de identidad o el principal del nuevo controlador.                                                                                                                                                                                                                                                                            |
| `--created-at-time <timestamp>`           | Marca de tiempo de la transacción en nanosegundos, utilizada para el control de deduplicación de transacciones. El valor predeterminado es el tiempo del sistema. Más información: [Transaction Deduplication](https://internetcomputer.org/docs/developer-docs/integrations/icrc-1/#transaction-deduplication).                                   |
| `--from-subaccount <subaccount>`          | Subcuenta de la identidad seleccionada desde donde se gastarán los ciclos.                                                                                                                                                                                                                                                                         |
| `--memory-allocation <memory>`            | Especifica la cantidad de memoria total permitida para el canister. Debe estar en el rango [0..12 GiB]. Un valor de `0` significa que el canister tendrá acceso a la memoria según disponibilidad: solo se le cobrará por la memoria que use, pero puede dejar de funcionar si intenta asignar más memoria de la que está disponible en el subnet. |
| `--reserved-cycles-limit <limit>`         | Especifica el límite superior para los ciclos reservados del canister.                                                                                                                                                                                                                                                                             |
| `--wasm-memory-limit <limit>`             | Especifica un límite superior flexible para la memoria del heap del canister.                                                                                                                                                                                                                                                                      |
| `--log-viewer <principal>`                | Especifica el principal como un visor permitido. Se puede especificar varias veces. No puede usarse con `--log-visibility`.                                                                                                                                                                                                                        |
| `--log-visibility <visibility>`           | Especifica quién puede leer los logs del canister: `"controllers"` o `"public"`. Para configurar visores personalizados, usa `--log-viewer`.                                                                                                                                                                                                       |
| `--no-wallet`                             | Ejecuta la llamada con la identidad del usuario como remitente de los mensajes, omitiendo el canister de Wallet. Habilitado por defecto.                                                                                                                                                                                                           |
| `--with-cycles <number-of-cycles>`        | Especifica el saldo inicial de ciclos a depositar en el canister recién creado. La cantidad especificada debe tomar en cuenta la tarifa de creación del canister. Este monto se deduce del saldo de ciclos de la wallet.                                                                                                                           |
| `--specified-id <PRINCIPAL>`              | Intenta crear el canister con este ID de Canister.                                                                                                                                                                                                                                                                                                 |
| `--subnet-type <subnet-type>`             | Especifica el tipo de subnet donde se creará el canister. Si no se proporciona, se asignará automáticamente a una subnet de aplicación por defecto.                                                                                                                                                                                                |
| `--subnet <subnet-principal>`             | Especifica la subnet en la que se creará el canister. Si no se proporciona, se asignará automáticamente a una subnet de aplicación por defecto.                                                                                                                                                                                                    |
| `--next-to <canister-principal>`          | Crea el canister en la misma subnet que el canister especificado.                                                                                                                                                                                                                                                                                  |

---

## Argumentos

Puedes utilizar el siguiente argumento con el comando `dfx canister create`:

| Argumento       | Descripción                                                                                                                                                                                                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--all`         | Permite crear múltiples identificadores de canister a la vez si tienes un archivo `dfx.json` con múltiples canisters definidos. Nota que debes especificar `--all` o un nombre de canister individual.                                                                           |
| `canister_name` | Especifica el nombre del canister para el cual deseas registrar un identificador. Si no usas la opción `--all`, este argumento es obligatorio y debe coincidir con al menos un nombre definido en la sección `canisters` del archivo de configuración `dfx.json` de tu proyecto. |

---

## Ejemplos

Puedes usar el comando `dfx canister create` para registrar identificadores de
canister sin compilar código previamente.  
Por ejemplo, si deseas crear el identificador del canister para el proyecto
`my_counter` antes de escribir el programa,  
puedes ejecutar el siguiente comando:

```bash
dfx canister create my_counter
```

Puedes usar el comando `dfx canister create` con la opción `--with-cycles` para
especificar el saldo inicial al crear un canister o todos los canisters en un
proyecto. Por ejemplo, para especificar un saldo inicial de 8000000000000 ciclos
para todos los canisters, ejecuta el siguiente comando:

```bash
dfx canister create --with-cycles 8000000000000 --all
```

#### Asignación de procesamiento de mensajes

La opción `--compute-allocation` te permite asignar recursos informáticos como
un porcentaje en el rango de 0 a 100 para indicar con qué frecuencia se
programará la ejecución de tu canister.

Por ejemplo, supongamos que ejecutas el siguiente comando:

```bash
dfx canister create --all --compute-allocation 50
```

Con esta configuración, todos los canisters en los proyectos actuales reciben
una asignación del 50%.  
Cuando los canisters en el proyecto reciben mensajes de entrada para procesar,
estos mensajes se programan para su ejecución.  
A lo largo de 100 ciclos de ejecución, los mensajes de cada canister serán
programados para su procesamiento al menos 50 veces.

El valor predeterminado para esta opción es 0, lo que indica que no hay una
asignación o programación específica en efecto.  
Si todos tus canisters usan la configuración predeterminada, el procesamiento
ocurre en un esquema de turnos (round-robin).

## dfx canister delete

Usa el comando `dfx canister delete` para eliminar un canister detenido del
entorno de ejecución local de canisters o del Internet Computer.  
Por defecto, este comando retira los ciclos restantes a tu wallet antes de
eliminar el canister.

Es importante notar que solo puedes ejecutar este comando desde dentro de la
estructura del directorio del proyecto.  
Por ejemplo, si el nombre de tu proyecto es `hello_world`, tu directorio de
trabajo actual debe ser el directorio principal `hello_world` o uno de sus
subdirectorios.

### Uso básico

```bash
dfx canister delete [options] [--all | canister_name]
```

### Opciones

Puedes usar las siguientes opciones con el comando `dfx canister delete`.

| Opción                                            | Descripción                                                                             |
| ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `--no-withdrawal`                                 | No retirar ciclos, solo eliminar el canister.                                           |
| `--initial-margin <ciclos>`                       | Deja esta cantidad de ciclos en el canister al retirar ciclos.                          |
| `--to-subaccount`                                 | Subcuenta de la identidad seleccionada para depositar los ciclos.                       |
| `--withdraw-cycles-to-dank`                       | Retira ciclos a dank con el principal actual.                                           |
| `--withdraw-cycles-to-canister <principal>`       | Retira ciclos de uno o más canisters al canister/wallet especificado antes de eliminar. |
| `--withdraw-cycles-to-dank-principal <principal>` | Retira ciclos a dank con el principal dado.                                             |
| `-y, --yes`                                       | Confirmación automática para eliminar un canister que no esté detenido.                 |

### Argumentos

Puedes usar los siguientes argumentos con el comando `dfx canister delete`.

| Argumento       | Descripción                                                                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `--all`         | Elimina todos los canisters configurados en el archivo `dfx.json`. Nota que debes especificar `--all` o el nombre de un canister individual. |
| `canister_name` | Especifica el nombre del canister que deseas eliminar. Nota que debes especificar el nombre de un canister o la opción `--all`.              |

### Ejemplos

Puedes usar el comando `dfx canister delete` para eliminar un canister
específico o todos los canisters.

Para eliminar el canister `hello_world`, puedes ejecutar el siguiente comando:

```bash
dfx canister delete hello_world
```

Para eliminar todos los canisters que has desplegado en el Internet Computer y
configurados en tu `dfx.json`, puedes ejecutar el siguiente comando:

```bash
dfx canister delete --all --network=ic
```

## dfx canister deposit-cycles

Utiliza el comando `dfx canister deposit-cycles` para depositar ciclos desde tu
billetera configurada en un canister.

Ten en cuenta que debes tener tu billetera de ciclos configurada para que esto
funcione.

### Uso básico

```bash
dfx canister deposit-cycles <cycles> [--all | canister_name]
```

### Argumentos

Puedes usar los siguientes argumentos con el comando
`dfx canister deposit-cycles`.

| Argumento       | Descripción                                                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--all`         | Deposita la cantidad especificada de ciclos en todos los canisters configurados en `dfx.json`. Nota que debes especificar `--all` o el nombre de un canister individual. |
| `canister_name` | Especifica el nombre del canister en el que deseas depositar ciclos. Nota que debes especificar el nombre de un canister o la opción `--all`.                            |

### Opciones

Puedes usar las siguientes opciones con el comando
`dfx canister deposit-cycles`.

| Opción                           | Descripción                                                                                                                                                                                                                                        |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--created-at-time <timestamp>`  | Marca temporal de la transacción, en nanosegundos, para controlar la deduplicación de transacciones, el valor por defecto es la hora del sistema. https://internetcomputer.org/docs/developer-docs/integrations/icrc-1/#transaction-deduplication- |
| `--from-subaccount <subaccount>` | Subcuenta de la identidad seleccionada de donde se retirarán los ciclos.                                                                                                                                                                           |

### Ejemplos

Puedes usar el comando `dfx canister deposit-cycles` para añadir ciclos a un
canister específico o a todos los canisters.

Para añadir 1T ciclos al canister llamado `hello`, puedes ejecutar el siguiente
comando:

```bash
dfx canister deposit-cycles 1000000000000 hello
```

Para añadir 2T ciclos a cada canister individual especificado en `dfx.json`,
puedes ejecutar el siguiente comando:

```bash
dfx canister deposit-cycles 2000000000000 --all
```

## dfx canister id

Usa el comando `dfx canister id` para mostrar el identificador/principal del
canister para un nombre de canister específico.

Ten en cuenta que solo puedes ejecutar este comando desde dentro de la
estructura del directorio del proyecto. Por ejemplo, si el nombre de tu proyecto
es `hello_world`, tu directorio de trabajo actual debe ser el directorio
principal del proyecto `hello_world` o uno de sus subdirectorios.

Si el canister ha sido desplegado por el usuario local, se proporcionará el ID
de canister almacenado localmente.

Si un canister ha sido desplegado por un tercero, el usuario puede configurar la
entrada `.canisters[$CANISTER_NAME].remote[$NETWORK]` en `dfx.json` con el ID

el usuario local debe asegurarse de que tienen el ID correcto del canister.

Si un canister típicamente se despliega con el mismo ID de canister en la red
principal y todas las redes de prueba, el usuario puede configurar un ID de
canister remoto para la red `__default`. En este caso,
`dfx canister id $CANISTER_NAME` devolverá el ID de canister por defecto para
todas las redes que no tengan una entrada dedicada.

### Uso básico

```bash
dfx canister id <canister_name>
```

### Argumentos

Puedes usar el siguiente argumento con el comando `dfx canister id`.

| Argumento       | Descripción                                                                     |
| --------------- | ------------------------------------------------------------------------------- |
| `canister_name` | Especifica el nombre del canister para el cual deseas mostrar un identificador. |

### Ejemplos

## dfx canister install

Utiliza el comando `dfx canister install` para instalar código compilado como un
canister en el Internet Computer o en el entorno de ejecución de canisters
local.

### Uso básico

```bash
dfx canister install [option] [--all | canister_name]
```

### Opciones

Puedes usar las siguientes opciones con el comando `dfx canister install`.

| Opción                             | Descripción                                                                                                                                                                                                                                                            |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--argument <argument>`            | Especifica un argumento para pasar al canister durante la instalación.                                                                                                                                                                                                 |
| `--argument-type <argument-type>`  | Especifica el tipo de dato para el argumento al hacer la llamada usando un argumento [valores posibles: idl, raw]                                                                                                                                                      |
| `--argument-file <argument-file>`  | Especifica el archivo desde el cual leer el argumento para pasar al método init. Se puede referir a la entrada estándar como `-`.                                                                                                                                      |
| `--async-call`                     | Te permite continuar sin esperar el resultado de la instalación, que será devuelto mediante la comprobación en la red de Internet Computer o en el entorno de ejecución local del canister.                                                                            |
| `-m`, `--mode <mode>`              | Especifica si deseas `instalar`, `reinstalar` o `actualizar` los canisters. Por defecto es `install`. Para más información sobre los modos de instalación y la gestión de canisters, consulta [gestionar canisters](/docs/building-apps/canister-management/settings). |
| `--no-wallet`                      | Realiza la llamada con la identidad del usuario como remitente de los mensajes. Omite el canister de la cartera. Habilitado por defecto.                                                                                                                               |
| `--no-asset-upgrade`               | Omite la actualización del canister de activos, solo instalando los propios activos.                                                                                                                                                                                   |
| `--upgrade-unchanged`              | Actualiza el canister incluso si el .wasm no ha cambiado.                                                                                                                                                                                                              |
| `--wasm <file.wasm>`               | Especifica un archivo Wasm particular para instalar, omitiendo la configuración del proyecto `dfx.json`.                                                                                                                                                               |
| `--skip-pre-upgrade`               | Omite el hook de pre_upgrade durante la actualización. Esto requiere el modo upgrade/auto.                                                                                                                                                                             |
| `--wasm-memory-persistence <mode>` | Mantiene o reemplaza la memoria principal del Wasm en la actualización. Valores posibles: keep, replace. Esto requiere el modo upgrade/auto.                                                                                                                           |

#### Especifica el argumento para pasar al punto de entrada init

Con `--argument-type`, puedes especificar el formato de datos para el argumento
cuando instales utilizando la opción `--argument`. Los valores válidos son `idl`
y `raw`. Por defecto, puedes especificar argumentos utilizando la
[sintaxis de Candid](/docs/building-apps/interact-with-canisters/candid/candid-concepts)
(`idl`) para los valores de datos. Para información sobre cómo usar Candid y sus
tipos soportados, consulta
[Interactuar con un servicio en un terminal](/docs/building-apps/interact-with-canisters/candid/using-candid#idl-syntax)
y [Tipos soportados](/docs/references/candid-ref). Puedes usar `raw` como el
tipo de argumento si deseas pasar bytes sin procesar a un canister.

### Argumentos

Puedes usar los siguientes argumentos con el comando `dfx canister install`.

| Argumento       | Descripción                                                                                                                                                                                                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--all`         | Te permite instalar varios canisters a la vez si tienes un archivo de proyecto `dfx.json` que incluye múltiples canisters. Ten en cuenta que debes especificar `--all` o el nombre de un canister individual.                                                                    |
| `canister_name` | Especifica el nombre del canister a desplegar. Si no estás utilizando la opción `--all`, el nombre del canister es un argumento requerido y debe coincidir con el nombre que has configurado para un proyecto en la sección `canisters` del archivo de configuración `dfx.json`. |

### Ejemplos

Puedes usar el comando `dfx canister install` para desplegar el WebAssembly que
has compilado utilizando el comando `dfx build` como un canister en la red de
Internet Computer o en el entorno de ejecución local del canister. El caso de
uso más común es instalar todos los canisters ejecutando el siguiente comando:

```bash
dfx canister install --all
```

#### Instalando un canister específico

También puedes usar el comando `dfx canister install` para desplegar un canister
específico en lugar de todos los canisters de tu proyecto. Por ejemplo, si
tienes un proyecto con un canister `hello_world_backend` y un canister
`hello_world_frontend` pero solo quieres desplegar el canister
`hello_world_backend`, puedes desplegar solo ese canister ejecutando el
siguiente comando:

```bash
dfx canister install hello_world_backend
```

#### Enviando una solicitud asíncrona

Si deseas enviar una solicitud para instalar el canister y obtener un
identificador de solicitud para verificar el estado de tu solicitud más tarde en
lugar de esperar a que el comando se complete, puedes ejecutar un comando
similar al siguiente:

```bash
dfx canister install hello_world_backend --async
```

Este comando envía una solicitud para instalar el canister y devuelve un
identificador de solicitud similar al siguiente:

```bash
0x58d08e785445dcab4ff090463b9e8b12565a67bf436251d13e308b32b5058608
```

Puedes usar el identificador de solicitud para verificar el estado de la
solicitud en un momento posterior, al igual que un número de seguimiento si
estuvieras enviando un paquete.

#### Anulando las opciones de implementación predeterminadas

Si deseas implementar un canister en una red de prueba sin cambiar la
configuración en tu archivo de configuración `dfx.json`, puedes especificar
explícitamente la red de prueba a la que deseas conectarte utilizando la opción
`--network`.

Por ejemplo, puedes especificar una URL de red de prueba ejecutando un comando
similar al siguiente:

```bash
dfx canister install --all --network http://192.168.3.1:5678
```

## dfx canister sign

Usa el comando `dfx canister sign` antes de enviar un mensaje con el comando
`dfx canister send` cuando quieras separar estos pasos, en lugar de usar el
único comando `dfx canister call`. Usar llamadas separadas puede agregar
seguridad a la transacción. Por ejemplo, cuando creas tu participación en
neuronas, puedes querer usar el comando `dfx canister sign` para crear un
archivo `message.json` firmado utilizando una computadora aislada, y luego usar
el comando `dfx canister send` para entregar el mensaje firmado desde una
computadora conectada a Internet Computer.

### Uso básico

```bash
dfx canister sign [options] <canister-name> <method-name> [argument]
```

### Opciones

Puedes especificar las siguientes opciones para el comando `dfx canister sign`.

| Opción                     | Descripción                                                                                                                                                                      |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--argument-file <file>`   | Especifica el archivo desde el cual leer el argumento para pasar al método. Stdin puede ser referido como `-`.                                                                   |
| `--expire-after <seconds>` | Especifica cuánto tiempo será válido el mensaje antes de que expire y no pueda ser enviado. Se debe especificar en segundos. Si no se define, el valor por defecto es 300s (5m). |
| `--file <output>`          | Especifica el nombre del archivo de salida. El valor por defecto es `message.json`.                                                                                              |
| `--query`                  | Envía una solicitud de consulta a un canister.                                                                                                                                   |
| `--random <random>`        | Especifica la configuración para generar argumentos aleatorios.                                                                                                                  |
| `--type <type>`            | Especifica el tipo de datos para el argumento al realizar una llamada usando un argumento. Los valores posibles son `idl` y `raw`.                                               |
| `--update`                 | Envía una solicitud de actualización al canister. Este es el método por defecto si no se utiliza el método `--query`.                                                            |

### Argumentos

Puedes especificar los siguientes argumentos para el comando
`dfx canister sign`.

| Argumento       | Descripción                                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `canister_name` | Especifica el nombre del canister al que se llama. El nombre del canister es un argumento obligatorio y debe coincidir con el nombre configurado para un proyecto en la sección `canisters` del archivo de configuración `dfx.json`. |
| `method_name`   | Especifica el nombre del método a llamar en el canister. El método del canister es un argumento obligatorio.                                                                                                                         |
| `argument`      | Especifica el argumento a pasar al método                                                                                                                                                                                            |

#### Especifica el argumento a pasar al método

Dependiendo de la lógica de tu programa, el argumento puede ser obligatorio u
opcional. Puedes especificar un tipo de formato de datos usando la opción
`--type` si pasas un argumento al canister. De forma predeterminada, puedes
especificar los argumentos usando la sintaxis de
[Candid](/docs/references/candid-ref) (`idl`) para los valores de los datos.
Para más información sobre cómo usar Candid y sus tipos soportados, consulta
[Interactuar con un servicio en una terminal](/docs/building-apps/interact-with-canisters/candid/using-candid#idl-syntax)
y [tipos soportados](/docs/references/candid-ref#supported-types). Puedes usar
`raw` como tipo de argumento si deseas pasar bytes sin procesar.

### Ejemplos

Usa el comando `dfx canister sign` para crear un archivo firmado `message.json`
usando la identidad seleccionada ejecutando un comando similar al siguiente:

`dfx canister sign --network=ic --expire-after=1h rno2w-sqaaa-aaaaa-aaacq-cai create_neurons ‘(“PUBLIC_KEY”)’`

Este comando muestra cómo crear un archivo `message.json` para crear neuronas en
Internet Computer especificado por el alias `ic`, que está firmado utilizando tu
identificador principal como el remitente del mensaje y con una ventana de
expiración que termina en una hora.

Nota que el tiempo permitido para enviar un mensaje firmado es una ventana fija
de 5 minutos. La opción `--expire-after` te permite especificar el momento en
que debe terminar la ventana de 5 minutos para enviar el mensaje firmado. Por
ejemplo, si configuras la opción `--expire-after` a una hora (`1h`), debes
esperar al menos 55 minutos antes de enviar el mensaje generado, y la firma del
mensaje será válida solo durante la ventana de 5 minutos que termina en el
minuto 60.

En este ejemplo, por lo tanto, necesitarías enviar el mensaje después de 55
minutos y antes de 60 minutos para que el mensaje sea reconocido como válido.

Si no especificas la opción `--expire-after`, la expiración por defecto es de
cinco minutos.

Envía el mensaje firmado al canister de token génesis (GTC) para crear un neurón
en tu nombre ejecutando el siguiente comando:

`dfx canister send message.json`

## dfx canister uninstall-code

Usa el comando `dfx canister uninstall-code` para desinstalar el código de un
canister que se está ejecutando actualmente en Internet Computer o en el entorno
de ejecución local del canister.

Este método elimina el código y el estado de un canister, dejándolo vacío
nuevamente. Solo el controlador del canister puede desinstalar el código.
Desinstalar el código de un canister rechazará todas las llamadas a las que el
canister aún no haya respondido y eliminará el código y el estado del canister.
Las respuestas pendientes al canister no se procesarán, incluso si llegan
después de que se haya instalado el código nuevamente. El canister ahora está
vacío.

Ten en cuenta que solo puedes ejecutar este comando desde dentro de la
estructura del directorio del proyecto. Por ejemplo, si el nombre de tu proyecto
es `hello_world`, tu directorio de trabajo actual debe ser el directorio
principal del proyecto `hello_world` o uno de sus subdirectorios.

### Uso básico

```bash
dfx canister uninstall-code [--all | canister_name]
```

### Argumentos

Puedes usar los siguientes argumentos con el comando
`dfx canister uninstall-code`.

| Argumento       | Descripción                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--all`         | Desinstala todos los canisters configurados en el archivo `dfx.json`. Ten en cuenta que debes especificar `--all` o el nombre de un canister individual. |
| `canister_name` | Especifica el nombre del canister que deseas desinstalar. Ten en cuenta que debes especificar un nombre de canister o la opción `--all`.                 |

### Ejemplos

Puedes usar el comando `dfx canister uninstall-code` para desinstalar un
canister específico o todos los canisters.

Para desinstalar el canister `hello_world`, puedes ejecutar el siguiente

## dfx canister update-settings

Usa el comando `dfx canister update-settings` para actualizar la configuración
de un canister que se está ejecutando en el entorno de ejecución local.

En la mayoría de los casos, ejecutas este comando para ajustar la cantidad de
recursos asignados a tu canister.

Ten en cuenta que solo puedes ejecutar este comando desde dentro de la
estructura del directorio del proyecto. Por ejemplo, si el nombre de tu proyecto
es `hello_world`, tu directorio de trabajo actual debe ser el directorio
principal del proyecto `hello_world` o uno de sus subdirectorios.

### Uso básico

```bash
dfx canister update-settings [options] [canister_name | --all]
```

### Opciones

Puedes especificar las siguientes opciones para el comando
`dfx canister update-settings`.

| Opción                                    | Descripción                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--add-controller <principal>`            | Agrega un principal a la lista de controladores del canister.                                                                                                                                                                                                                                                                                                                              |
| `--add-log-viewer <principal>`            | Agrega un principal a la lista de visualizadores de registros del canister. Puede especificarse más de una vez para agregar varios visualizadores. Si la visibilidad actual de los registros es `public` o `controllers`, se cambiará a la lista personalizada de visualizadores permitidos.                                                                                               |
| `-c`, `--compute-allocation <allocation>` | Especifica la asignación de cómputo del canister. Este valor debe estar en el rango [0..100].                                                                                                                                                                                                                                                                                              |
| `--confirm-very-long-freezing-threshold`  | Los umbrales de congelación superiores a ~1.5 años requieren esta opción como confirmación.                                                                                                                                                                                                                                                                                                |
| `--set-controller <principal>`            | Especifica el nombre de identidad o el principal del nuevo controlador. Puede especificarse más de una vez, lo que indica que el canister tendrá múltiples controladores. Si se establece algún controlador con este parámetro, se eliminarán los otros controladores.                                                                                                                     |
| `--set-log-viewer <principal>`            | Especifica el principal del visualizador de registros del canister. Puede especificarse más de una vez, lo que indica que el canister tendrá varios visualizadores de registros. Si se establece algún visualizador de registros con este parámetro, se eliminarán otros visualizadores de registros.                                                                                      |
| `--memory-allocation <allocation>`        | Especifica cuánta memoria se le permite usar al canister en total. Este valor debe estar en el rango [0..12 GiB]. Un valor de 0 significa que el canister tendrá acceso a la memoria de forma "por esfuerzo": solo se le cobrará por la memoria que use, pero en cualquier momento puede dejar de funcionar si intenta asignar más memoria cuando no haya espacio disponible en la subred. |
| `--reserved-cycles-limit <limit>`         | Especifica el límite superior de ciclos reservados del canister.                                                                                                                                                                                                                                                                                                                           |
| `--wasm-memory-limit <limit>`             | Especifica un límite superior suave para la memoria del montón del canister.                                                                                                                                                                                                                                                                                                               |
| `--log-visibility <visibility>`           | Especifica quién puede leer los registros del canister. Puede ser "controllers" o "public". Para visualizadores personalizados, usa `--set-log-viewer` o `--add-log-viewer`.                                                                                                                                                                                                               |
| `--remove-controller <principal>`         | Elimina un principal de la lista de controladores del canister.                                                                                                                                                                                                                                                                                                                            |
| `--remove-log-viewer <principal>`         | Elimina un principal de la lista de visualizadores de registros del canister. Puede especificarse más de una vez para eliminar varios visualizadores de registros.                                                                                                                                                                                                                         |
| `--freezing-threshold <seconds>`          | Establece el [umbral de congelación](/docs/references/ic-interface-spec/#ic-create_canister) en segundos para un canister. Este valor debe estar en el rango [0..2^64^-1]. Los umbrales muy largos requieren la opción `--confirm-very-long-freezing-threshold`.                                                                                                                           |
| `-y`, `--yes`                             | Omite las comprobaciones de sí/no respondiendo 'sí'. No se recomienda fuera de CI, ya que tales comprobaciones pueden resultar en la pérdida de control.                                                                                                                                                                                                                                   |

### Argumentos

Puedes usar los siguientes argumentos con el comando
`dfx canister update-settings`.

| Argumento       | Descripción                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `--all`         | Actualiza todos los canisters especificados en `dfx.json`. Debes especificar el nombre/id del canister o la opción --all. |
| `canister_name` | Especifica el nombre del canister que deseas actualizar. Debes especificar el nombre/id del canister o la opción --all.   |

### Ejemplos

Puedes usar el comando `dfx canister update-settings` para actualizar la
configuración de un canister específico.

Para actualizar la configuración del canister `hello_world`, puedes ejecutar el
siguiente comando:

```bash
dfx canister update-settings --freezing-threshold 2592000 --compute-allocation 99 hello_world
```

## dfx canister url

Usa el comando `dfx canister url` para obtener la URL de un canister específico.

Ten en cuenta que solo puedes ejecutar este comando desde dentro de la
estructura del directorio del proyecto. Por ejemplo, si el nombre de tu proyecto
es `hello_world`, tu directorio de trabajo actual debe ser el directorio
principal de `hello_world` o uno de sus subdirectorios.

Si el canister ha sido desplegado por el usuario local, se proporcionará el ID
del canister almacenado localmente dentro de la URL. Puedes consultar el archivo
`.dfx/local/canister_ids.json` en el directorio del proyecto para obtener más
detalles.

Si un canister ha sido desplegado por un tercero, el usuario puede configurar la
entrada `.canisters[$CANISTER_NAME].remote[$NETWORK]` en el archivo `dfx.json`
con el ID del canister. En este caso, el tercero es responsable de mantener el
canister y el usuario local debe asegurarse de tener el ID correcto del
canister. `dfx` usará el ID proporcionado sin realizar más comprobaciones.

### Uso básico

```bash
dfx canister url <canister>
```

### Argumentos

Puedes usar el siguiente argumento con el comando `dfx canister url`.

| Argumento  | Descripción                                                                |
| ---------- | -------------------------------------------------------------------------- |
| `canister` | Especifica el nombre o id del canister para el cual deseas mostrar la URL. |

### Ejemplos

Para mostrar la URL del canister `hello_world_backend`, puedes ejecutar el
siguiente comando:

```bash
dfx canister url hello_world_backend
```

El comando muestra una salida similar a la siguiente:

```bash
http://127.0.0.1:4943/?canisterId=br5f7-7uaaa-aaaaa-qaaca-cai&id=bkyz2-fmaaa-aaaaa-qaaaq-cai
```

El `bkyz2-fmaaa-aaaaa-qaaaq-cai` es el id del canister para `__Candid_UI`
canister en el entorno de ejecución local. Necesitas ejecutar `dfx deploy` para
generar la entrada local `__Candid_UI` en `.dfx/local/canister_ids.json`
primero.

Si ejecutas:

```bash
dfx canister url hello_world_backend --network ic
```

El comando muestra una salida similar a la siguiente:

```bash
https://a4gq6-oaaaa-aaaab-qaa4q-cai.raw.icp0.io/?id=bkyz2-fmaaa-aaaaa-qaaaq-cai
```

El `a4gq6-oaaaa-aaaab-qaa4q-cai` es el id del canister para `__Candid_UI` en la
red principal de Internet Computer (mainnet).
