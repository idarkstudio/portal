# dfx.json opciones de configuración

<MarkdownChipRow labels={["dfx", "Referencia"]} />

Cada proyecto creado y desplegado con `dfx` requiere un archivo `dfx.json`
presente en el directorio raíz del proyecto. El archivo `dfx.json` configura los
ajustes del proyecto, como los canisters en el proyecto, su nombre, tipo y
archivo fuente, la configuración de compilación predeterminada del proyecto y
otros parámetros de configuración como las optimizaciones de Wasm. Esta página
detallará algunas de las opciones de configuración más comunes. Para obtener una
lista completa de las posibles configuraciones en `dfx.json`, consulta el
[esquema `dfx.json`](/docs/building-apps/developer-tools/dfx-json-reference).

## Archivo `dfx.json` predeterminado

Por defecto, cuando se crea un proyecto con `dfx new <nombre-del-proyecto>` y se
seleccionan las opciones `Motoko` y `Sin canister de frontend`, el `dfx.json`
predeterminado generado para el proyecto contendrá lo siguiente:

```json
{
  "canisters": {
    "example_backend": {
      "main": "src/example_backend/main.mo",
      "type": "motoko"
    }
  },
  "defaults": {
    "build": {
      "args": "",
      "packtool": ""
    }
  },
  "output_env_file": ".env",
  "version": 1
}%
```

Esta configuración contiene los siguientes componentes:

- `canisters`: Define los nombres y configuraciones de los canisters para el
  proyecto. En este ejemplo predeterminado, se define un único canister llamado
  `example_backend`.

- `example_backend`: Define el nombre del canister en este proyecto.

- `main`: El archivo de código fuente principal del canister que sirve como
  punto de entrada del mismo. Por defecto, para los canisters en Motoko, este
  archivo es `main.mo`. Para los canisters en Rust, se usa la palabra clave
  `candid` en lugar de `main` para definir el punto de entrada de un canister.

- `type`: Define el tipo de canister. Los tipos admitidos son `motoko`, `rust`,
  `assets`, `pull` y `custom`. Los lenguajes Motoko y Rust son compatibles de
  forma predeterminada a través del IC SDK. El tipo `custom` se refiere a
  canisters escritos en otros lenguajes distintos de Motoko o Rust. El tipo
  `assets` se refiere a [canisters de frontend](#asset-canisters). El tipo
  `pull` se refiere a [canisters de terceros](#pullable-canisters).

- `defaults`: Configuraciones predeterminadas para la compilación del proyecto.

- `build`: Configuración del proceso de compilación.

- `args`: Argumentos para la configuración de `packtool`.

- `packtool`: Configura una herramienta de gestión de paquetes para las
  dependencias de tu canister. Algunos ejemplos incluyen `mops` y `vessel` para
  Motoko.

- `output_env_file`: Las variables de entorno se escribirán en este archivo sin
  sobrescribir ninguna variable definida por el usuario si el archivo ya existe.

- `version`: Se refiere a la versión de iteración de este archivo `dfx.json`.
  Por defecto, las versiones de `dfx.json` comienzan en `version: 1`.

## Definiciones de canisters personalizados

Para definir un canister que use un lenguaje distinto de `Motoko` o `Rust`, o
para usar un archivo Wasm personalizado, puedes establecer el canister como
`"type": "custom"` con los siguientes argumentos adicionales:

```json
"canisters": {
"example_backend": {
    "build": "npx azle example_backend",
    "candid": "src/example_backend/example_backend.did",
    "gzip": true,
    "main": "src/example_backend/src/index.ts",
    "type": "custom",
    "wasm": ".azle/example_backend/example_backend.wasm"
}
}
```

- `build`: El comando que construirá el canister.

- `candid`: La ruta al archivo de definición de la interfaz Candid del canister.

- `gzip`: `true` o `false`, si se debe usar la compresión gzip para el archivo
  Wasm.

- `main`: El archivo de código fuente principal del canister que sirve como
  punto de entrada del canister.

- `type`: Define el canister como `custom`.

- `wasm`: La ruta al archivo Wasm del canister.

## Canisters de assets

Un canister de assets es un tipo de canister que contiene la interfaz de usuario
del frontend y los archivos de assets de un proyecto. Para los proyectos creados
con el comando `dfx new <nombre_proyecto>` y con 'Vanilla JS' seleccionado como
el framework del frontend, el archivo `dfx.json` del proyecto contendrá la
siguiente definición para el canister de assets:

```json
  "canisters": {
    "example_frontend": {
      "dependencies": [
        "example_backend"
      ],
      "source": [
        "src/example_frontend/dist"
      ],
      "type": "assets",
      "workspace": "example_frontend"
    }
  },
```

- `dependencies`: Define qué canister depende el canister de assets para
  comunicarse.

- `source`: El directorio del proyecto que contiene los archivos fuente del
  canister de assets.

- `type`: Define el canister como tipo `assets`.

- `workspace`: El directorio del proyecto que contiene el archivo `package.json`
  de este canister.

## Canisters Pullables

Los canisters que proporcionan un servicio público con un ID de canister
estático pueden ser integrados en tu proyecto definiendo `"type": "pull"`. Esto
indica que el archivo Wasm y Candid del canister serán descargados desde el ID
del canister especificado en la mainnet.

A continuación se muestra un ejemplo de proyecto que define tres canisters:
`dapp`, que depende de `dep_b` y `dep_c`, ambos son canisters pullables:

```json
{
  "canisters": {
    "dapp": {
      "type": "motoko",
      "main": "src/main.mo",
      "dependencies": ["dep_b", "dep_c"]
    },
    "dep_b": {
      "type": "pull",
      "id": "yhgn4-myaaa-aaaaa-aabta-cai"
    },
    "dep_c": {
      "type": "pull",
      "id": "yahli-baaaa-aaaaa-aabtq-cai"
    }
  }
}
```

- `type`: Define el canister como tipo `pull`, lo que significa que los archivos
  Wasm y Candid del canister se obtendrán de la mainnet.

- `id`: Especifica el ID del canister en la mainnet que se debe utilizar para
  obtener los archivos Wasm y Candid.

## Configuración de la red

Se pueden configurar los ajustes de la red de desarrollo local en `dfx.json`,
como:

```json
"networks": {
    "dev": {
      "providers": [
        "https://ic0.app"
      ],
      "type": "persistent"
    }
  }
```

Las definiciones de red pueden tener los siguientes componentes de
configuración:

- `providers`: Define el proveedor de red, que puede ser localhost o cualquier
  otro nombre de dominio. Los nombres de dominio deben ser una URL completa,
  como `https://dominio.com`.

- `type`: Define el tipo de red, que puede ser efímera (no conserva los mismos
  IDs de canister) o persistente (conserva los mismos IDs de canister).

[Aprende más sobre definiciones y configuraciones de red personalizadas](/docs/building-apps/developer-tools/advanced-dfx/networks-json).

## Opciones de optimización de Wasm

Los canisters se pueden optimizar utilizando
[`wasm-opt`](https://github.com/WebAssembly/binaryen), que expone algunas
opciones de optimización diferentes utilizando la configuración `optimize`:

```json
{
  "canisters": {
    "my_canister": {
      "optimize": "cycles"
    }
  }
}
```

- `optimize`: Los valores posibles son `cycles` y `size`. El valor `cycles`
  optimiza tu canister en un `nivel 3` en `wasm-opt`, que es el valor
  recomendado por defecto. `size` proporciona una optimización agresiva del
  tamaño binario. Obtén más información en la documentación de
  [`wasm-opt`](https://github.com/WebAssembly/binaryen).
