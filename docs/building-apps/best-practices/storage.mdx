# Mejores prácticas para desarrolladores: Almacenamiento

<MarkdownChipRow labels={["Principiante", "Mejores prácticas"]} />

Existen dos formas de almacenamiento disponibles para los canisters de ICP:
**memoria heap** y **memoria estable**.

La **memoria heap** es la memoria Wasm de un canister. Esta memoria no almacena
datos a largo plazo. La memoria heap se borra cada vez que se actualiza un
canister. La memoria heap está limitada a 4GiB. Se utiliza de forma
predeterminada para datos como valores de variables, argumentos pasados a un
canister y el resultado de la ejecución de un método.

La **memoria estable** es un tipo de almacenamiento secundario que se utiliza
para almacenar datos a largo plazo. Los datos de la memoria estable se mantienen
a lo largo de la vida útil del canister, incluyendo las actualizaciones del
canister. La memoria estable está limitada a 500GiB. Para utilizar la memoria
estable, debes anticipar qué datos deseas persistir en diferentes procesos y
estados del canister.

| Característica de memoria   | Memoria heap                                                             | Memoria estable                                                                                   |
| --------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Capacidad de almacenamiento | 4GiB                                                                     | 500GiB                                                                                            |
| Uso previsto                | Conjuntos de datos pequeños, datos de acceso frecuente, datos temporales | Conjuntos de datos grandes, datos de acceso poco frecuente, datos importantes que deben persistir |
| Persistencia                | No persiste en las actualizaciones                                       | Los datos se conservan y persisten en las actualizaciones                                         |
| Rendimiento                 | Operaciones de lectura/escritura rápidas                                 | Operaciones de lectura/escritura ligeramente disminuidas                                          |

[Aprende más sobre el almacenamiento de canisters](/docs/building-apps/canister-management/storage).

## Mejores prácticas de almacenamiento

### Recomendación: Utiliza la memoria estable directamente.

Se recomienda utilizar la memoria estable directamente, como a través de
[estructuras estables](https://github.com/dfinity/stable-structures), para
cualquier dato que sea importante. Vincular datos al binario Wasm de tu canister
y utilizar ganchos de pre/post actualización puede ser extremadamente
arriesgado. Existen varias áreas donde pueden ocurrir errores o errores que
pueden resultar en pérdida de datos.

### Recomendación: Utiliza la memoria heap para conjuntos de datos pequeños.

Los datos de la memoria heap son más adecuados para conjuntos de datos pequeños
(menos de 4GiB) o datos que se acceden con frecuencia y no son necesarios para
una persistencia a largo plazo.

### Recomendación: Utiliza la memoria estable para conjuntos de datos grandes.

La memoria estable debe utilizarse para conjuntos de datos grandes (más de 4GiB
pero menos de 500GiB) o datos que se acceden con poca frecuencia.

En última instancia, la forma de memoria que elijas utilizar para tu canister
dependerá del flujo de trabajo más óptimo para tu proyecto.
