# Mejores prácticas para desarrolladores: General

<MarkdownChipRow labels={["Principiante", "Mejores prácticas"]} />

Esta guía describe las mejores prácticas de desarrollo esenciales para construir
en el Protocolo de Internet Computer (ICP).

### Recomendación: Recarga generosa de cycles de canister.

Asegúrate de que todos los canisters tengan suficientes cycles para mantener las
operaciones durante varios años inicialmente. Dado el costo-efectividad del
almacenamiento y la computación en ICP en comparación con otras plataformas,
esta inversión inicial suele ser modesta.

Consulta la página de
[topping up cycles](/docs/building-apps/canister-management/topping-up) para
aprender cómo recargar cycles de manera efectiva.

Consulta la página de
[estimación de cycles](/docs/building-apps/essentials/gas-cost) para estimar el
uso de cycles.

### Recomendación: Gestión de la depleción de cycles.

ICP cuenta con un mecanismo para evitar que los canisters se queden sin cycles.
Los canisters tienen un `freezing_threshold` configurable, evaluado
dinámicamente en cycles. Establece `freezing_threshold` de manera conservadora,
asegurando al menos 90 a 180 días de cycles para una gestión proactiva.

Consulta
[este recurso](/docs/building-apps/canister-management/topping-up#managing-cycle-depletion-with-freezing-threshold)
para aprender cómo configurar el `freezing_threshold` de un canister.

Para asegurarte de no sorprenderte con una alta tasa de consumo de cycles o
alcanzar un límite de instrucciones, puedes utilizar la API de
[contadores de rendimiento](https://internetcomputer.org/blog/features/async-performance-counter)
recientemente agregada para perfilar tus canisters incluso antes de lanzarlos.

### Recomendación: Implementaciones eficientes.

Optimiza la implementación del canister para evitar costos innecesarios.

Utiliza
[temporizadores de canister](/docs/building-apps/network-features/periodic-tasks-timers)
en lugar de latidos simples para reducir los costos diarios.

#### Motoko

1. Opta por `TrieMap` en lugar de `HashMap` para evitar los costos de
   redimensionamiento automático.
2. Utiliza `Buffer` en lugar de `Array` para redimensionamiento dinámico.
3. Considera `Blob` en lugar de `[Nat8]` para un almacenamiento compacto y una
   menor presión en la recolección de basura (GC):

   - Utiliza `Blob` en lugar de `[Nat8]` para almacenar activos binarios
     grandes.
   - Utiliza `Blob` en lugar de `[Nat8]` al enviar o recibir valores Candid
     `vec nat8/blob`. La elección es tuya, pero los `Blobs` son 4 veces más
     compactos y mucho menos exigentes para la recolección de basura (GC).

4. Almacena `Blobs` grandes en memoria estable para una gestión manual
   eficiente.
5. Utiliza la configuración `compacting-gc`, especialmente en escenarios de solo
   agregado, para permitir el acceso a montones más grandes y reducir el costo
   de copiar objetos grandes y estacionarios.
6. Ten cuidado al llamar a una [clase de
   actor]((/docs/motoko/main/writing-motoko/actor-classes), ya que el costo es
   similar al de instalar un canister nuevo.

#### Rust

1. Ten cuidado con los tipos `Vec<u8>` y `String` para la serialización del
   estado. Debido a las limitaciones de Rust, el uso de estos tipos aumentaría
   el número de instrucciones necesarias para codificar o decodificar el
   mensaje.
2. Consulta blogs y artículos recomendados para el desarrollo efectivo de
   canisters en Rust.

### Recomendación: Respaldo y restauración del estado.

Implementa mecanismos de respaldo dentro de los canisters para proteger el
estado contra problemas de desasignación o actualización. Explora
[estrategias de respaldo](https://forum.dfinity.org/t/backup-restore-function-for-a-canister/12849/3)
como las empleadas por [Distrikt](https://distrikt.app/).

### Recomendación: Almacenamiento del historial de transacciones.

Si tu aplicación necesita almacenar el historial de transacciones, considera
utilizar servicios dedicados como [CAP](https://cap.ooo/) para mantener
registros de transacciones. Esto facilita la integración con exploradores y
billeteras, y ayuda en la reconstrucción del estado de propiedad en caso de que
el canister principal se vea comprometido. Ten en cuenta los costos adicionales
asociados con las llamadas entre canisters.
