# Arquitectura de la aplicación

<MarkdownChipRow labels={["Principiante", "Empezando"]} />

Las aplicaciones desplegadas en ICP están compuestas por uno o más contratos
inteligentes, llamados canisters. Un canister contiene código en forma de un
módulo WebAssembly (Wasm) y estado, es decir, los datos almacenados en el
canister.

La arquitectura predeterminada tiene dos canisters:

- **Canister de backend**: Se utiliza para almacenar los datos de la aplicación
  y proporcionar puntos finales para acceder y modificar los datos. Los
  canisters de backend se pueden escribir en una variedad de lenguajes
  diferentes (Motoko, Rust, TypeScript, y más) a través del uso de kits de
  desarrollo de canisters (CDKs). Cada CDK incluye scripts de compilación que
  compilan el código de backend en un módulo Wasm compatible con ICP.

- **Canister de frontend**: Almacena los assets web para la interfaz de usuario
  de la aplicación y interactúa con el backend. El canister de frontend contiene
  un módulo Wasm llamado "canister de assets" al que se cargan los assets web.

## Estructura y archivos del proyecto

Una aplicación predeterminada, como el ejemplo de "Hello, world!" disponible en
ICP Ninja, tiene la siguiente estructura:

```
hello
├── README.md
├── dfx.json
├── package.json
├── src
│   ├── hello_backend
│   │   └── main.mo
│   └── hello_frontend
│       ├── index.html
│       ├── package.json
│       └── vite.config.js
```

- `dfx.json`: Define la estructura del proyecto, incluyendo cómo construirlo y
  desplegarlo.

- `src/hello_backend/`: Contiene el código del backend. Este ejemplo utiliza
  Motoko.

- `src/hello_frontend/`: Contiene los activos del frontend.

### dfx.json​

El archivo `dfx.json` en el directorio raíz define los canisters que componen la
aplicación y dónde se encuentra su código fuente. El proyecto `hello` tiene dos
canisters, el backend en Motoko y un canister de activos para el frontend:

```json title=dfx.json
{
  "canisters": {
    "hello_backend": {
      // Nombre del canister de backend
      "main": "src/hello_backend/main.mo", // Archivo de código fuente del canister de backend
      "type": "motoko" // Lenguaje del canister
    },
    "hello_frontend": {
      // Nombre del canister de frontend
      "dependencies": ["backend"], // El frontend depende del backend
      "frontend": {
        "entrypoint": "hello_frontend/index.html" // Archivo que se cargará como punto de entrada de la aplicación
      },
      "source": ["hello_frontend"], // Directorio para los archivos de activos
      "type": "assets" // Este canister se convertirá en un canister de activos
    }
  },
  "defaults": {
    "build": {
      "args": "",
      "packtool": ""
    }
  },
  "output_env_file": ".env",
  "version": 1
}
```

Aprende más sobre [dfx.json](/docs/building-apps/developer-tools/dfx-json).

## Backend​

El archivo `src/hello_backend/main.mo` contiene el código fuente del backend
escrito en [Motoko](/docs/motoko/main/getting-started/motoko-introduction):

```motoko
actor HelloWorld {
 stable var greeting : Text = "Hello, ";


 // Este método de actualización almacena el prefijo de saludo en la memoria estable.
 public func setGreeting(prefix : Text) : async () {
  greeting := prefix;
 };


 // Este método de consulta devuelve el saludo actualmente persistido con el nombre dado.
 public query func greet(name : Text) : async Text {
   return greeting # name # "!";
 };
};
```

Vamos a desglosar lo que hace este código:

1. El código primero define un
   [actor](/docs/motoko/main/writing-motoko/actors-async) llamado `HelloWorld`.
   Un actor es un objeto que puede almacenar estado e interactuar con el mundo a
   través del paso de mensajes.

2. Luego, define una variable estable
   [stable variable](/docs/motoko/main/canister-maintenance/upgrades) llamada
   `greeting`. Las variables estables se utilizan para almacenar datos que
   persistirán en las actualizaciones del canister.
   [Aprende más sobre cómo actualizar canisters](/docs/building-apps/canister-management/upgrade).

3. A continuación, se define un método de actualización
   [update method](/docs/building-apps/interact-with-canisters/update-calls)
   llamado `setGreeting`. Los métodos de actualización alteran el estado del
   canister. Este método específicamente actualizará el texto almacenado en la
   variable `greeting`.

4. Por último, se define un método de consulta
   [query method](/docs/building-apps/interact-with-canisters/query-calls)
   llamado `greet`. Los métodos de consulta son operaciones de solo lectura y
   simplemente devuelven datos del canister. No pueden alterar el estado del
   canister. Este método de consulta devolverá el texto almacenado en
   `greeting`, seguido del texto pasado al método. La sintaxis de este método se
   puede desglosar y explicar aún más:

- `public`: Permite que el método sea llamado públicamente por usuarios u otros
  canisters.

- `query`: Define el tipo de llamada que acepta el método.

- `greet`: El nombre del método.

- `(name : Text) : async Text`: Indica que este método espera una entrada de
  tipo `Text` cuando se llama. Se almacenará en la variable `name`. El método
  devuelve un valor `Text` al llamador de manera `async`.

El cuerpo del método devuelve `Text` concatenando `Hello ,`, el valor de entrada
`name` y un signo de exclamación.

### Llamando al canister de backend

Para interactuar con el método greet del canister, deberás implementar el
canister y luego hacer una llamada a él.

Si estás utilizando [ICP Ninja](https://icp.ninja/), puedes hacer clic en el
botón de implementación y Ninja te devolverá una URL que te permite llamar al
backend a través de una interfaz API genérica.

Si estás utilizando el IC SDK, puedes ejecutar los comandos:

```
dfx deploy --playground
dfx canister call hello_backend --playground greet ICP
```

Las partes de este comando son:

- `dfx canister call`: El comando `dfx` utilizado para llamar a los canisters.

- `hello_backend`: El nombre del canister.

- `--playground`: La red en la que el canister está desplegado y en ejecución.

- `greet ICP`: El nombre del método que deseas llamar seguido de la entrada que
  deseas pasarle.

El canister devolverá la siguiente salida:

```
("Hello, ICP!")
```

El comando `dfx canister call` envió una llamada al canister `hello_backend` que
está desplegado en mainnet de forma gratuita utilizando el argumento
`--playground`. La llamada se envió al método `greet`, al cual se le pasó la
entrada `"ICP"`. El canister de backend procesó la llamada y devolvió la
respuesta definida en el método.

Dado que el método está definido como un método de consulta (`query`), el
canister simplemente devuelve datos al llamador; no altera el estado del
canister.

En contraste, `setGreeting` es una llamada de actualización que **sí** altera el
estado del canister. Llamar a este método cambiará los datos almacenados en la
variable `greeting`, lo que resultará en que la función `greet` devuelva una
respuesta diferente cuando se llame.

Realiza una llamada a la función `setGreeting` con la entrada `"Hi, "`:

```
dfx canister call hello_world_backend --playground setGreeting "Hi, "
```

Luego, llama a la función `greet` de nuevo:

```
dfx canister call hello_world_backend --playground greet ICP
```

Observa el nuevo valor de la variable `greeting`:

```
("Hi, ICP!")
```

## Frontend

El frontend de una aplicación se utiliza para facilitar la interacción del
usuario con los métodos definidos en el backend. Está compuesto por activos,
como HTML, CSS y JavaScript.

En ICP, el frontend de una aplicación se crea siguiendo estos pasos:

1. Un desarrollador crea los activos del frontend.

2. El archivo `dfx.json` del proyecto define el canister de frontend y lo
   especifica como `"type": "asset"`.

3. Cuando se despliega el proyecto, `dfx` despliega una implementación de la
   [interfaz del canister de activos](https://github.com/dfinity/sdk/blob/master/docs/design/asset-canister-interface.md)
   en el canister. Luego, agrega un cliente de API llamado
   [ICP JavaScript agent](/docs/building-apps/interact-with-canisters/agents/overview)
   a los activos del frontend y carga todos los activos en el canister. El ICP
   JavaScript agent facilita la comunicación entre el frontend y el backend. En
   general, los agentes de ICP son bibliotecas para interactuar con las
   interfaces públicas de los canisters.

## Comunicación entre el backend y el frontend

El canister de frontend es básicamente un servidor web que aloja un sitio web.
Cuando un usuario carga la aplicación, el navegador web obtiene la interfaz de
usuario del canister de frontend. Una vez que el frontend se carga en el
navegador, el usuario puede interactuar con él, lo que desencadena el envío de
mensajes al backend.

Por ejemplo, el archivo `src/hello_frontend/index.html` define una página HTML
simple que incrusta el código JavaScript utilizado para comunicarse con el
canister de backend:

```html
...
<script type="module">
  // Importa el actor del backend
  import { backend } from "declarations/backend";
  // Agrega un event listener al formulario
  document.querySelector("form").addEventListener("submit", async (e) => {
    e.preventDefault();
    // Obtén el nombre del campo de entrada
    const name = document.getElementById("name").value.toString();
    // Llama al método "greet" en el actor del backend con el nombre
    const greeting = await backend.greet(name);
    // Muestra el saludo devuelto por el actor del backend
    document.getElementById("greeting").innerText = greeting;
  });
</script>
...
```

En este script, primero se importan las declaraciones del backend
`hello_backend`. Los archivos de declaración definen los métodos públicos de un
canister y sus tipos de entrada y salida. Para esta aplicación, el archivo de
declaraciones incluirá los métodos `setGreeting` y `greet` del backend y sus
tipos de entrada y salida de `Text`. Los archivos de declaración son generados
por `dfx` durante el proceso de compilación.

Cuando el agente realiza una llamada al canister de backend, utiliza estos
archivos de declaración para determinar a qué métodos públicos puede enviar
solicitudes. Luego, creará y enviará la solicitud que contiene el tipo de
solicitud, el ID del canister, el nombre del método y cualquier entrada o
argumento que se deba pasar al método.

En este ejemplo, la interfaz de usuario incluye un cuadro de texto de entrada y
un botón para enviar la entrada. Cuando se presiona el botón, el agente de
JavaScript de ICP envía una solicitud de `query` al método `greet` del canister
`hello_backend` que incluye la entrada de texto del usuario.

El backend procesa la solicitud y luego responde al agente con un mensaje
saliente que incluye el resultado del método, en este caso,
`"¡Hola, <nombre>!"`.
