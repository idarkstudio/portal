# Tipos avanzados de llamadas

<MarkdownChipRow labels={["Principiante", "Tutorial"]} />

Además de las consultas (`queries`) y actualizaciones (`updates`), existen tipos
avanzados de llamadas que se pueden realizar a los canisters.

## Consultas certificadas

Las consultas certificadas garantizan la integridad de los datos recuperados.
Utilizan  
[variables certificadas](/docs/references/samples/motoko/cert-var/) para probar
la autenticidad de los datos que acompañan la respuesta de la consulta.  
Las variables certificadas pueden establecerse mediante una llamada de
actualización y luego ser leídas a través de una consulta.

## Consultas replicadas

Las consultas replicadas, también conocidas como el modelo de ejecución
"query-as-update",  
son llamadas de consulta ejecutadas como actualizaciones. Aunque la consulta
sigue descartando cambios de estado,  
su ejecución ocurre en todos los nodos del `subnet`, y los resultados pasan por
consenso.

## Llamadas entre canisters

Las llamadas entre canisters se utilizan para realizar llamadas entre diferentes
canisters.  
Una llamada de este tipo involucra dos mensajes: una solicitud del llamador
(`caller`) al receptor (`callee`),  
junto con una respuesta que el receptor devuelve al llamador.

Un ejemplo de llamadas entre canisters es el  
[ejemplo de llamadas paralelas en Motoko](https://github.com/dfinity/examples/tree/master/motoko/parallel_calls).

## Llamadas autorizadas

Una llamada autorizada en ICP se refiere a una llamada a un canister que solo
puede ser realizada por un `principal`  
(un usuario u otro canister) que tenga los permisos necesarios para
ejecutarla.  
Por ejemplo, solo un controlador de un canister puede llamar a la función
`install_code` del canister.

Las llamadas autorizadas que devuelven un valor `()` indican que la función fue
exitosa,  
pero es posible que no acepten un argumento ni devuelvan un valor
significativo.  
Si una llamada autorizada no es exitosa, devolverá un error.

## Realización de llamadas con IDLs

A nivel de protocolo, las llamadas en ICP utilizan `blobs` para describir los
argumentos y resultados  
que se pasan y devuelven desde los canisters. Sin embargo, generalmente es más
fácil utilizar un  
[Lenguaje de Descripción de Interfaces](https://en.wikipedia.org/wiki/Interface_description_language)
(IDL)  
para definir las interfaces de un canister, permitiendo que los usuarios finales
u otros canisters puedan interactuar con él.

Si bien se puede utilizar cualquier IDL para este propósito, la mayoría de los
canisters en ICP usan  
[Candid](/docs/building-apps/interact-with-canisters/candid/candid-concepts),  
un IDL especializado desarrollado específicamente para ICP.
