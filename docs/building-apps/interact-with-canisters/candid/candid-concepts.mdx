# ¿Qué es Candid?

<MarkdownChipRow labels={["Principiante", "Concepto"]} />

Candid es un **lenguaje de descripción de interfaces**. Su propósito principal
es describir la interfaz pública de un **servicio**, generalmente en forma de un
programa desplegado como un <GlossaryTooltip>canister</GlossaryTooltip> que se
ejecuta en el Internet Computer. Uno de los principales beneficios de Candid es
que es independiente del lenguaje de programación y permite la interoperabilidad
entre canisters escritos en diferentes lenguajes de programación, como Motoko,
Rust y JavaScript.

Un archivo de descripción de servicio en Candid (un archivo `.DID`) puede ser
escrito a mano o generado a partir de una implementación de servicio. Candid es
un sistema fuertemente tipado con un conjunto de tipos que cubren de manera
canónica la mayoría de los casos de uso. Todos los tipos están descritos en
detalle en la [documentación de referencia](/docs/references/candid-ref).

La descripción de servicio más sencilla especifica un servicio con un método
`ping`:

```candid
service : {
  ping : () -> ();
}
```

Cada método de un canister tiene una secuencia de tipos de argumentos y
resultados. Un método también puede incluir anotaciones, como la notación
`query` mostrada en este ejemplo:

```candid
service counter: {
  "inc": () -> ();
  "read": () -> (nat) query;
  "write": (nat) -> ();
}
```

En este ejemplo, el servicio descrito como `counter` consta de los siguientes
métodos públicos:

- El método `inc` cambia el valor de un contador. No toma entradas y no devuelve
  tipos de salida.

- El método `read` lee el valor actual de un contador. No toma entradas y
  devuelve un tipo de salida `Nat`.

- El método `write` se puede usar para establecer el valor del contador. Toma
  una entrada de tipo `Nat` y no devuelve tipo de salida.

Dada esta simple descripción de interfaz, es posible interactuar con este
servicio `counter` directamente desde la línea de comandos, a través de un
frontend basado en la web o programáticamente desde un lenguaje de script.

Además de la interoperabilidad, Candid admite la evolución de las interfaces de
servicio al especificar de manera precisa los cambios que se pueden hacer sin
romper los clientes existentes. Por ejemplo, puedes agregar de forma segura
nuevos parámetros opcionales a un servicio sin perder compatibilidad con los
clientes existentes.

### ¿Por qué usar Candid?

Las características que hacen que Candid sea particularmente adecuado para
desarrollar dapps para el Internet Computer incluyen las siguientes:

- Muchos lenguajes como JSON, XML y Protobuf solo describen cómo mapear valores
  individuales a bytes o caracteres. Estos lenguajes de descripción de datos no
  describen los servicios como un todo. Estos lenguajes se enfocan en los tipos
  de datos que deseas transferir en lugar de los métodos que hacen uso de esos
  tipos de datos.

- Las implementaciones de Candid mapean el valor de Candid directamente a los
  tipos y valores del lenguaje anfitrión. Con Candid, los desarrolladores no
  construyen ni destruyen un valor abstracto `Candid`.

- Candid define reglas sobre cómo los servicios y sus interfaces pueden ser
  actualizados de manera sólida y compositiva.

- Candid es inherentemente un lenguaje de orden superior. Con Candid, puedes
  pasar más que solo datos planos, incluyendo referencias a servicios y métodos.
  El soporte de Candid para actualizaciones seguras toma en cuenta este uso de
  orden superior.

- Candid tiene soporte integrado para características específicas del Internet
  Computer, como la anotación `query`.
