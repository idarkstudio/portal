# Llamadas de consulta (Query calls)

<MarkdownChipRow labels={["Principiante", "Tutorial"]} />

ICP soporta dos tipos de llamadas: escritura (update) y consulta (query). Las
llamadas de consulta, también conocidas como consultas no replicadas, se
ejecutan en un solo nodo y devuelven una respuesta sincrónica.

Una llamada de consulta descarta los cambios de estado y típicamente se ejecuta
en un solo nodo. Una llamada de escritura se ejecuta en todos los nodos y
persiste los cambios de estado del canister. Como se ejecutan en un solo nodo,
no pasan por consenso y pueden ser mucho más rápidas que las llamadas de
[escritura](/docs/building-apps/interact-with-canisters/update-calls).

Es posible ejecutar una llamada de consulta como escritura. En ese caso, la
consulta sigue descartando los cambios de estado, pero la ejecución ocurre en
todos los nodos, y el resultado de la ejecución pasa por consenso. Este modo de
ejecución "consulta-como-escritura" también se conoce como consulta replicada.

Las llamadas de consulta son:

- Rápidas (200-400ms).
- No pueden modificar el estado.
- No pasan por consenso.
- Devuelven una respuesta sincrónica.
- Ejecutadas en un solo nodo.
- Actualmente gratuitas.

## Haciendo llamadas de consulta con `dfx`

Para hacer una llamada de consulta a un canister, usa el comando
[`dfx canister call`](/docs/building-apps/developer-tools/dfx/dfx-canister#dfx-canister-call)
con el flag `--query`:

- `dfx canister call --query <canister-name> <method_name>`: Haz una llamada de
  consulta a un canister desplegado localmente. La réplica local debe estar en
  ejecución para crear un canister localmente. Iníciala con
  `dfx start --background`.

- `dfx canister call --query <canister-name> <method_name> --network=playground`:
  Haz una llamada de consulta a un canister desplegado en el
  [playground](/docs/building-apps/developing-canisters/deploy#testnets). Las
  llamadas de consulta son gratuitas, pero los canisters son temporales y se
  eliminarán después de 20 minutos.

- `dfx canister call --query <canister-name> <method_name> --network=ic`: Haz
  una llamada de consulta a un canister desplegado en la mainnet. Las llamadas
  de consulta son gratuitas.

La desventaja de las llamadas de consulta es que la respuesta no es confiable ya
que proviene de un solo nodo. Se debe usar una llamada de escritura o una
[consulta certificada](#certified-queries) para llamadas críticas de seguridad.

## Estadísticas de consultas

La función de **estadísticas de consultas** brinda a los desarrolladores
información sobre el uso de las llamadas de consulta de cada canister. Una
aproximación de algunas estadísticas relacionadas con las estadísticas de
consultas está disponible para los desarrolladores como parte de la API de
estado del canister existente.

Las estadísticas recopiladas en el estado del canister son una aproximación.
Pueden no capturar todas las llamadas de consulta, especialmente para canisters
poco utilizados. Las estadísticas de consultas se recopilan en intervalos por el
sistema y, por lo tanto, pueden retrasarse respecto a la ejecución real de la
consulta hasta 30 minutos.

Actualmente no se recopilan estadísticas de consultas compuestas.

### Entradas de estado del canister

La función expone los siguientes campos al endpoint de estado del canister:

- Un contador para el número total de llamadas de consulta ejecutadas por ese
  canister.
- La suma de todas las instrucciones ejecutadas por el canister para llamadas de
  consulta.
- La suma de los tamaños de carga útil de todas las solicitudes de consulta al
  canister.
- La suma de los tamaños de carga útil de todas las respuestas de consulta del
  canister.

Cada valor representa el conteo total desde que se creó el canister. Las tasas
para estos valores se pueden calcular a partir de múltiples llamadas al estado
del canister y observando la diferencia entre los valores en diferentes
llamadas. Todos los valores son monótonamente crecientes.

### Obtener estadísticas de consultas usando `dfx`

Se puede usar `dfx` para devolver las estadísticas de consultas de un canister:

```
dfx canister status sample_canister
```

Esto devolverá un resultado como:

```
Canister status call result for sample_canister.
Status: Running
[..]
Number of queries: 0
Instructions spent in queries: 0
Total query request paylod size (bytes): 0
Total query response payload size (bytes): 0
```

Las estadísticas de consultas están disponibles en `dfx` desde la versión
`0.16.1`.

### Usar estadísticas de consultas programáticamente

También es posible recuperar las estadísticas de consultas programáticamente
desde dentro del canister a través del método de estado del canister. El
siguiente es un ejemplo de cómo hacer esto en Rust:

```rust
let canister_status = canister_status(CanisterIdRecord {
    canister_id: ic_cdk::id(),
})
.await.unwrap();
let query_stats = canister_status.0.query_stats;
```

Las estadísticas de consultas son compatibles con `ic-cdk` desde la versión
`0.12.1`.

## Consultas compuestas

Una actualización puede llamar a otras actualizaciones y consultas. Sin embargo,
una consulta no puede hacer ninguna llamada, lo que puede dificultar el
desarrollo de aplicaciones descentralizadas escalables, especialmente aquellas
que fragmentan datos en múltiples canisters.

Las consultas compuestas resuelven este problema. Puedes agregar consultas
compuestas a tu canister usando las siguientes anotaciones:

- Candid: `composite_query`
- Motoko: `composite query`
- Rust: `#[query(composite = true)]`

Los usuarios y el código JavaScript del lado del cliente pueden invocar un
endpoint de consulta compuesta de un canister usando la misma URL de consulta
para las consultas regulares existentes. A diferencia de las consultas
regulares, una consulta compuesta puede llamar a otras consultas compuestas y
regulares. Debido a limitaciones de la implementación actual, las consultas
compuestas tienen dos restricciones:

| Consulta                                       | Actualización                                                                          | Consulta compuesta                          |
| ---------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------- |
| No puede llamar a otras consultas o compuestas | Puede llamar a otras actualizaciones y consultas; No puede llamar consultas compuestas | Puede llamar a otras consultas y compuestas |
| Se puede llamar como actualización             | No se puede llamar como consulta                                                       | No se puede llamar como actualización       |
| Puede llamar canisters en otra subred          | Puede llamar canisters en otra subred                                                  | No puede llamar canisters en otra subred    |

Las consultas compuestas se habilitaron en las siguientes versiones:

| Plataforma/Lenguaje       | Versión                                                                                                                                                               |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Internet Computer mainnet | Release [7742d96ddd30aa6b607c9d2d4093a7b714f5b25b](https://nns.ic0.app/proposal/?u=qoctq-giaaa-aaaaa-aaaea-cai&proposal=123311)                                       |
| Candid                    | [2023-06-30 (Rust 0.9.0)](https://github.com/dfinity/candid/blob/master/Changelog.md#2023-06-30-rust-090)                                                             |
| Motoko                    | [0.9.4](https://github.com/dfinity/motoko/releases/tag/0.9.4), revisión: [2d9902f](https://github.com/dfinity/motoko/commit/2d9902fb75bb04e377c28913c311aa2be373e159) |
| Rust                      | [0.6.8](https://github.com/dfinity/cdk-rs/blob/219ae179b9c5ef0ebfff20b926a90f6624ebe704/src/ic-cdk/CHANGELOG.md#068---2022-11-28)                                     |
