# Agente de JavaScript para ICP

<MarkdownChipRow labels={["Intermedio", "Agentes"]} />

Un **agente** es un cliente API utilizado para interactuar con ICP. El  
[agente de JavaScript para ICP](https://www.npmjs.com/package/@dfinity/agent)  
se usa para interactuar con los endpoints públicos de la API de ICP y con los  
canisters desplegados en ICP.

El agente de JavaScript para ICP proporciona los métodos `call`, `query` y  
`readState`, junto con otras utilidades, para un actor.

Las llamadas realizadas a través del agente deben estructurarse mediante un
actor  
y configurarse con la interfaz del canister, la cual puede generarse desde una  
[interfaz Candid](/docs/building-apps/interact-with-canisters/candid/candid-concepts).  
Las llamadas en bruto están soportadas, pero no se recomiendan como buena
práctica.

## Autenticación

El agente de JavaScript para ICP admite autenticación a través de
`auth-client`,  
que utiliza el  
[servicio Internet Identity](/docs/building-apps/authentication/overview).

Primero, instala el paquete `auth-client`:

```bash
npm i --save @dfinity/auth-client
```

Crea un cliente de autenticación que abrirá una ventana en `identity.ic0.app`,  
guardará tu delegación en `indexedDb` y te proporcionará una identidad:

```javascript title="project_name/src/project_name_frontend/src/index.js"
const authClient = await AuthClient.create();
```

Luego, el `authClient` puede iniciar sesión con:

```javascript title="project_name/src/project_name_frontend/src/index.js"
authClient.login({
  // 7 días en nanosegundos
  maxTimeToLive: BigInt(7 * 24 * 60 * 60 * 1000 * 1000 * 1000),
  onSuccess: async () => {
    handleAuthenticated(authClient);
  },
});
```

Usa esa identidad para realizar llamadas autenticadas con el actor de
`@dfinity/agent`:

```js title="project_name/src/project_name_frontend/src/index.js"
const identity = await authClient.getIdentity();
const actor = Actor.createActor(idlFactory, {
  agent: new HttpAgent({
    identity,
  }),
  canisterId,
});
```

### Almacenamiento y gestión de claves

Por defecto, el agente de JavaScript para ICP utiliza una interfaz de
almacenamiento  
en `IndexedDb` y claves ECDSA.

Puedes usar cualquier estructura de almacenamiento que implemente la interfaz  
`AuthClientStorage`:

```js
export type StoredKey = string | CryptoKeyPair;
export interface AuthClientStorage {
  get(key: string): Promise<StoredKey | null>;

  set(key: string, value: StoredKey): Promise<void>;

  remove(key: string): Promise<void>;
}
```

:::caution

Si decides utilizar una implementación de almacenamiento personalizada que
solo  
admite tipos de datos de tipo `string`, se recomienda utilizar la opción
`keyType`  
para emplear una clave `Ed25519` en lugar de la clave ECDSA predeterminada:

```js
const authClient = await AuthClient.create({
  storage: new LocalStorage(),
  keyType: "Ed25519",
});
```

:::

### Gestión de sesión

`AuthClient` admite dos opciones para la gestión segura de sesiones:

1. La opción `maxTimeToLive` incorporada en la delegación de Internet Identity  
   determina en nanosegundos cuánto tiempo será válida la `DelegationIdentity`  
   devuelta.

2. **Idle Manager**, que monitorea la actividad del teclado, mouse y pantalla
   táctil.  
   Si el usuario no interactúa con el navegador durante un tiempo determinado,  
   se cerrará la sesión automáticamente.

   - Por defecto, este período es de **10 minutos**. Luego de este tiempo,  
     la `DelegationIdentity` se eliminará de `localStorage` y se llamará  
     `window.location.reload()`.

   - Alternativamente, puedes pasar una opción `onIdle` para reemplazar el  
     comportamiento predeterminado de `window.location.reload()` o registrar  
     callbacks con `idleManager.registerCallback()`, que también reemplazará  
     el callback predeterminado.

Consulta el conjunto completo de  
[opciones para IdleManager](https://agent-js.icp.xyz/auth-client/index.html).

## Inicialización de un actor

Los agentes se utilizan comúnmente para crear un actor mediante el constructor  
`Actor.createActor`:

```
Actor.createActor(interfaceFactory: InterfaceFactory, configuration: ActorConfig): ActorSubclass<T>
```

La función `interfaceFactory` devuelve una interfaz en tiempo de ejecución que  
el actor utiliza para estructurar las llamadas realizadas a un canister.

Esta función se genera ejecutando el comando `dfx generate` en tu proyecto  
o usando la herramienta `didc` para generar interfaces. También se puede
escribir  
manualmente, aunque no se recomienda.

Los actores en el contexto del agente de JavaScript para ICP se utilizan para:

- Realizar consultas en busca de actualizaciones.
- Construir el cuerpo codificado en Candid de la solicitud del agente.
- Analizar la respuesta.
- Proporcionar seguridad de tipos para la interfaz del canister.

Realizar una llamada directamente con `HttpAgent`, sin usar un actor, es un
caso  
avanzado y **no es necesario para la mayoría de las aplicaciones**.

Para configurar un actor, puedes importar una utilidad `createActor` desde las  
declaraciones Candid de tu canister y un `canisterId alias`, que por defecto  
apunta a `process.env<canister-id>_CANISTER_ID`.

Puedes pasar la variable de entorno del ID del canister a tu aplicación de
varias maneras, como:

- Editarla al inicio de los scripts en `package.json`  
  (`NFT_CANISTER_ID=... node....`).
- Instalar [dotenv](https://www.npmjs.com/package/dotenv) y configurarlo para
  leer  
  desde un archivo oculto `.env`.

El siguiente ejemplo usa un entorno de desarrollo local, donde se puede leer  
el ID del canister desde el archivo `canister_ids.json` ubicado en  
`.dfx/local/canister_ids.json`:

```js title="src/node/index.js"
import fetch from "isomorphic-fetch";
import { HttpAgent } from "@dfinity/agent";
import { createRequire } from "node:module";
import {
  canisterId,
  createActor,
} from "../declarations/agent_js_example/index.js";
import { identity } from "./identity.js";

// Se requiere `createRequire` para importar archivos JSON
const require = createRequire(import.meta.url);
const localCanisterIds = require("../../.dfx/local/canister_ids.json");

// Usa `process.env` si está disponible, o usa la configuración local
const effectiveCanisterId =
  canisterId?.toString() ?? localCanisterIds.agent_js_example.local;

const agent = new HttpAgent({
  identity: await identity,
  host: "http://127.0.0.1:4943",
  fetch,
});

const actor = createActor(effectiveCanisterId, {
  agent,
});
```

### Headers HTTP

Un actor puede inicializarse para incluir las headers HTTP del nodo límite
usando el constructor `Actor.createActor`:

```js
Actor.createActorWithHttpDetails(interfaceFactory: InterfaceFactory, configuration: ActorConfig): ActorSubclass<ActorMethodMappedWithHttpDetails<T>>
```

### Inspeccionar el agente de un actor

Para obtener el agente de un actor, usa el método `Actor.agentOf`:

```js
const defaultAgent = Actor.agentOf(defaultActor);
```

Este método puede usarse para reemplazar o invalidar una identidad usada por el
agente de un actor. Por ejemplo, el siguiente método puede usarse para
reemplazar la identidad actual del agente de un actor con una nueva identidad
autenticada desde Internet Identity:

```js
defaultAgent.replaceIdentity(await authClient.getIdentity());
```

## Realizar llamadas

El agente JavaScript de ICP soporta los siguientes métodos para hacer llamadas a
ICP:

- `call`: Usado para hacer
  [llamadas de actualización](/docs/building-apps/interact-with-canisters/advanced-calls).
- `query`: Usado para hacer
  [llamadas de consulta](/docs/building-apps/interact-with-canisters/advanced-calls).
- `readState`: Usado para leer información de estado de la réplica ICP.

Se pueden hacer llamadas directas usando el agente, pero se recomienda usar las
llamadas generadas por el agente.

### Llamadas de actualización

Las llamadas de actualización en ICP modifican el estado del canister. Para
hacer una llamada de actualización con el agente JavaScript de ICP, usa el
método `call`:

```js
call(canisterId: string | Principal, fields: CallOptions): Promise<SubmitResponse>
```

Este método está definido en
[packages/agent/src/agent/api.ts:178](https://github.com/dfinity/agent-js/blob/21e8d2b/packages/agent/src/agent/api.ts#L178).

Parámetros:

- `canisterId`: ID principal del canister como `string`.
- `fields`: Opciones de la llamada, definidas en
  [CallOptions](https://agent-js.icp.xyz/agent/interfaces/CallOptions.html).

Devuelve
`Promise<[SubmitResponse](https://agent-js.icp.xyz/agent/interfaces/SubmitResponse.html)>`.

### Llamadas de consulta

Las llamadas de consulta en ICP no modifican el estado del canister. Para hacer
una llamada de consulta, usa el método `query`:

```js
query(canisterId: string | Principal, options: QueryFields, identity?: Identity | Promise<Identity>): Promise<ApiQueryResponse>
```

Definido en
[packages/agent/src/agent/api.ts:200](https://github.com/dfinity/agent-js/blob/21e8d2b/packages/agent/src/agent/api.ts#L200).

Parámetros:

- `canisterId`: ID principal del canister como `string`.
- `options`: Opciones definidas en
  [QueryFields](https://agent-js.icp.xyz/agent/interfaces/QueryFields.html).
- `identity`: Opcional, identidad del remitente.

Devuelve `Promise<ApiQueryResponse>`.

### Leer información de estado

Para leer información de estado de la réplica ICP, usa `readState`:

```js
readState(effectiveCanisterId: string | Principal, options: ReadStateOptions, identity?: Identity, request?: any): Promise<ReadStateResponse>
```

Definido en
[packages/agent/src/agent/api.ts:170](https://github.com/dfinity/agent-js/blob/21e8d2b/packages/agent/src/agent/api.ts#L170).

Parámetros:

- `effectiveCanisterId`: ID principal relacionado.
- `options`: Opciones de
  [ReadStateOptions](https://agent-js.icp.xyz/agent/interfaces/ReadStateOptions.html).
- `identity`: Opcional, identidad del remitente.
- `request`: Opcional, solicitud pre-creada.

Devuelve `Promise<ReadStateResponse>`.

## Navegador

Para apps en navegador, se puede usar la API `fetch` como se describe a
continuación. La mayoría de apps pueden determinar si necesitan conectarse a
`https://icp0.io` o a una réplica local según su URL.

### Usando `fetch`

El agent de JavaScript de ICP utiliza la API `fetch` del navegador web para
realizar llamadas a ICP. Cuando el agente no se usa en el navegador, se puede
pasar una implementación de `fetch` al constructor del agente. Esto puede ser
útil si deseas incluir datos de implementación personalizados de `fetch`, como
agregar un encabezado de autenticación a tu solicitud.

Se recomienda usar el paquete `isomorphic-fetch` para proporcionar una API
consistente de `fetch` en Node.js y en el navegador. Deberás proporcionar una
opción de host al constructor del agente, ya que el agente no podrá determinar
el host desde el contexto global.

A continuación se muestra un ejemplo:

```js
import fetch from "isomorphic-fetch";
import { HttpAgent } from "@dfinity/agent";

const host =
  process.env.DFX_NETWORK === "local"
    ? "http://127.0.0.1:4943"
    : "https://icp-api.io";

const agent = new HttpAgent({ fetch, host });
```

También puedes pasar `fetchOptions` al constructor del agente, que luego se pasa
a la implementación de `fetch`. Esto es útil si deseas pasar opciones
adicionales a la implementación de `fetch`. A continuación se muestra un ejemplo
que especifica un encabezado personalizado:

```js
import fetch from "isomorphic-fetch";
import { HttpAgent } from "@dfinity/agent";

const host =
  process.env.DFX_NETWORK === "local"
    ? "http://127.0.0.1:4943"
    : "https://ic0.app";

/**
 * @type {RequestInit}
 */
const fetchOptions = {
  headers: {
    "X-Custom-Header": "value",
  },
};

const agent = new HttpAgent({ fetch, host, fetchOptions });
```

## Rendimiento

Al desarrollar una aplicación que se ejecuta en el navegador, es importante
tener en cuenta el rendimiento de la aplicación. Las actualizaciones en ICP
pueden parecer lentas para tus usuarios, alrededor de 2-4 segundos. Al construir
tu aplicación, ten en cuenta esa latencia y considera seguir estas mejores
prácticas:

- Evita bloquear las interacciones de la interfaz de usuario mientras esperas el
  resultado de la actualización. En su lugar, permite a los usuarios continuar
  realizando otras actualizaciones e interacciones, e informa a tus usuarios de
  éxito de forma asíncrona.

- Intenta evitar realizar llamadas entre canisters. Si el backend necesita
  comunicarse con otros canisters, la latencia puede acumularse rápidamente.

- Utiliza `Promise.all` para realizar múltiples llamadas en un lote, en lugar de
  hacerlas una por una.

- Si necesitas obtener activos o datos, puedes realizar llamadas directas de
  `fetch` al punto final `raw.icp0.io` de los canisters.

## Bundlers

Se recomienda utilizar un empaquetador para ensamblar tu código por conveniencia
y para facilitar la solución de problemas. A continuación se muestra un ejemplo
que proporciona una configuración estándar de Webpack, pero también puedes
utilizar otros frameworks como Rollup, Vite, Parcel u otros.

Para este patrón, se recomienda ejecutar un script para generar los archivos de
variables de entorno `.env.development` y `.env.production` para los IDs de
canister de tu proyecto. Este es un enfoque bastante estándar para los
empaquetadores y se puede admitir fácilmente utilizando
[dotenv](https://www.npmjs.com/package/dotenv). A continuación se muestra un
ejemplo de este script:

```js
// setupEnv.js
const fs = require("fs");
const path = require("path");

function initCanisterEnv() {
  let localCanisters, prodCanisters;
  try {
    localCanisters = require(path.resolve(
      ".dfx",
      "local",
      "canister_ids.json"
    ));
  } catch (error) {
    console.log("No local canister_ids.json found");
  }
  try {
    prodCanisters = require(path.resolve("canister_ids.json"));
  } catch (error) {
    console.log("No production canister_ids.json found");
  }

  const network =
    process.env.DFX_NETWORK ||
    (process.env.NODE_ENV === "production" ? "ic" : "local");

  const canisterConfig = network === "local" ? localCanisters : prodCanisters;

  const localMap = localCanisters
    ? Object.entries(localCanisters).reduce((prev, current) => {
        const [canisterName, canisterDetails] = current;
        prev[canisterName.toUpperCase() + "_CANISTER_ID"] =
          canisterDetails[network];
        return prev;
      }, {})
    : undefined;
  const prodMap = prodCanisters
    ? Object.entries(prodCanisters).reduce((prev, current) => {
        const [canisterName, canisterDetails] = current;
        prev[canisterName.toUpperCase() + "_CANISTER_ID"] =
          canisterDetails[network];
        return prev;
      }, {})
    : undefined;
  return [localMap, prodMap];
}
const [localCanisters, prodCanisters] = initCanisterEnv();

if (localCanisters) {
  const localTemplate = Object.entries(localCanisters).reduce((start, next) => {
    const [key, val] = next;
    if (!start) return `${key}=${val}`;
    return `${start ?? ""}
          ${key}=${val}`;
  }, ``);
  fs.writeFileSync(".env.development", localTemplate);
}
if (prodCanisters) {
  const prodTemplate = Object.entries(prodCanisters).reduce((start, next) => {
    const [key, val] = next;
    if (!start) return `${key}=${val}`;
    return `${start ?? ""}
        ${key}=${val}`;
  }, ``);
  fs.writeFileSync(".env", localTemplate);
}
```

Luego, puedes agregar comandos `"prestart"` y `"prebuild"` de
`dfx generate; node setupEnv.js`. Sigue la documentación de tu empaquetador
preferido sobre cómo trabajar con variables de entorno.

## Ejemplo

A continuación se muestra un ejemplo que crea un agente, obtiene la clave raíz
de la réplica y luego crea automáticamente un actor a través de la interfaz
Candid del canister.

:::caution

Este ejemplo usa `fetchRootKey`. No se recomienda que las dapps desplegadas en
la red principal llamen a esta función desde el agente de JavaScript de ICP, ya
que usar `fetchRootKey` en la red principal presenta graves preocupaciones de
seguridad para la dapp que realiza la llamada. Se recomienda ponerlo detrás de
una condición para que solo se ejecute localmente.

Esta llamada a la API obtendrá una clave raíz para la verificación de las
llamadas de actualización desde un solo réplica, por lo que es posible que esa
réplica responda con una clave maliciosa. Una clave raíz verificada de la red
principal ya está incrustada en el agente de JavaScript de ICP, por lo que solo
necesita ser llamada en tu réplica local, que tendrá una clave diferente de la
red principal que el agente de JavaScript de ICP no conoce de antemano.

:::

```js
import { Actor, HttpAgent } from "@dfinity/agent";

// Importa y vuelve a exportar la interfaz candid
import { idlFactory } from "./backend_canister.did.js";
export { idlFactory } from "./backend_canister.did.js";

/* CANISTER_ID se reemplaza por webpack según el entorno del nodo.
 * Nota: La variable de entorno del canister se estandarizará como
 * process.env.CANISTER_ID_<CANISTER_NAME_UPPERCASE>
 * comenzando en dfx 0.15.0
 */
export const canisterId =
  process.env.CANISTER_ID_BACKEND_CANISTER ||
  process.env.BACKEND_CANISTER_CANISTER_ID;

export const createActor = (canisterId, options = {}) => {
  const agent = options.agent || new HttpAgent({ ...options.agentOptions });

  if (options.agent && options.agentOptions) {
    console.warn(
      "Detectado tanto 'agent' como 'agentOptions' pasados a createActor. Ignorando 'agentOptions' y procediendo con el agente proporcionado."
    );
  } // Obtiene la clave raíz para la validación del certificado durante el desarrollo

  if (process.env.DFX_NETWORK !== "ic") {
    agent.fetchRootKey().catch((err) => {
      console.warn(
        "No se pudo obtener la clave raíz. Verifica que tu réplica local esté ejecutándose"
      );
      console.error(err);
    });
  } // Crea un actor usando la interfaz candid y el HttpAgent

  return Actor.createActor(idlFactory, {
    agent,
    canisterId,
    ...options.actorOptions,
  });
};

export const backend_canister = createActor(canisterId);
```
