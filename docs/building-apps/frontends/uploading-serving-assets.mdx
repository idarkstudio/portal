# Subir y servir web assets

<MarkdownChipRow labels={["Principiante", "Asset canisters"]} />

La biblioteca `@dfinity/assets` está disponible para cargar archivos en el asset
canister de tu proyecto. Necesitarás obtener el ID del canister, pasar tu agente
y luego subir los archivos. A continuación, se muestra un fragmento de código
que ilustra este flujo de trabajo:

```js
import { Blob } from "buffer";
global.Blob = Blob;
import { AssetManager } from "@dfinity/assets";
// ...

const assetCanisterId = localCanisterIds.asset.local;
const assetManager = new AssetManager({
  canisterId: assetCanisterId,
  agent, // Reutiliza el agente
  concurrency: 32, // Opcional (por defecto: 32), máximo de solicitudes concurrentes.
  maxSingleFileSize: 450000, // Opcional en bytes (por defecto: 450000), los archivos más grandes se cargarán en fragmentos.
  maxChunkSize: 1900000, // Opcional en bytes (por defecto: 1900000), tamaño de los fragmentos al subir un archivo en partes.
});

async function main() {
  // ...
  const uploadedFilePath = `token/${idx}${path.extname(node_example.asset)}`;
  const uploadedThumbnailPath = `thumbnail/${idx}.jpeg`;

  await assetManager.store(file, { fileName: uploadedFilePath });
  await assetManager.store(thumbnail, { fileName: uploadedThumbnailPath });
}
```

:::caution

Este ejemplo es un **fragmento de código** que forma parte de un archivo más
grande. Este código puede generar un error si se ejecuta por sí solo.

:::

## El canister `ic-asset`

El canister `ic-asset` está escrito en Rust y utiliza el  
[agente Rust de ICP](https://docs.rs/ic-agent/latest/ic_agent/) para
proporcionar una API cliente que permite listar assets, devolver propiedades de
los assets y cargarlos en el canister.

Los endpoints de la API para este canister incluyen:

- `api_version`: Devuelve la versión actual de la API.
- `commit_batch`: Confirma operaciones por lotes.
- `compute_evidence`: Calcula la prueba de hash sobre las operaciones por lotes
  necesarias para actualizar los assets.
- `create_batch`: Crea una operación por lotes.
- `create_chunk`: Crea un fragmento de datos dentro de un lote.
- `get_asset_properties`: Devuelve las propiedades de un asset.
- `list`: Lista los assets actuales.
- `propose_commit_batch`: Propone un lote de operaciones para su confirmación.

Por ejemplo, el endpoint `list` usa el siguiente código para listar los assets
mediante el agente:

```rust
use crate::canister_api::methods::method_names::LIST;
use crate::canister_api::types::{asset::AssetDetails, list::ListAssetsRequest};
use ic_agent::AgentError;
use ic_utils::call::SyncCall;
use ic_utils::Canister;
use std::collections::HashMap;

pub(crate) async fn list_assets(
    canister: &Canister<'_>,
) -> Result<HashMap<String, AssetDetails>, AgentError> {
    let (entries,): (Vec<AssetDetails>,) = canister
        .query(LIST)
        .with_arg(ListAssetsRequest {})
        .build()
        .call()
        .await?;

    let assets: HashMap<_, _> = entries.into_iter().map(|d| (d.key.clone(), d)).collect();

    Ok(assets)
}
```

Puedes encontrar más información sobre el canister `ic-asset` en el  
[código fuente](https://github.com/dfinity/sdk/tree/master/src/canisters/frontend/ic-asset).
