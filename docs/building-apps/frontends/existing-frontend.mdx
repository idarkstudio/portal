# Usar una aplicación frontend existente

<MarkdownChipRow labels={["Intermedio", "Tutorial"]} />

Si bien existen numerosos proyectos de inicio y ejemplos para quienes prefieren
comenzar desde cero, también es una opción viable desplegar una aplicación
frontend existente como un canister en ICP.

Los canisters de frontend se despliegan como aplicaciones solo del lado del
cliente, por lo que métodos del servidor como `getServerSideProps` no son
compatibles.

## Ejemplo: Frontend con Next.js

[Next.js](https://nextjs.org/) es un framework de desarrollo web de código
abierto que permite crear aplicaciones web en React con renderizado del lado del
servidor y generación de sitios estáticos. Este ejemplo demostrará cómo
desplegar una aplicación Next.js existente como un canister en ICP.

[Ver el repositorio de GitHub para este ejemplo](https://github.com/jennifertrin/nextjsicp).

### Paso 1: Construir tu aplicación Next.js

Para comenzar, debes generar archivos estáticos y compilar tu aplicación
Next.js. Para generar los archivos estáticos, agrega esta línea a tu archivo
`next.config.js`:

```js
const nextConfig = {
  output: "export",
};
```

No elimines tu configuración existente, ya que podrías sobrescribir otros
ajustes importantes.

Luego, compila tu aplicación Next.js ejecutando el comando de compilación
adecuado. Revisa la sección `scripts` de tu `package.json` para determinar el
comando correcto. Por ejemplo, si usas `npx`:

```bash
npx run build
```

Al compilar tu aplicación, se generará una carpeta `out`, que contendrá los
activos estáticos del frontend.

### Paso 2: Crear un archivo `dfx.json`

En el directorio raíz de tu repositorio, agrega un archivo `dfx.json` con el
siguiente contenido:

```json
{
  "canisters": {
    "frontend": {
      "entrypoint": "out/index.html",
      "source": ["out"],
      "type": "assets"
    }
  },
  "output_env_file": ".env"
}
```

El archivo `dfx.json` se usa para definir y configurar tu proyecto para su
compilación y despliegue en ICP. En este ejemplo, el canister se llama
`"frontend"`, pero puedes ajustar el nombre según el de tu canister.

Asegúrate de que las siguientes configuraciones apunten a los archivos
correctos:

- `"entrypoint": "out/index.html"`: Define el punto de entrada de la aplicación.
- `"source": ["out"]`: Especifica el directorio que contiene los activos web de
  la aplicación.

### Paso 3: Generar definiciones de Candid

Ejecuta el siguiente comando para generar las definiciones de tipo  
[Candid](/docs/building-apps/interact-with-canisters/candid/candid-concepts)
correctas:

```bash
dfx generate
```

### Paso 4: Desplegar el proyecto

Ahora puedes desplegar la aplicación Next.js localmente para hacer pruebas:

```bash
dfx deploy
```

O puedes desplegarla directamente en la mainnet. Ten en cuenta que desplegar en
la mainnet tendrá un costo en  
[cycles](/docs/building-apps/getting-started/tokens-and-cycles).

```bash
dfx deploy --network ic
```

Después de ejecutar cualquiera de estos comandos, se generará un enlace donde
ahora se alojará tu aplicación Next.js.

- La URL local tendrá el formato:  
  `http://127.0.0.1:4943/?canisterId=<canister-id>`
- La URL en la mainnet tendrá el formato:  
  `https://<canister-id>.icp0.io/`
