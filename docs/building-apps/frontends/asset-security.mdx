### Seguridad de assets

<MarkdownChipRow labels={["Intermedio", "Concepto"]} />

Para configurar cómo responde un <GlossaryTooltip>canister</GlossaryTooltip> de
frontend a solicitudes de assets específicos, puedes editar la Concent Security
Policy en el archivo `.ic-assets.json5` de un proyecto. Cada entrada en este
archivo permite especificar un patrón
[glob](https://code.visualstudio.com/docs/editor/glob-patterns) junto con los
encabezados que se devolverán para cualquier archivo que coincida con el patrón.
También puedes definir si se realizan redirecciones desde un endpoint no
certificado a un endpoint certificado para un patrón de nombre de archivo
determinado.

## Políticas de Seguridad de Contenido (CSP)

Por defecto, los canisters de frontend creados con `dfx new` contienen la
siguiente Política de Seguridad de Contenido (CSP) en el archivo
`.ic-assets.json5` del proyecto:

```
"Content-Security-Policy": "default-src 'self';script-src 'self';connect-src 'self' http://localhost:* https://icp0.io https://*.icp0.io https://icp-api.io;img-src 'self' data:;style-src * 'unsafe-inline';style-src-elem * 'unsafe-inline';font-src *;object-src 'none';base-uri 'self';frame-ancestors 'none';form-action 'self';upgrade-insecure-requests;",
```

Esta CSP incluye la configuración `img-src data` porque los archivos de imagen
suelen formar parte de las interfaces de frontend. También incluye la
configuración de seguridad `frame-ancestors: none`, que se usa para mitigar los
[ataques de clickjacking](https://owasp.org/www-community/attacks/Clickjacking).

## Recomendaciones de seguridad

Esta Política de Seguridad de Contenido predeterminada está diseñada para
funcionar con la mayor cantidad posible de aplicaciones en lugar de proporcionar
la máxima seguridad. Se recomienda actualizar esta política según las
necesidades específicas de tu aplicación utilizando herramientas como:

- Utilizar la herramienta [CSP Evaluator](https://csp-evaluator.withgoogle.com/)
  para validar tu política de seguridad.

- Seguir estas
  [recomendaciones de CSP](https://csp.withgoogle.com/docs/strict-csp.html). Ten
  en cuenta que en ICP no se pueden usar _nonces_ porque los cuerpos de
  respuesta deben ser estáticos para que funcione la certificación de assets
  HTTP.

- Se recomienda incluir
  [hashes de scripts en combinación con _strict-dynamic_](https://csp.withgoogle.com/docs/faq.html)
  en la CSP para compensar la imposibilidad de usar _nonces_.

- Restringir la directiva `connect-src`, ya que la CSP predeterminada permite
  que cualquier canister sea llamado a través de
  `https://icp0.io/api/v2/canister/{canister-ID}`.

- Configurar las directivas `style-src`, `style-src-elem` y `font-src` en lugar
  de utilizar el comodín (`*`).

Puedes ver más detalles sobre la
[CSP predeterminada](/docs/references/asset-canister).

### `dfx v0.21.0` y versiones anteriores

Las versiones `0.21.0` y anteriores de `dfx` incluyen `script-src 'unsafe-eval'`
en la política de seguridad predeterminada. Esto era necesario en versiones
antiguas porque las versiones anteriores del
[agente de JavaScript de ICP](https://www.npmjs.com/package/@dfinity/agent)
utilizaban un módulo WebAssembly para la validación de firmas BLS. Este módulo
ha sido eliminado y ya no está presente en las versiones más recientes de `dfx`.

Si estás utilizando una versión antigua de `dfx`, se recomienda actualizar tu
política de seguridad para eliminar la directiva `script-src 'unsafe-eval'`.
