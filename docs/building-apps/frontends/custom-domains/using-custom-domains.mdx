# Uso de dominios personalizados

<MarkdownChipRow labels={["Intermedio", "Tutorial"]} />

Por defecto, todos los canisters en el Internet Computer son accesibles a través
del dominio `icp0.io` y su ID de canister. Además de ese dominio predeterminado,
también se puede hacer que un canister sea accesible bajo un dominio
personalizado utilizando uno de los siguientes enfoques:

- [Registrar el dominio con los nodos de frontera](#dominios-personalizados-en-los-nodos-de-frontera).
- [Alojar el dominio en tu propia infraestructura](#dominios-personalizados-usando-tu-propia-infraestructura).

Para ambos enfoques, es necesario adquirir un dominio a través de cualquier
registrador, como NameCheap o GoDaddy.

Los dos enfoques difieren en facilidad de uso y configurabilidad. Al registrar
el dominio con los nodos de frontera, solo hay que configurar los registros DNS
del dominio personalizado. Los nodos de frontera se encargan de obtener un
certificado, renovarlo antes de su expiración y optimizar el SEO.

Al alojar el dominio en tu propia infraestructura, debes obtener y renovar los
certificados, además de proporcionar tu propia infraestructura con soporte para
el
[protocolo de puerta de enlace HTTP](../../../references/http-gateway-protocol-spec.md).
Sin embargo, este enfoque ofrece mayor flexibilidad en la configuración.

## Registrar el dominio con los nodos de frontera

Siguiendo los pasos a continuación, puedes alojar tu canister bajo tu dominio
personalizado utilizando los nodos de frontera. Primero se describen los pasos
de configuración, luego se usa un [ejemplo concreto](#ejemplo-concreto) para
ilustrarlos, seguido de instrucciones sobre
[solución de problemas](#solucion-de-problemas).

- #### Paso 1: Configurar el registro DNS de tu dominio (`CUSTOM_DOMAIN`).

  - Agrega un registro `CNAME` para tu dominio apuntando a
    `CUSTOM_DOMAIN.icp1.io`, de modo que todo el tráfico destinado a tu dominio
    sea redirigido a los nodos de frontera.
  - Agrega un registro `TXT` con el ID del canister en el subdominio
    `_canister-id` de tu dominio (por ejemplo, `_canister-id.CUSTOM_DOMAIN`).
  - Agrega un registro `CNAME` para el subdominio `_acme-challenge` (por
    ejemplo, `_acme-challenge.CUSTOM_DOMAIN`) apuntando a
    `_acme-challenge.CUSTOM_DOMAIN.icp2.io`, permitiendo que los nodos de
    frontera adquieran el certificado.

:::caution

Estos registros deben estar configurados antes de continuar con los siguientes
pasos.

:::

:::info

En muchos casos, no es posible establecer un registro `CNAME` para la parte
superior de un dominio (registro Apex). Algunos proveedores de DNS admiten
`CNAME` flattening y ofrecen tipos de registros como `ANAME` o `ALIAS`, que
pueden usarse en lugar del `CNAME` a `CUSTOM_DOMAIN.icp1.io`. La
[guía de configuración de DNS personalizada](./dns-setup.mdx) proporciona
instrucciones detalladas para tres registradores populares.

:::

- #### Paso 2: Crear un archivo `ic-domains` en el canister dentro del directorio `.well-known`, incluyendo el dominio personalizado.

La estructura de directorios debe ser la siguiente:

```
├── dfx.json
├── package.json
├── src
│ ├── project_frontend
│ │ ├── src
│ │ │ ├── .well-known
│ │ │ │ └── ic-domains
```

Por defecto, `dfx` excluye todos los archivos y directorios cuyos nombres
comienzan con `.` del canister de activos. Para incluir el archivo `ic-domains`,
crea un archivo adicional `.ic-assets.json5` en el mismo directorio de nivel
superior que `.well-known`:

```
├── dfx.json
├── package.json
├── src
│ ├── project_frontend
│ │ ├── src
│ │ │ ├── .ic-assets.json
│ │ │ ├── .well-known
│ │ │ │ └── ic-domains
```

Abre el archivo `ic-domains` e inserta los nombres de los dominios
personalizados. Si usas múltiples dominios y subdominios con un solo canister,
enuméralos en líneas separadas:

```sh
custom-domain1.com
subdomain1.custom-domain1.com
subdomain2.custom-domain1.com
custom-domain2.com
subdomain1.custom-domain3.com
custom-domain4.com
```

Por ejemplo, `subdomain1` podría representar `www`.

Configura el directorio `.well-known` para que sea incluido en el canister,
escribiendo lo siguiente en el archivo `.ic-assets.json5`:

```
[
  {
    "match": ".well-known",
    "ignore": false
  }
]
```

- #### Paso 3: Desplegar el canister actualizado.

- #### Paso 4: Registrar el dominio con los nodos de frontera ejecutando el siguiente comando, reemplazando `CUSTOM_DOMAIN` con tu dominio personalizado:

```sh
curl -sL -X POST \
    -H 'Content-Type: application/json' \
    https://icp0.io/registrations \
    --data @- <<EOF
    {
      "name": "CUSTOM_DOMAIN"
    }
EOF
```

Si la llamada fue exitosa, recibirás una respuesta JSON con el ID de la
solicitud, que puedes usar para consultar el estado de tu registro:

```
{"id":"REQUEST_ID"}
```

Si la llamada falló, recibirás un mensaje de error indicando la razón:

- **Registro DNS CNAME faltante**: Falta la entrada `CNAME` para el subdominio
  `_acme-challenge`.
- **Registro DNS TXT de desafío existente**: Ya existe una entrada `TXT` en el
  subdominio `_acme-challenge`. Elimínala y prueba de nuevo.
- **Registro DNS TXT faltante**: Falta la entrada `TXT` para el subdominio
  `_canister-id`.
- **Registro DNS TXT inválido**: El contenido del registro `TXT` no es un ID de
  canister válido.
- **Más de un registro DNS TXT**: Hay múltiples entradas `TXT` en el subdominio
  `_canister-id`. Mantén solo una.
- **No se pudo recuperar los dominios conocidos**: El archivo `ic-domains` no es
  accesible en `.well-known/ic-domains`.
- **El dominio falta en la lista de dominios conocidos**: El dominio
  personalizado no está en el archivo `ic-domains`.
- **Límite de solicitudes superado para el dominio Apex**: Se enviaron
  demasiadas solicitudes de registro para el dominio Apex. Inténtalo más tarde
  (máximo 5 solicitudes por dominio Apex por hora).

- #### Paso 5: Procesamiento del registro (puede tardar varios minutos).

Para rastrear el progreso, ejecuta el siguiente comando reemplazando
`REQUEST_ID` con el ID obtenido en el paso anterior:

```sh
curl -sL -X GET \
    https://icp0.io/registrations/REQUEST_ID
```

El estado puede ser:

- `PendingOrder`: La solicitud fue enviada y está en cola.
- `PendingChallengeResponse`: El certificado ha sido solicitado.
- `PendingAcmeApproval`: El desafío ha sido completado.
- `Available`: La solicitud se procesó con éxito.
- `Failed`: La solicitud de registro falló.

- #### Paso 6: Cuando el estado de la solicitud pase a `Available`, espera unos minutos para que el certificado esté disponible en todos los nodos de frontera.

Después de eso, deberías poder acceder a tu canister usando el dominio
personalizado.

## Ejemplo

Imagina que quieres registrar tu dominio `foo.bar.com` para tu canister con el
ID `hwvjt-wqaaa-aaaam-qadra-cai`.

### Configuración de DNS

| Tipo de Registro | Host                           | Valor                                |
| ---------------- | ------------------------------ | ------------------------------------ |
| `CNAME`          | foo.bar.com                    | foo.bar.com.icp1.io                  |
| `TXT`            | \_canister-id.foo.bar.com      | hwvjt-wqaaa-aaaam-qadra-cai          |
| `CNAME`          | \_acme-challenge.foo.bar.com   | \_acme-challenge.foo.bar.com.icp2.io |

:::info

Algunos proveedores de DNS no requieren que especifiques el dominio principal
(`bar.com`). Por ejemplo:

- `foo` en lugar de `foo.bar.com`.
- `_canister-id.foo` en lugar de `_canister-id.foo.bar.com`.
- `_acme-challenge.foo` en lugar de `_acme-challenge.foo.bar.com`.

:::

### Pasos para registrar el dominio

#### Paso 1: Crear el archivo `ic-domains` con el siguiente contenido en el directorio `.well-known`:

```
foo.bar.com
```

#### Paso 2: Crear el archivo `.ic-assets.json` en la raíz del canister:

```
[
  {
    "match": ".well-known",
    "ignore": false
  }
]
```

#### Paso 3: Desplegar el canister actualizado.

#### Paso 4: Iniciar el proceso de registro.

```sh
curl -sL -X POST \
    -H 'Content-Type: application/json' \
    https://icp0.io/registrations \
    --data @- <<EOF
    {
        "name": "foo.bar.com"
    }
EOF
```

## Solución de problemas

Cuando te encuentres con problemas al intentar registrar tu dominio
personalizado, prueba los siguientes pasos de solución de problemas:

- Verifica la configuración de tu DNS utilizando una herramienta como `dig` o
  `nslookup`. Por ejemplo, para verificar el registro `TXT` con el ID del
  canister, puedes ejecutar `dig TXT _canister-id.CUSTOM_DOMAIN`. En particular,
  asegúrate de que no haya entradas adicionales (por ejemplo, múltiples
  registros `TXT` para el subdominio `_canister-id`).
- Verifica que no haya registros `TXT` para el subdominio `_acme-challenge` (por
  ejemplo, utilizando `dig TXT _acme-challenge.CUSTOM_DOMAIN`). Si hay registros
  `TXT`, es probable que sean restos de desafíos ACME anteriores de tu proveedor
  de dominio. Ten en cuenta que estos registros a menudo no aparecen en el panel
  de administración de tu dominio. Intenta desactivar todas las ofertas de
  certificados TLS/SSL de tu proveedor de dominio para eliminar estos registros.
- Verifica el archivo `ic-domains` descargándolo directamente desde tu canister
  (por ejemplo, abriendo `CANISTER_ID.icp0.io/.well-known/ic-domains` en tu
  navegador o utilizando `curl CANISTER_ID.icp0.io/.well-known/ic-domains` en tu
  terminal).

:::info

Es posible que necesites especificar un `host` en tu código frontend al usar un
dominio personalizado, ya que el `HttpAgent` podría no inferirlo automáticamente
como lo hace en `icp0.io`. Para configurarlo, puedes hacer lo siguiente:

```ts
// Apunta a icp-api para mainnet. Dejando host undefined funcionará para localhost
const host = isProduction ? "https://icp-api.io" : undefined;
const agent = await HttpAgent.create({ host });
```

:::

## Actualización de un dominio personalizado

Si deseas actualizar el dominio para que apunte a un canister diferente, primero
debes actualizar el registro DNS de tu dominio y luego notificar a un boundary
node:

#### Paso 1: Actualiza la entrada `TXT` para que contenga el nuevo ID del canister en el subdominio `_canister-id` de tu dominio (por ejemplo, `_canister-id.CUSTOM_DOMAIN`).

#### Paso 2: Notifica a un boundary node del cambio con una solicitud `PUT` y el ID de tu registro (`REQUEST_ID`).

```sh
curl -sL -X PUT \
    https://icp0.io/registrations/REQUEST_ID
```

:::info

Si olvidaste el ID de tu registro, puedes enviar otra solicitud de registro para
tu dominio y el boundary node te devolverá el ID correspondiente.

:::

## Eliminación de un dominio personalizado

Si deseas eliminar tu dominio, solo necesitas eliminar los registros DNS y
notificar a un boundary node:

#### Paso 1: Elimina la entrada `TXT` que contiene el ID del canister en el subdominio `_canister-id` (por ejemplo, `_canister-id.CUSTOM_DOMAIN`) y la entrada `CNAME` para el subdominio `_acme-challenge` (por ejemplo, `_acme-challenge.CUSTOM_DOMAIN`).

#### Paso 2: Notifica a un boundary node de la eliminación con una solicitud `DELETE`.

```sh
curl -sL -X DELETE \
    https://icp0.io/registrations/REQUEST_ID
```

:::info

Si olvidaste el ID de tu registro, puedes enviar otra solicitud de registro para
tu dominio y el boundary node te devolverá el ID correspondiente.

:::

## Uso de dominios personalizados con tu propia infraestructura

- #### Paso 1: Despliega tu canister en ICP y toma nota del ID del canister.

- #### Paso 2: Clona el [repositorio oficial de ICP](https://github.com/dfinity/ic), cambia al commit `2304690ca1d241d9ce6e19a427a18de9aac95b82` y navega a la [carpeta del service worker](https://github.com/dfinity/ic/tree/2304690ca1d241d9ce6e19a427a18de9aac95b82/typescript/service-worker) ubicada en `ic/typescript/service-worker`.

- #### Paso 3: Mapea tu dominio al ID del canister agregando tu asignación dominio-canister a `hostnameCanisterIdMap` en el archivo [`service-worker/src/sw/domains/static.ts`](https://github.com/dfinity/ic/blob/2304690ca1d241d9ce6e19a427a18de9aac95b82/typescript/service-worker/src/sw/domains/static.ts).

- #### Paso 4: Compila el service worker siguiendo las instrucciones en `service-worker/README.md`. La salida debería incluir:

- Un `index.html`.
- Un archivo `.js` minificado.
- Un archivo `.map`.

- #### Paso 5: Aloja los archivos (`index.html`, `.js` y `.map`) en un servidor o CDN y apunta tu dominio personalizado a este servidor.

- #### Paso 6: Prueba que todo funcione correctamente.

:::caution

Para frontends que usan Internet Identity (II) para autenticar usuarios, los
`principals` proporcionados por II dependen del dominio desde el cual se inició
la solicitud de inicio de sesión. Si autenticas a tus usuarios a través de la
URL del canister y luego cambias a un dominio personalizado, los usuarios
tendrán un `principal` diferente.

Puedes evitar este problema configurando
[orígenes alternativos](/docs/building-apps/authentication/alternative-origins).

:::
