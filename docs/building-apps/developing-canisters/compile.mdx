# Compilar

<MarkdownChipRow labels={["Principiante", "Desarrollando canisters"]} />

Después de haber creado tus canisters, necesitas compilar el código en un módulo
WebAssembly antes de que pueda ser desplegado en ICP.

:::danger

Debes crear tus canisters antes de poder compilarlos; de lo contrario, recibirás
un mensaje de error indicando que no existen.

:::

:::info

La compilación del canister se realiza automáticamente en segundo plano cuando
se ejecuta el comando `dfx deploy`. Sin embargo, puede haber ciertos flujos de
trabajo en los que sea necesario compilar manualmente el código a Wasm.

:::

[`dfx build`](/docs/building-apps/developer-tools/dfx/dfx-build) busca el código
fuente para compilarlo para cada canister configurado en la sección `canisters`
del archivo
[`dfx.json`](/docs/building-apps/developer-tools/dfx-json-reference).
`dfx build` se puede usar para compilar un canister específico o todos los
canisters definidos en el proyecto.

Verifica la ubicación de los archivos de tu proyecto y sus nombres. Si es
necesario, edita el archivo `dfx.json` de tu proyecto para reflejar la
configuración actual prevista.

Compila tus canisters desde el directorio del proyecto:

```
dfx build <canister-name> --network=<NETWORK>
```

La compilación ocurre en la máquina local del desarrollador. `dfx build` no es
el único flujo de trabajo que se puede utilizar para compilar código. Por
ejemplo, los canisters escritos en Rust pueden ser compilados utilizando
`cargo`.

Cuando se ejecuta este comando, ocurren los siguientes pasos:

- El código fuente de un canister se compila en un módulo Wasm.

- Si un canister está escrito en Motoko, las declaraciones de tipos se generan
  automáticamente usando Candid.

- Si un canister está escrito en Rust, el proceso de construcción verifica
  vulnerabilidades en Rust.

### Cómo se compila el código a Wasm

WebAssembly (Wasm) es un formato binario independiente de la plataforma que
puede ser ejecutado en la máquina virtual de Wasm. Muchos compiladores modernos
admiten Wasm como objetivo de compilación junto con objetivos tradicionales como
x86 y arm32.

Existen tres tipos de Wasm dependiendo de dónde se aloje la máquina virtual de
Wasm y cómo interactúe con los usuarios y el entorno del host:

- **Navegador web**: El programa Wasm interactúa con los usuarios a través de
  los enlaces de JavaScript del navegador. La cadena de herramientas principal
  para compilar Wasm para navegadores es [Emscripten](https://emscripten.org/).
  Ten en cuenta que dichos programas Wasm son incompatibles con ICP.

- **WASI**: Esta abreviatura significa
  [WebAssembly System Interface](https://wasi.dev/). Se está convirtiendo en el
  estándar para ejecutar programas Wasm fuera de los navegadores web. Los
  principales entornos de ejecución de Wasm como Wasmtime y Wasmer admiten este
  estándar. Los compiladores denominan este objetivo como `wasm32-wasi`. ICP no
  admite directamente WASI, pero es posible preprocesar un programa WASI y
  hacerlo ejecutable en ICP con el proyecto comunitario
  [`wasi2ic`](https://github.com/wasm-forge/wasi2ic).

- **Wasm Vanilla**: No existe una API estándar para interactuar con los usuarios
  y el entorno del host. Cada entorno de host proporciona su propia API. ICP
  utiliza este enfoque y proporciona un conjunto de funciones, llamadas la API
  del Sistema, al programa Wasm. Muchos compiladores denominan este objetivo
  como `wasm32-unknown-unknown` ya que no conocen el entorno de host objetivo y
  no hacen suposiciones sobre las APIs disponibles.

El Kit de Desarrollo de Canisters (CDK) de los lenguajes de programación
compatibles viene con scripts de construcción que enlazan la API del Sistema y
compilan el código a programas Wasm que son compatibles con ICP:

- Rust y Motoko se compilan al objetivo `wasm32-unknown-unknown` directamente
  bajo el capó.
- Azle y Kybra primero se compilan al objetivo `wasm32-wasi` y luego convierten
  el binario Wasm a `wasm32-unknown-unknown` utilizando la herramienta
  `wasi2ic`.

Para la conveniencia de los desarrolladores, `dfx` envuelve los scripts de
construcción específicos del CDK y proporciona el comando `dfx build` para
compilar el código a un binario Wasm.
