# Despliegue

<MarkdownChipRow labels={["Principiante", "Desarrollando canisters"]} />

Después de haber
[creado](/docs/building-apps/developing-canisters/what-are-canisters) un

<GlossaryTooltip>canister</GlossaryTooltip>, puedes desplegarlo en:

- La red local creada por `dfx`, donde se fabrican los ciclos.
- El playground en la mainnet, que es un entorno similar a una testnet. No se
  requieren ciclos para desplegar y ejecutar tus canisters en el playground,
  pero se eliminarán después de 20 minutos.
- Una
  [red local o playground personalizada](/docs/building-apps/developing-canisters/create).
- La mainnet, diseñada para uso en producción. Este método de despliegue tendrá
  un costo en [ciclos](/docs/building-apps/essentials/gas-cost).

Verifica que estés en el directorio de tu proyecto y que los canisters que
deseas desplegar estén configurados en el archivo `dfx.json` de tu proyecto.
Luego, despliega tus canisters utilizando el comando `dfx deploy`:

```
dfx deploy <canister-name> --network=<NETWORK>
```

## Compartir enlaces a canisters

Una vez que un dapp ha sido desplegado en la mainnet, cada canister puede ser
accesado a través de una URL pública. Esta URL puede ser compartida con
cualquiera, permitiéndoles ver e interactuar con tu dapp sin necesidad de
configurar nombres de dominio, registros DNS u otras configuraciones de red.

Puedes usar el siguiente formato de URL para acceder a un canister desde el
navegador web:

```
https://<canister_id>.icp0.io
```

Si compartes un enlace a un canister frontend, se mostrará el frontend del dapp.

Si compartes un enlace a un canister backend, se mostrará la
[UI Candid](/docs/building-apps/interact-with-canisters/candid/candid-concepts).

## Usar una versión personalizada de Motoko con `dfx deploy`

Para usar una versión personalizada de Motoko con `dfx deploy`, exporta la
siguiente variable de entorno que indica qué versión base de Motoko deseas que
`dfx` utilice:

```bash
DFX_MOC_PATH="$(vessel bin)/moc" dfx deploy
```

## Configurar los argumentos de inicialización de un canister

Puedes configurar los argumentos de inicialización de un canister cuando el
canister es desplegado pasando la opción `--argument`:

```bash
dfx deploy <canister-name> --argument "(arg in candid)"
```

Si se deben usar varios argumentos, se puede definir un archivo de argumentos
con la opción `--argument-file`:

```bash
dfx deploy <canister-name> --argument-file file.txt
```

Alternativamente, los argumentos de inicialización pueden configurarse en
`dfx.json` en versiones de `dfx` `v0.17.0` y superiores:

```json title="dfx.json"
"canisters": {
    "hello_backend": {
      "candid": "src/hello_backend/hello_backend.did",
      "package": "hello_backend",
      "type": "rust",
      "init_arg": "(arg in candid)"
    },
 }
```

Si se configura un argumento de inicialización en `dfx.json` y también se
configura mediante el comando CLI, se usará el argumento configurado en el
comando CLI.

## Testnets (redes de prueba)

La mayoría de las redes blockchain tienen testnets separadas que permiten a los
desarrolladores probar sus proyectos en un entorno similar al de producción a un
costo significativamente menor que en la mainnet. Debido a que la ejecución de
canisters en ICP es bastante barata y los canisters pueden ser actualizados una
vez desplegados, no existe una testnet para ICP.

Se anima a los desarrolladores a probar sus canisters localmente o directamente
en la mainnet.

Sin embargo, herramientas como [ICP Ninja](https://icp.ninja) (un IDE web) y el
entorno de playground (disponible desde la CLI) pueden usarse como opciones de
despliegue similares a testnets. No requieren ciclos para desplegar y operar un
canister, pero tienen limitaciones y los canisters serán eliminados
automáticamente después de 20 minutos.

Para la mayoría de los desarrolladores, la opción del playground puede ser
utilizada. Para desarrolladores más avanzados y casos de uso más específicos,
existen dos opciones posibles para un entorno similar a testnet:

- [Playgrounds personalizados](/docs/building-apps/developing-canisters/custom-networks):
  Los desarrolladores pueden desplegar su propia instancia personalizada del
  playground en la mainnet, permitiendo una personalización total de los
  parámetros del playground.
- [Redes personalizadas de `dfx`](/docs/building-apps/developing-canisters/custom-networks):
  La característica de red nombrada de `dfx` puede usarse para crear redes
  personalizadas que se pueden utilizar para pruebas separadas de otros
  proyectos desplegados localmente.
