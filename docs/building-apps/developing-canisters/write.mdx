# Escribir

<MarkdownChipRow labels={["Principiante", "Desarrollo de canisters"]} />

ICP admite una amplia gama de aplicaciones y tipos de arquitecturas. Estas
pueden ir desde un solo canister hasta proyectos complejos y
multi-<GlossaryTooltip>canister</GlossaryTooltip>, y todo lo que hay entre
ellos.

Puedes comenzar a escribir y estructurar tu aplicación utilizando uno de los dos
principales flujos de trabajo:

- **Flujo de trabajo estándar**: El desarrollador escribe tanto el código del
  frontend como del backend, y luego despliega ambos en ICP como canisters.

- **Flujo de trabajo basado en frameworks**: Se utiliza un framework externo
  para facilitar la creación y el despliegue de canisters.  
  [Más información sobre frameworks](#framework-based-workflow).

### Flujo de trabajo estándar

#### Elección del lenguaje de programación para el backend

El backend almacena los datos de la aplicación y contiene la lógica central. Se
admiten varios lenguajes, como:

- **[Motoko](/docs/motoko/main/getting-started/motoko-introduction)**:
  Compatible con [DFINITY](https://github.com/dfinity/motoko). Motoko está listo
  para producción y fue diseñado específicamente para facilitar la incorporación
  de desarrolladores a ICP y aprovechar el modelo de programación basado en
  actores de ICP. Es un lenguaje de alto nivel con un recolector de basura y una
  sintaxis similar a TypeScript. Algunos ejemplos de canisters en producción que
  usan Motoko incluyen [ICDex](https://github.com/iclighthouse/ICDex) y
  [CycleOps](https://github.com/CycleOperators/cycles-manager).  
  [Más información sobre el uso de Motoko](/docs/motoko/main/getting-started/motoko-introduction).

- **[Rust](/docs/building-apps/developer-tools/cdks/rust/intro-to-rust)**:
  Compatible con [DFINITY](https://github.com/dfinity/cdk-rs). Actualmente, Rust
  es el lenguaje con mayor cobertura en producción para aplicaciones en ICP.
  Todos los canisters del sistema, como
  [el DAO que gobierna ICP](https://github.com/dfinity/ic/tree/master/rs/nns),
  [el ledger de ICP](https://github.com/dfinity/ic/tree/master/rs/ledger_suite/icp),
  y los canisters de integración con
  [Bitcoin](https://github.com/dfinity/bitcoin-canister) y
  [Ethereum](https://github.com/dfinity/ic/tree/master/rs/ethereum), están
  escritos en Rust. Este lenguaje brinda al desarrollador un control total sobre
  todos los aspectos del canister, desde el rendimiento hasta la gestión de
  memoria. La única desventaja de Rust es que es un lenguaje de más bajo nivel
  en comparación con otros y requiere habilidades avanzadas para escribir código
  seguro.  
  [Más información sobre el uso de Rust](/docs/building-apps/developer-tools/cdks/rust/intro-to-rust).

- **TypeScript (beta)**: Compatible con
  [Demergent Labs](https://github.com/demergent-labs) bajo el nombre Azle. Azle
  está en fase beta. Consulta
  [el sitio web de Azle](https://demergent-labs.github.io/azle/) para más
  información.

- **Python (beta)**: Compatible con
  [Demergent Labs](https://github.com/demergent-labs) bajo el nombre Kybra.
  Kybra está en fase beta. Consulta
  [el sitio web de Kybra](https://demergent-labs.github.io/kybra/kybra.html)
  para más información.

- **[C++](https://docs.icpp.world/)**: Compatible a través del
  [CDK de C++](https://docs.icpp.world/).

#### Elección de un framework web para el frontend

El [protocolo HTTP Gateway](/docs/references/http-gateway-protocol-spec) de ICP
permite que los navegadores carguen activos web como JS, HTML y CSS desde un
canister a través de HTTP. Esto significa que
[los activos web pueden almacenarse completamente en la blockchain](/docs/building-apps/frontends/using-an-asset-canister)
y que los desarrolladores no necesitan usar servicios de alojamiento web
centralizados para servir la interfaz de usuario de su aplicación.

[Svelte](https://svelte.dev/), [React](https://react.dev/) y
[Vue](https://vuejs.org/) han sido utilizados con éxito en producción.  
`dfx v0.17.0` y versiones posteriores pueden generar plantillas de proyectos que
incluyen uno de estos frameworks.

No tener frontend también es una opción válida para canisters sin interfaz de
usuario, que solo pueden ser llamados por usuarios u otros canisters.  
[Más información](/docs/building-apps/frontends/using-an-asset-canister).

#### Uso de un proyecto de ejemplo existente

También puedes obtener proyectos de otras fuentes, como
[ICP Ninja](https://icp.ninja) o el
[repositorio de ejemplos](https://github.com/dfinity/examples).  
Si obtienes un proyecto de una fuente distinta al comando `dfx new`, asegúrate
de que el directorio raíz del proyecto contenga un archivo `dfx.json` que defina
los canisters del proyecto.

### Flujo de trabajo basado en frameworks

#### Juno

[Juno](https://juno.build/docs/intro) es un proyecto comunitario diseñado para
desarrolladores Web2. Se encarga del alojamiento de código y datos en canisters,
permitiendo a los desarrolladores escribir aplicaciones Web3 utilizando
conceptos y patrones familiares de Web2.  
Para más detalles, consulta
[la documentación oficial de Juno](https://juno.build/docs/intro).

#### Bitfinity EVM

[Bitfinity EVM](https://docs.bitfinity.network/) está diseñado para
desarrolladores de Solidity. Es un canister que ejecuta una instancia de la
Ethereum Virtual Machine y permite a los desarrolladores subir y ejecutar
canisters escritos en Solidity.  
Para más detalles, consulta
[la documentación oficial de Bitfinity](https://docs.bitfinity.network/).

## Creación de un proyecto

Antes de escribir código para canisters, debes crear un proyecto ejecutando el
siguiente comando:

```bash
dfx new PROJECT_NAME --type=motoko
cd PROJECT_NAME
```

Las opciones para la flag `--type` son `motoko`, `rust`, `azle` y `kybra`.  
Usar [Rust](/docs/building-apps/developer-tools/cdks/rust/intro-to-rust),
[Azle](https://demergent-labs.github.io/azle//) o
[Kybra](https://demergent-labs.github.io/kybra/) puede requerir la instalación
de dependencias adicionales si aún no has desarrollado con esos lenguajes en tu
entorno. Consulta su documentación correspondiente para más información.

Debes estar en un directorio que contenga un archivo llamado `dfx.json`. Este
archivo se usa para configurar la configuración de tu proyecto. Incluye las
definiciones de los canisters del proyecto, como el tipo de canister, el archivo
del código fuente y las dependencias.

```json title=dfx.json
{
  "canisters": {
    "PROJECT_NAME_backend": {
      // Nombre del canister de backend
      "main": "src/PROJECT_NAME_backend/main.mo", // Código fuente del canister de backend
      "type": "motoko" // Lenguaje del canister
    },
    "PROJECT_NAME_frontend": {
      // Nombre del canister de frontend
      "dependencies": ["PROJECT_NAME_backend"],
      "source": [
        "src/PROJECT_NAME_frontend/dist" // Código fuente del canister de frontend
      ],
      "type": "assets", // Todos los canisters de frontend tendrán el tipo 'assets' sin importar el framework usado
      "workspace": "PROJECT_NAME_frontend"
    }
  },
  "defaults": {
    "build": {
      "args": "",
      "packtool": ""
    }
  },
  "output_env_file": ".env",
  "version": 1
}
```

### Paso 2: Agrega aleatoriedad.

Una característica clave de ICP es su capacidad de generar
[aleatoriedad en la blockchain](/docs/building-apps/network-features/randomness)
usando una función aleatoria verificable (VRF) y
[criptografía de clave en cadena](https://internetcomputer.org/how-it-works/chain-key-technology).
En cada ronda de consenso en un subnet, la VRF se evalúa con el número de la
ronda como entrada, produciendo un nuevo conjunto de bytes aleatorios. Estos
bytes se utilizan como semilla para un generador de números pseudoaleatorios
(PRNG), llamado _random tape_, el cual usa criptografía de clave en cadena para
crear un valor único y aleatorio para cada canister que lo solicite. A través de
este proceso, es imposible predecir los resultados futuros.

Para utilizar la aleatoriedad en tu canister, debes hacer una llamada al método
`raw_rand` del
[canister de gestión](/docs/references/system-canisters/management-canister).

Para demostrar cómo usar la aleatoriedad, crearemos una aplicación simple que
genera un número aleatorio.

Elimina el código existente en tu archivo backend y agrega el siguiente:

<AdornedTabs groupId="language">
<TabItem value="motoko" label="Motoko" default>

```motoko title="src/PROJECT_NAME_backend/main.mo" no-repl
import Nat8 "mo:base/Nat8";
import Debug "mo:base/Debug";
import Blob "mo:base/Blob";
import Nat "mo:base/Nat";
// El ID principal del canister de gestión es "aaaaa-aa".
import IC "ic:aaaaa-aa";

actor {
  stable var currentRandomNumber : Nat = 0;

  private func generateNewNumber() : async () {
      let randomBytes = await IC.raw_rand();
      if (randomBytes.size() > 0) {
          let bytes : [Nat8] = Blob.toArray(randomBytes);
          currentRandomNumber := Nat8.toNat(bytes[0]);
          Debug.print("Generated new random number: " # Nat.toText(currentRandomNumber));
      };
  };

  public query func getCurrentNumber() : async Nat {
      currentRandomNumber
  };
}
```

</TabItem>

```rust title="src/PROJECT_NAME_backend/src/lib.rs"
use candid::Nat;
// Import the management canister's raw_rand method
use ic_cdk::api::management_canister::main::raw_rand;
use std::time::Duration;

// Define a variable to hold the current random number.
thread_local! {
    static CURRENT_RANDOM_NUMBER: std::cell::RefCell<Nat> = std::cell::RefCell::new(Nat::from(0u8));
}

// Define an init function to generate a new random number.
#[ic_cdk::init]
fn generate_new_number() {
  let _ = ic_cdk::spawn(async {
      let random_bytes = raw_rand().await.unwrap().0;
      if !random_bytes.is_empty() {
          CURRENT_RANDOM_NUMBER.with_borrow_mut(|n| {
              *n = Nat::from(random_bytes[0]);
          });
          // Print the random number
          ic_cdk::println!(
              "New random number generated: {}",
              CURRENT_RANDOM_NUMBER.with_borrow(|n| n.clone())
          );
      }
  });
}

// Define a query function to get the random number.
#[ic_cdk::query]
fn get_current_number() -> Nat {
    CURRENT_RANDOM_NUMBER.with_borrow(|n| n.clone())
}
```

### Paso 3: Agregar un temporizador.

Hasta ahora, el código del canister genera un número aleatorio y lo almacena en
una variable. Puedes recuperar este valor con una función de consulta (_query
function_). Para demostrar otra función de ICP, agregaremos un temporizador que
generará un nuevo número aleatorio cada 5 segundos.

Los temporizadores permiten ejecutar acciones automáticamente después de un
intervalo o retraso especificado, permitiendo que los canisters realicen tareas
autónomas.

Añade la siguiente línea a tu código backend:

<AdornedTabs groupId="language">
<TabItem value="motoko" label="Motoko" default>

```motoko title="src/PROJECT_NAME_backend/main.mo" no-repl
import Nat8 "mo:base/Nat8";
import Debug "mo:base/Debug";
import Blob "mo:base/Blob";
import Nat "mo:base/Nat";
// The management canister's principal ID is "aaaaa-aa".
import IC "ic:aaaaa-aa";
// highlight-start
import Timer "mo:base/Timer";
// highlight-end

actor {
  // Create a stable variable to store the current random number.
  // Stable variables persist across canister upgrades.
  stable var currentRandomNumber : Nat = 0;

  // Create a function to generate a new random number.
  // This function calls the raw_rand method of the management canister.
  // Then it uses the random bytes returned to generate a random number.
  private func generateNewNumber() : async () {
      let randomBytes = await IC.raw_rand();
      if (randomBytes.size() > 0) {
          // Use the first byte to generate a number between 0 and 255
          let bytes : [Nat8] = Blob.toArray(randomBytes);
          currentRandomNumber := Nat8.toNat(bytes[0]);
          Debug.print("Generated new random number: " # Nat.toText(currentRandomNumber));
      };
  };

  // Use a query call to get the current random number.
  public query func getCurrentNumber() : async Nat {
      currentRandomNumber
  };

  // highlight-start
  // Initialize timer to generate a new number every 5 seconds
  let timer = Timer.recurringTimer(#seconds 5, generateNewNumber);
  // highlight-end
}
```

### Paso 4: Obtener datos externos.

Las llamadas HTTPS pueden obtener datos de cualquier fuente externa, incluyendo
otras blockchains, APIs Web2 tradicionales y otros servicios web. Cuando se
utilizan llamadas HTTPS localmente, el resultado devuelto no se valida ya que la
réplica local es solo un nodo. Las llamadas HTTPS utilizadas en la mainnet
validan el resultado devuelto a través del consenso del subnet, proporcionando
seguridad de que los datos obtenidos no han sido manipulados maliciosamente
durante el transporte.

Las llamadas HTTPS actualmente admiten los métodos `GET` y `POST` de HTTPS.

Para demostrar cómo crear y enviar llamadas HTTPS, agreguemos una llamada HTTPS
GET que devuelve información sobre las estadísticas diarias de ICP desde la API
de ICP. Inserta el siguiente código resaltado en tu archivo de código fuente
backend:

<AdornedTabs groupId="language">
<TabItem value="motoko" label="Motoko" default>

```motoko title="src/PROJECT_NAME_backend/main.mo" no-repl
import Nat8 "mo:base/Nat8";
import Debug "mo:base/Debug";
import Blob "mo:base/Blob";
import Nat "mo:base/Nat";
// The management canister's principal ID is "aaaaa-aa".
import IC "ic:aaaaa-aa";
import Timer "mo:base/Timer";
// highlight-start
import Cycles "mo:base/ExperimentalCycles";
import Text "mo:base/Text";
import Types "Types";
// highlight-end

actor {
  // Create a stable variable to store the current random number.
  // Stable variables persist across canister upgrades.
  stable var currentRandomNumber : Nat = 0;

  // Create a function to generate a new random number.
  // This function calls the raw_rand method of the management canister.
  // Then it uses the random bytes returned to generate a random number.
  private func generateNewNumber() : async () {
      let randomBytes = await IC.raw_rand();
      if (randomBytes.size() > 0) {
          // Use the first 2 bytes to generate a number between 0 and 255
          let bytes : [Nat8] = Blob.toArray(randomBytes);
          currentRandomNumber := Nat8.toNat(bytes[0]);
          Debug.print("Generated new random number: " # Nat.toText(currentRandomNumber));
      };
  };

  // Use a query call to get the current random number.
  public query func getCurrentNumber() : async Nat {
      currentRandomNumber
  };

  // Initialize a timer to generate a new number every 5 seconds.
  let timer = Timer.recurringTimer<system>(#seconds 5, generateNewNumber);

  // highlight-start

  // Define a public function to get the daily stats about ICP from the ICP API.
  public func getIcpInfo() : async Text {

    // Define the API endpoints to obtain data from.
    // This example uses the IC API, but any API endpoint can be used.
    let url = "https://ic-api.internetcomputer.org/api/v3/daily-stats?format=json";
    let transform_context : Types.TransformContext = {
      function = transform;
      context = Blob.fromArray([]);
    };

    // Define the http_request components.
    let http_request = {
        url = url;
        max_response_bytes = null; // Optional.
        headers = [];
        body = null; // Optional.
        method = #get;
        transform = ?transform_context;
    };

    // HTTP outcalls require cycles to be attached to the call.
    Cycles.add<system>(20_949_972_000);

    // Execute the HTTP outcall.
    let http_response = await IC.http_request(http_request);

    let response_body: Blob = http_response.body;
    switch (Text.decodeUtf8(response_body)) {
        case null { "No value returned" };
        case (?y) { y };
    };
  };

  // Define a transform function to return the status response and body.
  public query func transform(raw : Types.TransformArgs) : async IC.http_request_result {
      {
          status = raw.response.status;
          body = raw.response.body;
          headers = [ ];
      };
  };
// highlight-end
}
```

Este código de llamadas HTTP externas hace referencia a tipos personalizados,
como se indica en la declaración de importación `import Types "Types";` y en
declaraciones de código como `Types.TransformContext`. Las definiciones de tipos
personalizados pueden crearse dentro del archivo `main.mo`, pero para tipos que
pueden usarse en varios archivos de código fuente, puede ser beneficioso
definirlos en un solo archivo `Types.mo` y luego importarlos según sea
necesario.

Crea un nuevo archivo llamado `src/PROJECT_NAME_backend/Types.mo` que contenga
lo siguiente:

```motoko title="src/PROJECT_NAME_backend/Types.mo" no-repl
import IC "ic:aaaaa-aa";

module Types {

  // HTTPS outcalls have an optional "transform" key. These two types help describe it.
  // The transform function may transform the body in any way, add or remove headers, modify headers, etc.

  public type TransformArgs = {
    response : IC.http_request_result;
    context : Blob;
  };

  public type TransformContext = {
    function : shared query TransformArgs -> async IC.http_request_result;
    context : Blob;
  };

}
```

### Paso 5: Combinándolo todo.

En este punto, tenemos tres funciones en este código que demuestran tres
características diferentes de ICP: **aleatoriedad en la cadena (onchain
randomness)**, **temporizadores (timers)** para ejecución autónoma y **llamadas
HTTP externas (HTTPS outcalls)** para obtener datos. Vamos a editar el código
para usarlas en conjunto en lugar de por separado:

1. La aleatoriedad en la cadena se utilizará para generar un número entre 133000
   y 133255. Este número se usará para seleccionar aleatoriamente una propuesta
   reciente del [NNS](/docs/building-apps/governing-apps/nns/overview).

2. El número aleatorio se pasará a la llamada HTTP externa. La llamada HTTP
   consultará el endpoint de la API de IC para obtener detalles sobre esa
   propuesta específica.

3. Se utilizarán temporizadores para generar un nuevo número cada 30 segundos y
   enviar una nueva llamada HTTP externa cada 32 segundos.
