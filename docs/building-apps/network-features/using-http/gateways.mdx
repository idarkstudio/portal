# Gateways HTTPS y solicitudes entrantes

<MarkdownChipRow labels={["Avanzado", "Tutorial"]} />

Los canisters que se ejecutan en ICP pueden utilizar solicitudes HTTP de dos
maneras: entrantes y salientes. Las solicitudes HTTP entrantes se refieren a las
solicitudes HTTP enviadas a un canister. Se pueden usar para recuperar datos de
un canister o enviar nuevos datos al mismo. Las solicitudes HTTP salientes se
refieren a las solicitudes HTTP que un canister envía a otros canisters o
servicios externos para recuperar o enviar datos.

## Ciclo de vida de una solicitud HTTP

En ICP, una solicitud HTTP pasa por el siguiente ciclo de vida:

1. Un cliente HTTP realiza una solicitud saliente.
2. El HTTP gateway intercepta la solicitud y resuelve el ID del canister de
   destino.
3. La solicitud se codifica en Candid y se envía como una consulta
   (`query call`) al método `http_request` del canister de destino.
4. La solicitud es enviada a un nodo de frontera de la API de ICP, que luego la
   reenvía a un nodo réplica en la subred correspondiente.
5. El canister recibe y procesa la solicitud, luego devuelve la respuesta.
6. El HTTP gateway decodifica la respuesta de Candid.
7. Si el canister lo solicita, el gateway reenvía la solicitud mediante una
   llamada de actualización (`update call`) al método `http_request_update` del
   canister. Esta actualización pasa por el proceso de consenso en la subred.
8. Si el tamaño de la respuesta
   [excede el máximo permitido](/docs/building-apps/canister-management/resource-limits),
   el HTTP gateway obtiene datos adicionales del cuerpo de la respuesta a través
   de consultas (`query calls`).
9. El HTTP gateway valida el certificado de la respuesta, si corresponde.
10. El HTTP gateway devuelve la respuesta decodificada al cliente HTTP.

### Terminología

- **Solicitud (Request)**: Un mensaje enviado a un servidor o endpoint.
- **Cliente (Client)**: Un servicio capaz de enviar una solicitud en formato
  HTTP y recibir una respuesta de un servidor.
- **Gateway**: Un componente que facilita la transferencia de mensajes entrantes
  y salientes.

## Gateways HTTP

El protocolo **HTTP gateway** de ICP permite que los clientes HTTP
convencionales interactúen con la red de ICP. Los HTTP gateways funcionan en
paralelo a ICP y proporcionan una conexión utilizada por navegadores web y otras
aplicaciones para enviar y recibir solicitudes y respuestas HTTP estándar,
incluyendo activos estáticos como HTML, JavaScript, imágenes o videos.

El **HTTP gateway** hace posible este flujo de trabajo al traducir las
solicitudes HTTP estándar en llamadas a la API de los canisters de ICP y
viceversa para las respuestas HTTP.

Existen varias instancias de **HTTP gateway** mantenidas para ICP. Sin embargo,
es importante señalar que un **HTTP gateway es un componente centralizado**, lo
que significa que podría verse comprometido, representando un riesgo para los
usuarios que reciben contenido HTTP.

DFINITY controla exclusivamente los **HTTP gateways** que sirven los canisters
en `ic0.app` y `icp0.io`. Los desarrolladores pueden configurar sus propios
[dominios personalizados](/docs/building-apps/frontends/custom-domains/using-custom-domains)
para apuntar a los gateways HTTP controlados por DFINITY.

Como alternativa, los desarrolladores pueden ejecutar sus propios **HTTP
gateways** en sus dominios personalizados en lugar de usar los gateways
controlados por DFINITY, aunque esta opción aún no está bien soportada.

Para una solución más segura, es posible ejecutar una instancia local de un
**HTTP gateway**. Se pueden encontrar más detalles en la
[especificación del protocolo HTTP gateway](/docs/references/http-gateway-protocol-spec).

### Ejecutando un HTTP gateway local

Para ejecutar tu propio **HTTP gateway local**, puedes utilizar una
implementación de prueba de concepto que permite una conexión segura de extremo
a extremo con los canisters desplegados en ICP.

Esta implementación incluye:

- Traducción entre solicitudes de activos HTTP y llamadas a la API de ICP.
- Detección de dominios ICP a partir de principals y registros de dominios
  personalizados.
- Terminación de conexiones TLS localmente.
- Omisión de listas de denegación de gateways remotos.
- Resolución de dominios criptográficos.

#### Instalación

Puedes descargar el paquete de instalación preconstruido para tu
[sistema operativo](https://github.com/dfinity/http-proxy?tab=readme-ov-file#installation).

Una vez instalado, tendrás la opción de iniciar o detener el servicio IC HTTP
proxy. Inicia el servicio para comenzar a usarlo. Una vez que el proxy esté en
ejecución, manejará todo el tráfico en tu computadora. Cualquier tráfico que no
esté destinado a la ICP mainnet pasará a través del gateway, y el tráfico que
esté destinado a ICP será interceptado por el proxy. El proxy registrará el
tráfico en el archivo
`$HOME/Library/Preferences/dfinity/ichttpproxy/ic-http-proxy-proxy.log` en
máquinas macOS o en el directorio `tmp` en máquinas Windows.

Por ejemplo, realiza la siguiente solicitud `curl` al NNS:

```
curl -v https://nns.ic0.app
```

Esto generará un registro de:

```
{"level":30, "time": "2024-06-17T13:46:40.947Z","pid":43956,"hostname":"JessieMgeonsMBP.attlocal.net","name":"IC HTTP Proxy Server","msg":"Proxying web3 request for nns.ic0.app:443"}
```

## Solicitudes HTTP salientes

Para solicitudes HTTP salientes, se debe usar la función
[HTTPS outcalls](/docs/building-apps/network-features/using-http/https-outcalls/overview).

## Solicitudes HTTP entrantes

Cada solicitud HTTP llega primero a `http_request`, y solo si se devuelve
`upgrade: true`, será mejorada y llamada nuevamente como `http_request_update`.
El método HTTP (`GET`, `POST`) no importa.

Consulta la
[referencia de la interfaz HTTP Candid](/docs/references/http-gateway-protocol-spec#canister-http-interface)
para más información.

### `GET` requests

Las solicitudes HTTP `GET` se utilizan para recuperar y devolver datos
existentes desde un endpoint. Para manejar las solicitudes `GET` entrantes de un
canister, se puede exponer el método `http_request`. Los usuarios y otros
servicios pueden llamar a este método usando una llamada `query`. Para devolver
datos en la respuesta HTTP, los siguientes ejemplos muestran cómo configurar
`http_request` para responder a una solicitud `GET`.

### `POST` requests

Las solicitudes HTTP `POST` se utilizan para enviar datos a un endpoint con la
intención de almacenar esos datos. No se pueden hacer llamadas directas `POST`
al método `http_request_update` de un canister con clientes HTTP como `curl`. En
su lugar, se puede hacer una llamada `POST` al endpoint HTTP de un canister y
luego configurar el método `http_request` del canister para
[mejorar la llamada a `http_request_update`](/docs/references/http-gateway-protocol-spec#upgrade-to-update-calls).
