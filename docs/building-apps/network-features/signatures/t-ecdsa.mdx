# Threshold ECDSA

<MarkdownChipRow labels={["Avanzado", "Firmas"]} />{" "}

El Internet Computer implementa un novedoso protocolo de ECDSA de umbral como
parte de su conjunto de firmas chain-key\_. En este protocolo, la clave privada
de ECDSA existe solo como fragmentos secretos mantenidos por los nodos. Estos
fragmentos son partes de la clave privada de ECDSA, y las firmas se generan
utilizando estos fragmentos sin que la clave privada sea reconstruida en ningún
momento.

Cada réplica de un subnet con soporte para ECDSA mantiene una parte de la clave
que, por sí sola, no proporciona información. Se requiere más de un tercio de
los nodos para generar una firma de umbral usando sus respectivos fragmentos de
clave.

Además del protocolo de firma de umbral, chain-key ECDSA incluye protocolos para
la generación segura y distribuida de claves y la re-distribución periódica de
claves. La generación distribuida de claves permite a los nodos en un _subnet
colaborar para generar claves, mientras que la re-distribución periódica de
claves permite que las claves ECDSA se vuelvan a compartir dentro del subnet_.
Esto hace que las firmas chain-key ECDSA sean mucho más poderosas que cualquier
otro protocolo ECDSA de umbral convencional.

Cada canister en un subnet tiene control sobre una clave pública única de ECDSA
y puede solicitar firmas para esta clave pública. Los canisters no tienen acceso
a sus claves privadas de ECDSA; solo pueden solicitar firmas. Esto se debe a que
la clave privada nunca se almacena en un solo lugar.

Casos de uso de Threshold ECDSA

- Canisters que pueden retener Bitcoin de manera nativa.
- Integración con Ethereum y otras cadenas EVM, permitiendo la interoperabilidad
  con tokens ERC-20 y la firma de transacciones en Ethereum.
- Integraciones con otras blockchains que utilizan ECDSA como esquema de firma
  para transacciones.
- Implementación de una autoridad certificadora descentralizada (CA) donde los
  certificados se emiten mediante ECDSA de umbral.

## Firma de mensajes y transacciones

La API de Threshold ECDSA permite a los canisters firmar mensajes y
transacciones de forma segura sin que las claves privadas correspondientes
existan explícitamente. Cada canister puede controlar un número ilimitado de
claves mediante la especificación de diferentes rutas de derivación
(`derivation_path`).

La API proporciona dos métodos principales:

- `sign_with_ecdsa`: Permite firmar mensajes.
- `ecdsa_public_key`: Obtiene claves públicas.

### Firma de mensajes

Para firmar un mensaje, se utiliza el método `sign_with_ecdsa`, que tiene la
siguiente interfaz en Candid:

```candid
type sign_with_ecdsa_args = record {
    message_hash : blob;  // Hash del mensaje a firmar.
    derivation_path : vec blob; // Ruta de derivación opcional.
    key_id : record { curve : ecdsa_curve; name : text };
};

type sign_with_ecdsa_result = record {
    signature : blob;
};

service: {
  sign_with_ecdsa : (sign_with_ecdsa_args) -> (sign_with_ecdsa_result);
}
```

El método `sign_with_ecdsa` permite especificar una `derivation_path` opcional
para que un canister pueda solicitar firmas para diferentes claves que controla.
El campo `key_id` especifica la curva y el nombre de la clave a utilizar para la
firma. Actualmente, solo se admite la curva `secp256k1` y los siguientes nombres
de claves:

- `dfx_test_key`: Disponible solo en la réplica local iniciada por `dfx`.
- `test_key_1`: Clave de prueba disponible en la mainnet de ICP.
- `key_1`: Clave de producción disponible en la mainnet de ICP.

El método `sign_with_ecdsa` requiere la asignación de cycles*. En el Rust CDK*,
los cycles se adjuntan automáticamente. En Motoko, deben agregarse
manualmente.  
[Más información sobre los costos de Threshold ECDSA\_](/docs/references/t-sigs-how-it-works).

## Obtención de claves públicas

Para verificar una firma, se necesita la clave pública correspondiente a la
clave privada utilizada para firmar el mensaje. Además, la clave pública puede
emplearse para derivar direcciones controladas por el canister en diversas redes
blockchain. ICP proporciona el método `ecdsa_public_key` para obtener claves
públicas, con la siguiente interfaz en Candid:

```candid
type ecdsa_public_key_args = record {
    canister_id : opt canister_id;
    derivation_path : vec blob;
    key_id : record { curve : ecdsa_curve; name : text };
};

type ecdsa_public_key_result = record {
    public_key : blob;
    chain_code : blob;
};

service : {
  ecdsa_public_key : (ecdsa_public_key_args) -> (ecdsa_public_key_result);
};
```

El método `ecdsa_public_key` permite obtener claves públicas controladas por
_canisters_. A diferencia de `sign_with_ecdsa`, este método permite especificar
un `canister_id` opcional, lo que significa que un canister puede solicitar
claves públicas de otros canisters\_, pero no firmas.

El campo `chain_code` en el resultado puede usarse para derivar claves
secundarias sin necesidad de llamar repetidamente a `ecdsa_public_key`.
